## 0. バージョンとパッチの制約

- バージョンは 1.3.3 → **1.3.4**（`build.gradle` の `version` と `WeakSpotMod.VERSION` の2か所を、そろえて変える）
- `WeakSpotMod.ACCEPTED_VERSIONS`（`[1.3,1.4)`）は、変えない。1.3.x 同士は、互いに接続できる
- **パッチなので、互換性を破る変更を入れない**（パケット・`SyncedSettings`・保存データは変えない）。§1 の設定はサーバーだけが使う（送らない）ので、足してよい。§2 の数値はコード内の定数にする

## 1. 近接のクリティカルで武器の耐久を回復する

- サーバーが近接の弱点でクリティカルにした（`critHits` を数えた）とき、クリティカル **5 回ごと**に、メインハンドに持っている物の耐久を **1** 回復する
  - 耐久がある物ならなんでも（剣・斧に限らない）。耐久がない物・減っていない物は、回復しない（数え方は進む）
  - 数え方の余りは、メモリにだけ持つ（ログアウトで 0。採掘の耐久回復と同じ）
  - 回復してから、バニラが攻撃で武器の耐久を減らす
- 節目には数えない（今までどおり）
- 設定（**サーバーだけが使う**。クライアントには送らない）

| キー | 初期値 | 説明 |
|---|---|---|
| `critsPerRepair` | 5 | クリティカル何回ごとに、手に持っている物の耐久を回復するか。0 で回復しない |
| `critRepairPerStep` | 1 | `critsPerRepair` ごとに回復する耐久 |

## 2. 弓の過剰チャージ

- 弓を引き切ったあとも、弓の弱点を出し続ける。引き切ったあとのヒットは「過剰チャージ」で、1 ヒットごとに、放つ矢のダメージを **+10%**、最大 **5 ヒット（+50%）**まで上げる。5 ヒットで弱点を消す
- 引き切る前のヒットは、今までどおり引きを進める
- 矢を放ったとき、サーバーがその矢のダメージ（パワーのエンチャントを含む）に倍率を掛ける（`ArrowLooseEvent` で倍率を覚え、同じ tick にワールドに出たその プレイヤーの矢 `EntityArrow` に掛ける）
- 引き直す（引き始める）と、過剰チャージは 0 に戻る
- 引きゲージ: 引き切ったあと、ゲージのすぐ下に、過剰チャージの目盛り（5 つ。達した分を赤 `#FF4D4D`、残りを暗い背景 `#1E1E1E` 半透明）を出す
- サーバーでの確認は、今までどおり（弓を引いている、間隔）。引き切ったあとは、過剰チャージが上限未満なら受け付ける
- 統計の「弓ヒット数」・ヒット音・コンボには、過剰チャージのヒットも数える
- 数値（+10%、5 ヒット）は、コード内の定数にする（`common/BowMath`）

## 3. 一時オフのキーの初期値を HOME に

- 弱点の一時オフ（1.1.6）のキーの初期値を、J から **HOME** に変える（JourneyMap の J と重なるため。ユーザーの報告）
- Minecraft は、キーの割り当てを各自の `options.txt` に保存するので、すでに遊んでいる人は J のまま。README に、「設定 → 操作設定 → 弱点破壊」で変えるか「リセット」を押すと HOME になる、と書く
- 画面の文字（アクションバーなど）で J キーと書いているところは、キーの名前を割り当てから読んで出す（すでにそうなっていれば、そのまま）
- 統計画面の K キーは、変えない

## 4. 単体テスト（`common/` の純粋な計算）

- 過剰チャージの倍率: 0 ヒットで 1.0、3 ヒットで 1.3、5 ヒット以上で 1.5
- クリティカルの耐久回復: 採掘と同じ精算（`RepairSettlement`）で、5 回ごとに 1 回復、余りが持ち越されること

## 6. ユーザーに確認してもらうこと

- 近接: 減った剣で敵の弱点を殴り、クリティカル 5 回ごとに耐久が回復すること（回復のあと、攻撃の分で 1 減る）
- 弓: 引き切ったあとも弱点が出て、当てるとゲージの下の赤い目盛りが増えること。5 つで弱点が消えること
- 弓: 過剰チャージした矢が、普通に引き切った矢より大きく減らすこと（+50% で、ゾンビへのダメージが目に見えて増える）
- キー: 新しく入れた環境（または操作設定でリセット）で、HOME で一時オフが切り替わること。J が JourneyMap だけに効くこと
