## 1.11.0（マイナー。相談中）: 的当て

1.10.0 のあとの相談。仕様書はまだない（決まったら `SPEC_v1.11.0.md` を書く）。

- **決まったこと**
  - 新しいアイテム（仮の名前「弱点の的」／ Weak Spot Target）。手に持って右クリックすると、「3・2・1」のカウントダウンのあと **30 秒**のタイムアタック（ユーザーの判断: 30 秒）
  - 弱点は照準のまわりに出て、合わせると当たり。時間がたつほど難しくなる（0〜10 秒: 大きめ・近め、10〜20 秒: 小さく・遠く・ゆっくり動く、20〜30 秒: さらに小さく速く、**当ててはいけない「ハズレ」**も混ざり、当てると減点）

  - 終わったら画面の中央に点数と「NEW BEST!」、自己ベストなら花火
  - 自己ベストはワールドごと・プレイヤーごとに保存。K キーのメニューに「的当て」タブ（自己ベスト・回数・サーバーの上位 10 人）
  - **サーバー 1 位を更新したら、全員のチャットに知らせる**（ユーザーの判断: 出す。節目の知らせと同じ仕組みで、各自の設定で消せる）
  - ラウンドのコンボは、いつものコンボ（採掘などの掛け数）には入れない。ラウンドの間は、ほかの種類の弱点を出さない。途中でやめる（もう一度右クリック・持ち替え）と記録なし。アイテムに耐久はなし
  - アイテム・通信・保存データが増えるので**マイナー**。ほかの内容も一緒に入れる（ユーザーの判断: 入れる。何を入れるかは下の 4）
  - ハズレのルールは、始まる前に伝える必要がある（ユーザーの指摘）
- **決めること**（案とおすすめ）
  1. ハズレの伝え方: 毎回のカウントダウンの間に画面の中央に見本「● 当てる　✕ 当てない」／初めて使ったときだけチャットにルール／ガイドの本にページ／最初のハズレで一度だけ「赤は避けて！」。おすすめは前の 3 つ。ハズレは色だけでなく形も変える（当てる: オレンジ `#FF8A2A` の円、ハズレ: 赤 `#E53935` の ✕）
  2. ご褒美: 演出の解放（自己ベストの段階 銅 5,000・銀 15,000・金 30,000・虹 50,000 で、マーカーの形・特別色・当てたときの粒子。すべての種類の弱点に使える）／経験値（1 ラウンドで最大 5 くらい）／称号／進捗。おすすめは演出の解放と進捗（必要なら経験値を少し）
  3. 名前と入手方法: 名前の案は「弱点の的」（おすすめ）・「的当ての的」・「練習の的」。入手は、作業台で安く（棒 1 + 羊毛 1 + レッドストーン 1。おすすめ）／少し高め（金インゴット・レッドストーン・棒）／初回ログインで 1 個配る。アイコンの叩き台は、オレンジ `#FF8A2A` と白 `#FFFFFF` の同心円に、真ん中の赤 `#E53935` の点
  4. 一緒に入れる内容: `/weakspot top`（下の D。的当ての順位とつながる）・進捗（下の B）・ゲーム内のリンク（下の A）。おすすめは 3 つとも
- **経緯**: 最初の案は「当てると何か得がある暇つぶしのアイテム」。得の候補（経験値・コンボをつなぐ・短い効果・道具の修理・悪い効果を早く切る（牛乳と役目が重なる）・演出の解放・フィーバー・溜めて放つ・鉱石の探知・幸運）を比べ、ユーザーの判断でミニゲーム（的当て）にした

## 1.11.0（マイナー）: 弱点の大きさの設定

- 弱点の大きさを、**共通の 1 つの値**で変えられるようにする（サーバーの設定）。種類ごとの設定は増やさず、種類ごとに決まった倍率を掛ける（例: 釣りは ×0.75。釣りのマーカーは少し小さくてよいというユーザーの指摘から）

## 1.11.0 のあと: 別の Minecraft の版への対応

1.10.2 のあとの相談。仕様書はまだない（版を決めたら書く）。

- **決まったこと**
  - **順番**: 1.11.0（的当て・弱点の大きさ・コンボの段階）を先に出し、そのあと下ごしらえ（1.11.x のパッチ）、そのあと移植
  - **分け方**: リポジトリは 1 つのまま（長く残すブランチも `main` だけ）。版ごとに別々の Gradle のビルドを置き、版に依存しない計算（`common`）は**ソースで共有**する（各版のビルドが `../common/src/main/java` を読み込む）。1.12.2 の ForgeGradle 3 + Gradle 4.9 と新しい版の Gradle 8 は 1 つのマルチプロジェクトにできないため
  - **配布**: `common` は各版の本体の jar に入れる。別のライブラリ Mod としては公開しない（DL 数は分けても本体には足されず、入れ忘れ・版の食い違いの手間が増えるため）
  - 1.11.0 で足す計算（的当ての点数・難しさの段階・コンボの掛け数など）は、今の `common` パッケージに書いておく（あとでディレクトリごと移すだけで済む）
- **置き方の案**

```
common/            版に依存しない計算とそのテスト（1.12.2 版を残す限り Java 8 の書き方）
mc1.12.2/          今の src/ と build.gradle（Gradle 4.9、JDK 8）
mc1.xx.x/          新しい版（Gradle 8、JDK 17 など）
lang/              翻訳の元データ（ビルド時に .lang と .json を作る）
doc/ CHANGELOG.md update.json   共通（update.json は promos の「1.12.2-latest」などで版ごとに分ける）
```

- **下ごしらえ（1.11.x のパッチ。動作は変えない）**: `common/` を独立したディレクトリに出す → `src/` を `mc1.12.2/` へ `git mv`（開いている PR がない時期に）→ CI の `build` を matrix にして版ごとの JDK で走らせる → `client/`・`server/` にある版に依存しない処理を少しずつ `common/` に寄せる
- 共有するのは計算・`HitKind` の番号・設定のまとめ（`SettingGroups`）の並び・翻訳。設定の仕組み・通信・描画は版ごとに書く
- **版の候補**（未定）
  - 1.20（1.20.1）: Mod の利用者が多い。Java 17・Mojang の名前で、ほぼ書き直し。土台は Forge 47 か NeoForge（未定）
  - 1.8（1.8.9）: API は 1.12.2 に近く、Java 8。ただし、エリトラ（1.9 から）・近接の溜め（攻撃のクールダウンは 1.9 から）がなく、オフハンドがないので「両手が空」の判定も変える。1.8.9 の PvP サーバー（Hypixel など）には Mod を入れられないので、遊べるのはシングルか自分で立てたサーバーだけ。出すかどうかは未定
- **決めること**: 対応する版と土台・翻訳の元データの形式（`.json` がおすすめ）・版の番号を全版で揃えるか（おすすめは揃えて、jar 名を `weakspot-1.20.1-1.11.0.jar` の形に）・全機能が揃う前に一部だけで出してよいか

## 保留: 素手と同じに扱うアイテム

1.10.0 のあとの相談（ユーザーの判断: 一旦保留）。

- 今は、成長・収穫は利き手が空、機械はしゃがみ＋両手が空、動物は両手が空のときだけ弱点が出る。右クリックで何もしないアイテム（棒・インゴットなど）を持っていても出せるようにしたい
- ほかの Mod は「素手だけ」「専用の道具（レンチなど）」「設定の一覧」が多い。アイテムの作りを調べて自動で見分けるやり方は、あまり見ない
- 案: **既定の許可の一覧**（バニラの素材: 棒・各インゴット・宝石・糸・骨・羽根・火打石など。Mod のアイテムは設定に足す。おすすめ）／自動の判定＋除外の一覧／専用の道具（「弱点の手袋」）
- 注意: 小麦などの繁殖の餌は、動物に使うと繁殖になるので対象外（一覧に入れた物でも、その動物の餌なら外す）。もう片方の手のたいまつなど、置けるアイテムの動きにも気を付ける
- サーバーの設定をクライアントに送るなら通信が変わる（マイナー）

## 1.10.0 のあとの候補

1.9.4 のあとの相談。まだどの版に入れるかは決めていない。

- **A. ゲーム内のリンク先を配布サイトに**: 新しい版の通知の [ダウンロード]（`UpdateCheckNotice`）と、更新のお知らせの [変更点を見る]（`UpdateNotes.RELEASES_URL`）を、GitHub の Release から Modrinth・CurseForge のページへ。配布サイトの審査が通って公開されてから。パッチでも出せる。
