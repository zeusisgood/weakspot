## 1.11.11〜1.12.0: 別の Minecraft の版への対応

仕様書は [spec/SPEC_v1.11.11.md](spec/SPEC_v1.11.11.md)（コメントの整理）・[spec/SPEC_v1.11.12.md](spec/SPEC_v1.11.12.md)（下ごしらえ）はリリース済み。[spec/SPEC_v1.12.0.md](spec/SPEC_v1.12.0.md)（移植）は下書き（ユーザーが「実装」と言うまで実装しない）。

- **決まったこと**（1.10.2 のあと・1.11.10 のあとの相談）
  - **移植先**: 1.21.1 + NeoForge（Modpack での採用が多い版にしたい。All the Mods 10 など、上位の Modpack が 1.21.1 + NeoForge）
  - **順番**: 1.11.11（コメントの整理。名前の言い直しを消し、振る舞いはテストの名前に、How は名前に移す）→ 1.11.12（下ごしらえ。`common/` を外に出す・`src/` を `mc1.12.2/` へ・翻訳の元データを `lang/*.json` に・版に依存しない処理を `common/` に寄せる・版ごとのリリースの流れ）→ 1.12.0（移植）
  - **分け方**: リポジトリは 1 つのまま（長く残すブランチも `main` だけ）。版ごとに別々の Gradle のビルドを置き、`common` は**ソースで共有**する（1.12.2 の Gradle 4.9 と新しい版の Gradle 8 は 1 つのマルチプロジェクトにできないため）。`common` は各版の本体の jar に入れ、別のライブラリ Mod としては公開しない
  - **揃え続ける**: 移植のあとも、1.12.2 版と機能を揃える。片方の版だけを直したときも、両方の jar を同じ番号で出す
  - **版の番号**: 移植は 1.12.0（マイナー。新しい Minecraft の版に対応する節目のため）。jar は `weakspot-<Minecraft の版>-<版>.jar`
  - **配布**: GitHub の Release・CurseForge・Modrinth は、それぞれ 1 つのタグ・プロジェクトに、Minecraft の版ごとの jar を並べる。Modrinth の番号は `<版>+<Minecraft の版>`。`update.json` は 1 つのファイルに版ごとの節。Modrinth の審査は待たない
  - **出し方**: 全種類が揃ってから出す。PR と版は 1 つ、コミットは種類ごとに分けてよい
  - 的当ての数字（大きさ・距離・動きの速さ・ご褒美のしきい値）は今の値で決める
- **ほかの版の候補**（1.21.1 のあと。未定）
  - 1.20.1 + Forge 47: Modpack はまだ多い（Better MC 4 など）
  - 1.8（1.8.9）: API は 1.12.2 に近く、Java 8。ただし、エリトラ・近接の溜め・オフハンドがない。1.8.9 の PvP サーバーには Mod を入れられないので、遊べるのはシングルか自分で立てたサーバーだけ

### 照準のまわりの弱点の基準の向き（メモ）

1.11.0 のあとの相談。的当ては始めたときの向きを基準にした枠の中に出すようにした。立ったまま使う種類（飲食・ネザーゲート・弓・投擲物）も、弱点が出始めたときの向きを基準にすると流れにくくなる。今は左右・上下を交互に出して流れを抑えているので、遊んでみて流れが気になったら考える（ユーザーの判断: メモ）。移動する種類（落下・エリトラ・乗り物・ダッシュ・泳ぎ・はしご）は今の向きについていく今の出し方のまま。

- 的当てのペース表示（自己ベストのときのペースより速いか遅いか）も、優先度低めのメモとして残す

## いつかやる（やるときに相談する）

- **レッドストーンの前倒しの重さ**（1.11.6 のあとの相談。ユーザーの判断: 報告が来るまで何もしない）: `ScheduledTicks.boost` は、予約を持つ加速中の部品ごとに 1 tick に 1 回、ディメンションの予約を全部調べる（バニラの `getPendingBlockUpdates`）。巨大な回路で多くの部品を同時に加速したときだけ重くなりうる。重いと分かったら（spark などで測る）、予約の時刻を最初の 1 回だけ調べて覚え、全部調べるのは動かす瞬間だけにする。同時に加速できる数の上限は付けない。
- **音まわりの残り**（1.11.1 の相談で見送り）: 種類ごとの楽器（採掘はプリング、成長はチャイムなど）、演出の音（節目のベル・途切れの音・的当ての ✕）の音量を別に、的当ての間だけ別の音階、途切れの音のオン・オフ。
- **プレイ動画**（1.9.4 のあとの相談）: 30〜60 秒（採掘のコンボと音階・節目の花火・ほかの種類を少しずつ・K キーのメニュー。BGM なし）を YouTube に上げ、`doc/store/description.md` の冒頭に埋め込む（Modrinth は自動、CurseForge は貼り替え）。README には 10 秒ほどの MP4 を余裕があれば。撮影はスクショと同じ設定（チャット非表示・チュートリアルの案内なし・ほかの Mod の表示なし）。
- Boothに無料、支援版を置く 内容は同一 curceforge,githubへのリンクのみ 更新漏れを防ぐ

## 見送ったもの（ユーザーの判断。同じ案がまた出たときのために）

- 的当ての管理者向けの機能（1.11.10 のあとの相談。公開サーバーで使われる予定がないため。話が出たら両方の版で作る）:
  - サーバー設定 `targetPracticeEnabled`（オフでラウンドを始められない。設定を送るなら通信が変わる）
  - 記録を消す管理コマンド `/weakspot resettarget <プレイヤー>`
  - 不正対策（案 A）: 弱点・ハズレの位置と動きをサーバーが決めて送り、ヒットの瞬間の向きをサーバーが確かめる。今はクライアントの「当てた」を信じるので、改造クライアントなら最大 300 HIT を送れる。手間が大きく、自動照準は防げない。ほかの種類（落下を含む）の不正は、バニラ用のチートツールでもできる程度なので塞がない（ユーザーの判断）
- `server/QueryHandlers` を switch にしない: `HitHandlers` と同じ「種類 → 処理の表」の形で揃えておくと、移植のときに読みやすい（1.11.8）
- 手動用の配布のワークフロー（`modrinth-publish.yml` / `curseforge-publish.yml`）を 1 本にしない: 失敗したときの非常用で、Actions の画面で名前から選べたほうが間違えにくい。CurseForge だけ「二重に上がる」の注意書きがある（1.11.8）
- `CLAUDE.md` の JDK 8 を入れる手順と 429 の再実行を `doc/development.md` へのリンクにしない: クラウドのセッションで毎回使うので、開く文書を増やさない（1.11.8）
- `TimedBoostMath.multiplier` と `MachineComboBoost.multiplier` を統合しない: 上限が 0 以下のときの扱いが違う（機械に、乗り物・はしご・走りの「上限 0 = なし」の意味が入り込む）（1.11.7・1.11.8）
- `GrowthProgress.fraction` を `MachineProgress.ratio` にしない: 中身は同じだが、作物のクラスが「機械」のクラスに頼る形になる（1.11.7）
- `PlayerRules.canUse` を呼び出し側に書き込まない: クライアントとサーバーで同じ条件を使うための置き場所がなくなる（1.11.7）
- 0〜1 に収める `Math.max(0, Math.min(1, x))` をまとめない: どれも 1 行（1.11.7）
- 成長バーを `age` / `stage` 以外の整数の状態にも出さない: IC2 のゴムの木は列挙の状態なので効かず、耕地の水分などを間違ってバーにする心配が大きい。既知の問題のまま（1.11.7）
