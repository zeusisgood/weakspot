## 1.11.0（マイナー。仕様書は下書き）: 的当て・弱点の大きさ・コンボの段階ほか

相談で決まった内容を [spec/SPEC_v1.11.0.md](spec/SPEC_v1.11.0.md)（下書き）に書いた。ユーザーが「実装」と言うまで実装しない。

- **的当て**: アイテム「弱点の的」（棒・羊毛・レッドストーン）。右クリックでカウントダウン 3 秒のあと 30 秒。記録は**ヒット数**（ハズレは −5 HIT、0 より下にはならない）。ご褒美は自己ベストの段階（銅 15・銀 30・金 45・虹 60 HIT）で演出の解放と進捗。サーバー 1 位の更新は全員に知らせる
- **弱点の大きさ**: サーバーの設定 1 つ（0.5〜2.0、初期値 1.0）× 種類ごとの決まった倍率（釣り ×0.75）。見た目と当たり判定の両方
- **コンボの段階**: 10・25・50・75・100・150・200・250・300、以降 100 ごと。掛け数は 300 で ×4、その先も 100 ごとに ×0.5 ずつ上がり続ける。文字の出し場所は今のまま。**ほかの人が最大コンボを初めて超えて段階に届いたら全員に知らせる**（10 から全段階）
- **一緒に入れる**: `/weakspot top`（OP でなくても使える）・進捗・ゲーム内のリンクを CurseForge へ
- **素手と同じに扱うアイテム**: 右クリックで何もしないアイテム（ツルハシ・棒・インゴットなど）を自動で見分け、素手と同じに弱点を出す（動物では餌などを外す。除外の一覧も設定に）
- **落下の弱点**（新しい種類）: 落ちている間に当てると、落下ダメージが減る
- 1.11.0 のあとは機能を止め、1.11.x のパッチ（不具合の修正・音階の往復・下ごしらえ）を経て移植へ（ユーザーの判断）
- **経緯**: 最初の案は「当てると何か得がある暇つぶしのアイテム」。得の候補（経験値・コンボをつなぐ・短い効果・道具の修理・悪い効果を早く切る（牛乳と役目が重なる）・演出の解放・フィーバー・溜めて放つ・鉱石の探知・幸運）を比べ、ユーザーの判断でミニゲーム（的当て）にした。記録は最初、点数（1 ヒット 100 点 × 掛け数 ＋ ボーナス）の案だったが、分かりにくいのでヒット数にした（ユーザーの判断）

## 1.11.0 のあと: 別の Minecraft の版への対応

1.10.2 のあとの相談。仕様書はまだない（版を決めたら書く）。

- **決まったこと**
  - **順番**: 1.11.0（的当て・弱点の大きさ・コンボの段階）を先に出し、そのあと下ごしらえ（1.11.x のパッチ）、そのあと移植
  - **分け方**: リポジトリは 1 つのまま（長く残すブランチも `main` だけ）。版ごとに別々の Gradle のビルドを置き、版に依存しない計算（`common`）は**ソースで共有**する（各版のビルドが `../common/src/main/java` を読み込む）。1.12.2 の ForgeGradle 3 + Gradle 4.9 と新しい版の Gradle 8 は 1 つのマルチプロジェクトにできないため
  - **配布**: `common` は各版の本体の jar に入れる。別のライブラリ Mod としては公開しない（DL 数は分けても本体には足されず、入れ忘れ・版の食い違いの手間が増えるため）
  - 1.11.0 で足す計算（的当ての記録・難しさの段階・コンボの掛け数など）は、今の `common` パッケージに書いておく（あとでディレクトリごと移すだけで済む）
- **置き方の案**

```
common/            版に依存しない計算とそのテスト（1.12.2 版を残す限り Java 8 の書き方）
mc1.12.2/          今の src/ と build.gradle（Gradle 4.9、JDK 8）
mc1.xx.x/          新しい版（Gradle 8、JDK 17 など）
lang/              翻訳の元データ（ビルド時に .lang と .json を作る）
doc/ CHANGELOG.md update.json   共通（update.json は promos の「1.12.2-latest」などで版ごとに分ける）
```

- **下ごしらえ（1.11.x のパッチ。動作は変えない）**: `common/` を独立したディレクトリに出す → `src/` を `mc1.12.2/` へ `git mv`（開いている PR がない時期に）→ CI の `build` を matrix にして版ごとの JDK で走らせる → `client/`・`server/` にある版に依存しない処理を少しずつ `common/` に寄せる
- 共有するのは計算・`HitKind` の番号・設定のまとめ（`SettingGroups`）の並び・翻訳。設定の仕組み・通信・描画は版ごとに書く
- **版の候補**（未定）
  - 1.20（1.20.1）: Mod の利用者が多い。Java 17・Mojang の名前で、ほぼ書き直し。土台は Forge 47 か NeoForge（未定）
  - 1.8（1.8.9）: API は 1.12.2 に近く、Java 8。ただし、エリトラ（1.9 から）・近接の溜め（攻撃のクールダウンは 1.9 から）がなく、オフハンドがないので「両手が空」の判定も変える。1.8.9 の PvP サーバー（Hypixel など）には Mod を入れられないので、遊べるのはシングルか自分で立てたサーバーだけ。出すかどうかは未定
- **決めること**: 対応する版と土台・翻訳の元データの形式（`.json` がおすすめ）・版の番号を全版で揃えるか（おすすめは揃えて、jar 名を `weakspot-1.20.1-1.11.0.jar` の形に）・全機能が揃う前に一部だけで出してよいか

## 配布サイト

- Modrinth・CurseForge とも、自動公開の仕組みはできた。CurseForge は、ユーザーがプロジェクトを作り、`CURSEFORGE_TOKEN` と `CURSEFORGE_PROJECT_ID` を登録したら動く（1.9.4 は「CurseForge publish」を手動で 1 回流す）。
- CurseForge は公開済みで、README などのダウンロードは CurseForge を指す。Modrinth は審査中。済んだら README のダウンロードに 1 行足し、ゲーム内のリンク（1.11.0 で CurseForge へ）に Modrinth も足す（[development.md](development.md) の「配布サイト」）。
