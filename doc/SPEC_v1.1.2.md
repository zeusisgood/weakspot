# 弱点破壊 Mod 追加仕様書（v1.1.2）

`SPEC_v1.1.md`（Mod 1.1.0）と `SPEC_v1.1.1.md`（Mod 1.1.1。耐久回復の修正）に対する**パッチ**の仕様。ここに書かれていないことは、それらと現行実装のままとする。
仕様書は、リポジトリの `doc/` ディレクトリに置く（この仕様書は `doc/SPEC_v1.1.2.md`）。
仕様と食い違う実装をする場合は、`CLAUDE.md` のリリースの流れ（止まる条件）に従う。

- 対象: Minecraft Java Edition 1.12.2 / Forge 14.23.5.2860
- 前提: **1.1.1 がリリースされたあと**に、この仕様書の作業を始める（1.1.1 の内容を土台にする）
- 内容: **成長促進の対象の拡張**（サトウキビ、サボテン、ネザーウォート）と、意味のないブロックの除外
- この仕様書の内容は、Mod のバージョン **1.1.2** として、リリースする
- 追加リスト（§2.2）を設定にすることは、通信内容が変わるため、**1.2.0**（`SPEC_v1.2.md`）で行う。この仕様書では、コード内の固定のリストにする。除外リスト（§2.3）は、1.1.0 からある設定 `growthExcludedBlocks` を、そのまま使う

---

## 0. バージョンとパッチの制約

- バージョンは 1.1.1 → **1.1.2**（`build.gradle` の `version` と `WeakSpotMod.VERSION` の2か所を、そろえて変える）
- `WeakSpotMod.ACCEPTED_VERSIONS`（`[1.1,1.2)`）は、変えない。1.1.x 同士は、互いに接続できる
- **パッチなので、互換性を破る変更を入れない**（`SPEC_v1.1.md` §0 のバージョンの方針）
  - パケットの追加・削除・中身の変更をしない。`SyncedSettings`（サーバーから送る設定値）に、項目を足さない
  - サーバーが保存するデータの形式を、古い版で読めなくなるように変えない
  - 設定キーの削除や、意味の変更をしない
- **追加リスト**（§2.2）は、コード内の**固定のリスト**にする。設定（`weakspot.cfg`）には出さない
- **除外リスト**（§2.3）は、1.1.0 からある設定 `growthExcludedBlocks`（`[サーバー]`。`SyncedSettings` で同期済み）を、そのまま使う。新しい設定は足さない
- サーバーとクライアントで、バージョンが違っても、壊れないこと: 1.1.1 以前のクライアントは、サトウキビなどに弱点を出さない（ヒットも送らない）。1.1.1 以前のサーバーは、サトウキビなどへの成長ヒットを、対象外として受け付けないだけで、エラーにはならない

## 1. 症状と原因

### 1.1 症状
サトウキビに、右クリックを押しっぱなしにしても、弱点が出ず、成長を促進できない。

### 1.2 原因
成長促進の対象を、`IGrowable` を持つブロックに限っている（`SPEC_v1.1.md` §6.2）ため。Java版では、骨粉をサトウキビに使えない。つまり、サトウキビは `IGrowable` を持たないので、対象から外れている（実装のバグではなく、仕様の抜け）。

- サボテンも、同じ作りの可能性が高い
- ネザーウォートも、`IGrowable` を持たない可能性がある
- これらを、実装時にコードや Forge のソースで確認する（§4）

### 1.3 逆の問題（確認が必要）
`IGrowable` は、育っても意味がないブロックにも付いている（草ブロック、背の高い草、花の大きな草、キノコなど）。

**確認済み**: 1.1.0 から、設定 `growthExcludedBlocks`（初期値は §2.3 の5つ）で除外している。初期設定では、これらに弱点は出ない。そのため、この問題は、新しい対応が要らない。

## 2. 対象の決め方

### 2.1 対象の定義
次のどちらかを満たすブロックを、成長促進の対象にする。

- **A. `IGrowable` を持つブロック**: 成長できる状態（`canGrow`）で、かつ、除外リスト（§2.3）に入っていないもの
- **B. 追加リスト（§2.2）に入っているブロック**: 「育てる余地」（§2.4）があり、かつ、除外リスト（§2.3）に入っていないもの（サーバーの管理者が、`growthExcludedBlocks` にサトウキビなどを足して、外せるようにする）

サーバーとクライアントで、同じ条件を使う（`RightClickTargets` が、両側で共通の判定を使っているので、そこに足す）。

### 2.2 追加リスト（固定。`IGrowable` を持たない植物）

| 登録名 | 植物 |
|---|---|
| `minecraft:reeds` | サトウキビ |
| `minecraft:cactus` | サボテン |
| `minecraft:nether_wart` | ネザーウォート |

チョラスフラワー、つるなど、ほかの植物は、含めない。

### 2.3 除外リスト（既存の設定 `growthExcludedBlocks`。`IGrowable` を持つが、育っても意味がないもの）

コード内に、固定の除外リストは作らない。1.1.0 からある設定 `growthExcludedBlocks` を、そのまま使う。初期値は次のとおり（すでにこの値になっている）。

| 登録名 | 内容 |
|---|---|
| `minecraft:grass` | 草ブロック |
| `minecraft:tallgrass` | 背の低い草（シダを含む） |
| `minecraft:double_plant` | 背の高い草・花（ヒマワリ、バラの低木など） |
| `minecraft:brown_mushroom` | キノコ（茶） |
| `minecraft:red_mushroom` | キノコ（赤） |

- 設定なので、サーバーの管理者が、足したり外したりできる。追加リストのブロック（サトウキビなど）にも効く
- ほかにも、意味のないものが見つかったら、ユーザーに報告して、足すか決める
- 小麦などの作物、苗木、スイカ・カボチャのくき、カカオは、今までどおり対象にする

### 2.4 「育てる余地」の判定（追加リストのブロック）

私の知る限りの内容。実装時に、Forge 1.12.2 のソースで確認する（§4）。

| ブロック | 育てる余地がある条件 |
|---|---|
| サトウキビ、サボテン | その柱（同じブロックが縦に連続したもの）の高さが **3未満**。かつ、柱の一番上の、すぐ上が空気 |
| ネザーウォート | 成長段階が、最後（3）でない |

- 育てる余地がない（例: 高さ3の柱）ときは、弱点を出さない
- **土台の条件**: 高さ1のサトウキビは、土台の条件（下の土と、隣の水）を満たさないと、ランダムtickで根こそぎ壊れる（`checkForDrop`。バニラでも、次のランダムtickで壊れる）。そのため、土台の条件を満たさない高さ1のサトウキビには、弱点を出さない（実装時に、判定の方法を確認する。§4）
- 判定の純粋な部分（「高さが3未満か」「段階が最後でないか」）は、Minecraft に依存しない計算として `common/` に置く（§3.6）

### 2.5 効果（サーバー）
- 既存の成長ヒットと同じく、そのブロックに `randomTick` を `growthTicksPerHit` 回（初期値5）、余分に呼ぶ
- **サトウキビ、サボテン**: 育つのは、上が空気の**一番上の節だけ**。柱のどの節に弱点が出ていても、効果は、柱の**一番上の節**にかける
- サトウキビとサボテンは、ランダムtickを1回呼ぶごとに、成長段階が1つ進み、最大で新しいブロックが伸びる（初期値5回で、約3ヒットで1ブロック伸びる見込み）
- ネザーウォートは、確率で育つ（私の知る限り、ランダムtickごとに10分の1）ので、ほかより遅い。必要なら、後で調整する
- 検証（`RightClickHits`）は、今までどおり: 直前に右クリックしたか、届く距離か、間隔、対象か（§2.1 の判定を使う）

### 2.6 弱点の位置
- 成長の弱点は、今までどおり「一番大きい面」にだけ出す。サトウキビの柱は、上面より側面のほうが大きいので、側面に出る
- **同じ大きさの面が複数あるときの修正**: 現行の「一番大きい面」の選び方（`FaceMath.largestFaceAxis`）は、X 軸の面と Z 軸の面が同じ大きさのとき、必ず X 軸の面（視点がある側の東か西の面）を選ぶ。サトウキビ（当たり判定 0.75 × 1 × 0.75）とサボテンは、側面が上面より大きく、東西と南北の側面が同じ大きさなので、南北から見ると、ほぼ真横を向いた面に弱点が出る。さらに、ヒットは、照準が当たっている面と弱点の面が一致しないと成立しないので、当てられない
  - 直し方: 一番大きい面が側面で、X 軸と Z 軸の面が同じ大きさのときは、**照準が当たっている側面を優先**する
  - 上面が一番大きい作物（小麦など）の挙動は、変えない
  - ココアも、成長段階によって X 軸と Z 軸の面が同じ大きさになるので、同じ問題があり、同時に直る
  - 弱点が出ている間に、照準が別の側面に移っても、弱点の面がちらつかないようにする（例: ヒットで弱点が動くとき、または、弱点が消えて出し直すときに、面を選び直す）
  - 判定の純粋な部分は、`FaceMath`（`common/`）に置き、テストを書く
- サトウキビやサボテンは、柱のどの節でも、弱点を出してよい

### 2.7 統計
- 成長ヒットは、今までどおり、統計の「成長ヒット数」に数える（変更なし）

## 3. 実装の範囲

### 3.1 やること
- 成長促進の対象の判定（`RightClickTargets`）に、§2.1 の条件を足す（クライアントとサーバーで、同じ判定にする）
- 追加リストを、コード内の固定のリストとして持つ（登録名 → 柱の植物か、段階の植物か）。除外は、既存の設定 `growthExcludedBlocks` を使う
- 一番大きい面が同じ大きさで複数あるときの、弱点を出す面の選び方を直す（§2.6）
- 土台の条件を満たさない高さ1のサトウキビには、弱点を出さない（§2.4）
- サトウキビ、サボテンの効果を、柱の一番上の節にかける（§2.5）
- 弱点を出す・出さないの判定に、「育てる余地」（§2.4）を使う

### 3.2 やらないこと
- 対象のリストの設定化（1.2.0 で行う）
- チョラスフラワーなど、ほかの植物への対応
- 小さいブロックの弱点の配置の修正（1.2.0 で行う）

### 3.3 通信内容
- 変えない（§0）

### 3.4 リリース
- README の「最新版」の行を 1.1.2 にし、「更新履歴」に 1.1.2 を追加する
- README の、成長促進の説明に、サトウキビ、サボテン、ネザーウォートにも使えることを書く
- `CLAUDE.md` の、成長促進の対象（`RightClickTargets` の記述）を、この仕様に合わせて更新する
- リリースの流れは、今までと同じ: README の更新 → コミット → 注釈付きタグ `v1.1.2` → `main` とタグを push。GitHub Release は、ユーザーが手動で作り、`build/libs/weakspot-1.1.2.jar` を添付する

**README の更新履歴の案（1.1.2）**

```markdown

- サトウキビ、サボテン、ネザーウォートにも、右クリックを押しっぱなしにして弱点を当てると、成長を促進できるようにした
- サトウキビ、サボテン、ココアで、弱点が横向きの面に出て当てられない場合がある問題を直した（照準が当たっている面に出る）
- 通信内容は変わっていない。1.1.x 同士は、そのまま接続できる
```

### 3.5 CLAUDE.md
- 追加リスト（`RightClickTargets` の固定リスト）と、除外リスト（設定 `growthExcludedBlocks`）の場所を、`CLAUDE.md` に書く（後で 1.2.0 で、追加リストを設定にするときの手がかりになる）

### 3.6 単体テスト
「育てる余地」の純粋な部分を、`common/` に置き、テストを書く。
- サトウキビ・サボテン: 柱の高さが1、2のとき「余地あり」、3のとき「余地なし」。柱の一番上の上が空気でないとき「余地なし」
- ネザーウォート: 成長段階が 0〜2 のとき「余地あり」、3のとき「余地なし」
- 面の選び方（`FaceMath`）: 上面が一番大きいとき（小麦など）は、今までと同じ面になること。側面が一番大きく、X 軸と Z 軸の面が同じ大きさのとき、照準が当たっている側面が選ばれること（東西から見ても、南北から見ても）

## 4. 実装時に確認すること

- 現行の対象の判定が、どこで、どのような条件になっているか（確認済み: `IGrowable` だけが入口で、除外は設定 `growthExcludedBlocks`）
- サトウキビ、サボテン、ネザーウォートが、Forge 1.12.2 のソースで、実際に `IGrowable` を持たないこと。持っていれば、追加リストは不要になる
- 草ブロック、背の高い草、キノコなどが、1.1.0 で対象になっているか
- サトウキビとサボテンの成長条件（上が空気であること、柱の高さの上限）と、1回の `randomTick` で進む量（成長段階）。ネザーウォートの成長の確率
- 「柱の一番上の節」の探し方（上に同じブロックが続く間、上へ進む）と、その節の `randomTick` の呼び方
- 同じ大きさの面が複数あるときの、弱点を出す面の選び方（§2.6。確認済み: 現行は X 軸の面を選ぶ）
- 高さ1のサトウキビの、土台の条件（`checkForDrop`）の判定を、弱点を出すかどうかに使う方法（§2.4）

## 5. 未決事項（仮置きで進めてよい）

- 除外リストの中身（§2.3）。既存の設定なので、サーバーの管理者が変えられる
- ネザーウォートの成長の遅さ（最後まで約6ヒット）。今回は調整しない。気になれば、後で、ブロックごとの回数の調整を考える
- スイカ・カボチャのくきが、育ちきると対象から外れ、実を付けるのは速められない。今までどおりで、今回は変えない
- 対象のリストの設定化（1.2.0）

## 6. ユーザーに確認してもらうこと（クライアントの見た目・操作は、Claude Code が確認できない）

ビルドした jar を、ホストの Minecraft で試す。

- サトウキビ: 高さ1、高さ2の柱で、素手で右クリックを押しっぱなしにすると弱点が出て、当てると伸びること。柱のどの節に弱点が出ても、一番上の節が伸びること
- サトウキビ: 高さ3の柱には、弱点が出ないこと
- サボテン: サトウキビと同じであること
- ネザーウォート: ソウルサンドに植えたものに、弱点が出て、当てると成長段階が進むこと。最後まで育ったものには、弱点が出ないこと
- 草ブロック、背の低い草、背の高い草、キノコには、弱点が出ないこと
- 小麦、苗木、スイカ・カボチャのくきは、今までどおり動くこと
- 1.1.1 のサーバー（またはクライアント）と、1.1.2 のクライアント（またはサーバー）で、接続できること
