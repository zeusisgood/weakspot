## 1. 耐久回復の不具合の修正

### 1.1 不具合
弱点に当てるだけで、ブロックを壊さなくても、耐久が回復し続ける（ブロックを壊さずに、マークを狙い続ければ、無限に回復できる）。

考えられる再現の方法（確認用）:
- 長押しを始めてヒットを取り、壊れる前に離して、また押すことを繰り返す（離しても弱点は約2秒残るので、すぐ次のヒットが取れる）
- 黒曜石など、ツールの等級が足りずに、壊れるまでとても時間がかかるブロックを、掘り続ける

### 1.2 直し方
`SPEC_v1.1.md` の §4（耐久回復）のとおりにする。要点:
- 採掘ヒットは、いったん「**未確定**」として持ち、ブロックの**破壊を確認したとき**に、回復の数え方に足す。壊さずにやめたり、別のブロックに移ったり、破壊が中断されたりしたら、未確定のヒットを捨てる
- 精算のしかた:
  1. 数え方 += 確定したヒット数
  2. 回復の回数 = 数え方 ÷ `hitsPerRepair`（切り捨て）
  3. 数え方 = 数え方を `hitsPerRepair` で割った余り（余りだけを次の破壊へ持ち越す。上限で回復できなかった分は捨てる）
  4. 回復する耐久 = min(回復の回数 × `repairPerStep`、`maxRepairPerBreak`)
- 手に持っているツール（メインハンド）に回復をかける。耐久のないもの（素手など）や、耐久が減っていないものには、かけない（数え方は進む）
- 回復は、ブロックが壊れる**前**（ツールの耐久が減る前）にかける。壊れたあとだと、耐久が残り1のときに、ツールがなくなってしまうため
- 破壊が途中で取り消された（イベントがキャンセルされた）ときは、回復をかけたままにしない

### 1.3 初期値と設定
- `hitsPerRepair` = 5、`repairPerStep` = 1、`maxRepairPerBreak` = **1**（新規）
- `maxRepairPerBreak` は、**サーバーだけが使う項目**なので、`SyncedSettings` には入れない（通信内容は変えない）。0 にすると、耐久回復が無効になる
- `weakspot.cfg` に、`[サーバー]` の項目として足す。README の設定表にも足す（`CLAUDE.md` の「設定を追加するときは、README の設定表の該当する方にも追加する」）
- 既存の `weakspot.cfg` には、次に起動したときに、初期値で追加される（設定キーの削除や意味の変更ではないので、互換性は保たれる）

### 1.4 保存データ
- 「回復の数え方」の余りは、**メモリだけ**に持つ（再ログインで 0 に戻ってよい）。保存データの形式は変えない
- 節目（`rewardHits`）の数え方と報酬は、変えない。節目の耐久回復は、達成ごとの1回きりなので、`maxRepairPerBreak` の対象外
- 統計の「弱点ヒット数」は、確定前のヒットも数える（変更なし）

### 1.5 既知の性質
- 「耐久力」エンチャントのツールは、耐久が減る確率が下がる。そのため、1回の破壊での回復が、減った耐久を上回ることがあり、硬いブロックを掘り続けると、少しずつ回復する。壊さない限り回復しないので、問題として扱わない。気になる場合は、`maxRepairPerBreak` を下げる

### 1.6 単体テスト
精算の計算は、Minecraft に依存しない純粋な計算として、`common/`（`Milestones` の隣、または別クラス）に置き、単体テストを書く。

- 壊さずに捨てた場合（未確定のヒットが、数え方に足されない）: 回復は 0
- 1回の破壊で、確定したヒットが5未満: 回復は 0、数え方が持ち越される
- 1回の破壊で、確定したヒットが5〜9: 回復は 1
- 硬いブロックで、確定したヒットが50: 回復は `maxRepairPerBreak`（1）まで。余りは 5 未満だけ持ち越される
- ツールの耐久が減っていない場合: 回復は 0、数え方は進む
- `maxRepairPerBreak` = 0: 回復は常に 0

## 3. 実装時に確認すること

- 1.1.0 の実装が、上のとおりになっているか。`CLAUDE.md` には、未確定のヒットや `maxRepairPerBreak` の記述が見当たらない。すでに入っていれば、この仕様書の作業は不要（README の更新履歴の該当行も入れない）
- 破壊イベントが、ツールの耐久が減る前に来るか。耐久が残り1のツールで、回復をかけてから壊した場合に、ツールが残ること
- 破壊が途中で取り消されたとき、回復をかけたままにならないか。未確定のヒットを捨てるタイミング（長押しをやめたとき、別のブロックに移ったとき）の検出方法
- 採掘のヒットを受け付ける処理（`ServerBoostTracker`）と、報酬の処理（`MiningRewards`）の、どちらに未確定のヒットを持たせるか

## 4. ユーザーに確認してもらうこと（Claude Code が確認できない）

ビルドした jar を、ホストの Minecraft で試す。

- ブロックを壊さずに、弱点を当て続けても、耐久が回復しないこと（長押しをやめて、また押す繰り返しでも）
- 壊したときに、傷みが減ること（5ヒットごとに1回復。ヒットが少ないブロックでは、持ち越されること）
- 黒曜石のような硬いブロックで、1回の破壊での回復が、1までであること
- `maxRepairPerBreak` を 0 にすると、回復しないこと
- 耐久が残り1のツールで、ヒットを重ねてから壊したときに、ツールが残ること
- 1.1.0 のサーバーに、1.1.1 のクライアントで接続できること（逆も）
