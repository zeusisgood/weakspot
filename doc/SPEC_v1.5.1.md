# 弱点破壊 Mod 追加仕様書（v1.5.1）

`SPEC_v1.5.md`（Mod 1.5.0）に対する**パッチ**の仕様。ここに書かれていないことは、それと現行実装のままとする。
仕様書は、リポジトリの `doc/` ディレクトリに置く（この仕様書は `doc/SPEC_v1.5.1.md`）。
仕様と食い違う実装をする場合は、`CLAUDE.md` のリリースの流れ（止まる条件）に従う。

- 対象: Minecraft Java Edition 1.12.2 / Forge 14.23.5.2860
- 前提: 1.5.0 がリリース済み。1.5.0 の内容を土台にする
- 内容: サーバーとクライアントの Mod の版（パッチ）が違うときに、ログインした本人・OP 権限を持つプレイヤー・サーバーのログに知らせる。同じマイナーなら今までどおり接続できる（片方だけ古いと、新しい側の機能が中途半端に動いて分かりづらいため。1.4.4 のディスペンサーで実際に起きた）
- この仕様書の内容は、Mod のバージョン **1.5.1** として、リリースする

---

## 0. バージョンとパッチの制約

- バージョンは 1.5.0 → **1.5.1**（`build.gradle` の `version` と `WeakSpotMod.VERSION` の2か所を、そろえて変える）
- `WeakSpotMod.ACCEPTED_VERSIONS`（`[1.5,1.6)`）は、変えない。接続できる範囲は今までどおり
- **パッチなので、互換性を破る変更を入れない**。パケット・`SyncedSettings`・保存データ・設定は変えない

## 1. 相手の版の知り方（サーバー）

- クライアントの Mod の一覧は、接続のときの Forge の手順で、サーバーに届いている（`NetworkDispatcher.get(player.connection.netManager).getModList()`。Mod の ID → 版）。そこから `weakspot` の版を読む
- 読めないとき（一覧がない、`weakspot` がない）は、何もしない
- 版の比べ方は `common/ModVersions`（`1.5.1` のような「.」区切りの数を、前から数として比べる。数でない部分は無視）。単体テストを書く

## 2. 知らせ

プレイヤーがログインして **40 tick（2 秒）後**に、版が違えば知らせる（すぐだと、ログインのメッセージに埋もれるうえ、プレイヤーの言語の設定がまだ届いていないため）。その前にログアウトしたら、知らせない。

| 宛先 | 条件 | 内容（日本語） |
|---|---|---|
| 本人 | クライアントが古い | あなたの弱点破壊 Mod は %s です（サーバーは %s）。一部の機能が正しく動かないことがあります。新しい版に更新してください |
| 本人 | サーバーが古い | サーバーの弱点破壊 Mod は %s です（あなたは %s）。一部の機能が正しく動かないことがあります。サーバーの管理者に更新を頼んでください |
| OP 権限を持つ、オンラインのほかのプレイヤー | 違うとき | %s さんの弱点破壊 Mod は %s です（サーバーは %s） |
| サーバーのログ（WARN） | 違うとき | `Player <名前> joined with weakspot <クライアントの版> (server <サーバーの版>)`（英語） |

- チャットの色は黄色（`TextFormatting.YELLOW`、`#FFFF55`）
- 「OP 権限を持つ」は、サーバーのコマンドを使える（`PlayerList#canSendCommands`）プレイヤー。本人が OP でも、OP 宛ての知らせは本人には出さない（本人宛てのものが出るので）
- **文章はサーバーで作る**。クライアントが古いときは、新しい翻訳キーを持っていないので、翻訳キーで送るとキーのまま出てしまうため
  - サーバーは、Mod の jar の中の言語ファイル（`assets/weakspot/lang/<言語>.lang`）を読み、受け取るプレイヤーの言語の設定（`EntityPlayerMP` の非公開の `language`、SRG `field_71148_cg`。`Reflect.field` で読む）の文章で作る。その言語のファイルやキーがなければ `en_us`
  - 翻訳キーは `weakspot.version.clientOlder` / `weakspot.version.serverOlder` / `weakspot.version.op`。`en_us.lang` と `ja_jp.lang` の両方に足す
  - 言語ファイルの読み込みと、`%s` の埋め込みは `server/ServerLang` に置く

## 3. README

- 「導入」の節に、「サーバーとクライアントは同じ版にそろえてください。パッチ（1.5.0 と 1.5.1 など）が違っても接続はできますが、新しい側の機能が正しく動かないことがあります。1.5.1 からは、版が違うとログインしたときにチャットで知らせます」の旨を書く
- 「最新版」の行を 1.5.1 にし、「更新履歴」に 1.5.1 を追加する（通信内容は変わっていない）
- 「開発」の節の仕様書へのリンクに `doc/SPEC_v1.5.1.md` を足す
- ガイドの本は変えない（遊び方ではないため）

## 4. `CLAUDE.md` に書くこと

- 「仕様の正本」の一覧に `doc/SPEC_v1.5.1.md` を足す。現行のバージョンを 1.5.1 に
- 版の違いの知らせ（`server/VersionCheck`・`server/ServerLang`・`common/ModVersions`）を足す

## 5. ユーザーに確認してもらうこと

- サーバーを 1.5.1、クライアントを 1.5.0 にしてログインすると、2 秒ほどで本人に「あなたの弱点破壊 Mod は 1.5.0 です…」が日本語で出ること（1.5.0 のクライアントでも、キーのままにならないこと）
- そのとき、ほかの OP のプレイヤーのチャットと、サーバーのログにも出ること
- 同じ版同士では、何も出ないこと
