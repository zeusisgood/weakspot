# 弱点破壊 Mod 追加仕様書（v1.2.3）

`SPEC_v1.2.2.md`（Mod 1.2.2）に対する**パッチ**の仕様。ここに書かれていないことは、それと現行実装のままとする。
仕様書は、リポジトリの `doc/` ディレクトリに置く（この仕様書は `doc/SPEC_v1.2.3.md`）。
仕様と食い違う実装をする場合は、`CLAUDE.md` のリリースの流れ（止まる条件）に従う。

- 対象: Minecraft Java Edition 1.12.2 / Forge 14.23.5.2860
- 前提: 1.2.2 がリリース済み。1.2.2 の内容を土台にする
- 内容: 設定ファイルを読み直すコマンド `/weakspot reload` を足す（サーバー）
- この仕様書の内容は、Mod のバージョン **1.2.3** として、リリースする

---

## 0. バージョンとパッチの制約

- バージョンは 1.2.2 → **1.2.3**（`build.gradle` の `version` と `WeakSpotMod.VERSION` の2か所を、そろえて変える）
- `WeakSpotMod.ACCEPTED_VERSIONS`（`[1.2,1.3)`）は、変えない。1.2.x 同士は、互いに接続できる
- **パッチなので、互換性を破る変更を入れない**（パケット・`SyncedSettings`・保存データ・設定キーは変えない）

## 1. 問題

専用サーバーでは、Forge の設定画面が使えないので、`weakspot.cfg` を書き換えたら、サーバーを再起動するしかない。
Forge 1.12.2 には、設定を読み直すコマンドがない。

## 2. 変更: `/weakspot reload`

- 既存の `/weakspot` コマンドに、サブコマンド `reload` を足す（引数なし。権限レベル 2 はそのまま）
- 動き
  1. `weakspot.cfg` をファイルから読み直し、`WeakSpotConfig` のフィールドに反映する
  2. 接続中の全員に、サーバーの設定（`SettingsMessage`）を送り直す（設定画面で変えたときと同じ）
  3. 節目の数の食い違いの警告（`warnIfMisconfigured`）を、もう一度確かめる
  4. 実行した人に「設定を読み直しました」と返す
- 読み直し方（Forge の `ConfigManager` の制約）
  - 起動後の `ConfigManager.sync` は、フィールドの値をファイルへ書き出す向きに動く。ファイルの値をフィールドへ読み込むのは、その項目が「変わった」（`Property#hasChanged`）ときだけ（Forge の設定画面は、この仕組みを使っている）
  - そこで、`ConfigManager` が持っている `weakspot.cfg` の `Configuration`（非公開の `CONFIGS`。Forge のクラスなので、名前は開発環境と実際の環境で同じ）をリフレクションで取り出し、`load()` でファイルから読み直す。すべての項目に「変わった」の印を付けて（同じ値を `set` し直す）、`ConfigManager.sync` を呼ぶ
  - ファイルにない項目は、今の値のまま（ファイルに書き足される）
  - 取り出せなかったときは、警告をログに1回出し、「読み直せませんでした（再起動してください）」と返す
- 1人プレイ・LAN でも使える（同じファイルを読み直す。`[クライアント]` の項目も読み直される）
- 読み直しは、次のヒット・判定から効く。進行中の機械の加速などは、そのまま終わるまで続く

## 3. 文字列

- `weakspot.command.usage` に `reload` を足す。`weakspot.command.reload`（成功）と `weakspot.command.reload.failed`（失敗）を `en_us.lang` と `ja_jp.lang` に足す
- README のコマンドの説明に足す

## 4. 確認事項

- ビルド・テストが通ること
- ゲーム内での確認（ユーザーに依頼）: サーバーの `weakspot.cfg` を書き換えて `/weakspot reload` を実行すると、再起動せずに反映されること（例: `mushroomGrowChance` を 1.0 にすると、キノコが1回で育とうとする）
