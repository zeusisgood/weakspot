# 仕組み（開発者向け）

[← README に戻る](../README.md)

コードの構成と、各機能の仕組みの詳細です。約束事（守ること）は [../CLAUDE.md](../CLAUDE.md)、遊び方は [play.md](play.md)、設定の一覧は [config.md](config.md) を参照してください。仕組みを変えたら、ここも直します。


## 全体

サーバーとクライアントは、同じマイナー同士なら接続できる（`@Mod` の `acceptableRemoteVersions` = `WeakSpotMod.ACCEPTED_VERSIONS`）。パッケージは `io.github.zeusisgood.weakspot`。

弱点の種類は `common/HitKind`（一覧はコード。通信は番号。`key()` が設定・翻訳キーの小文字の名前。下の各項目）。基本の3種類: **採掘**（左の長押し。対象は、壊せて、今の破壊速度で 1 tick に進む量 `getPlayerRelativeBlockHardness` が 1.0 未満のブロック。1.0 以上のブロックはバニラの `PlayerControllerMP.clickBlock` がクリックした瞬間に壊し、「掘っている」状態にも入らないので、弱点も耐久バーも出せない。素手の土などは対象）、**成長**（素手で右クリックを押しっぱなし。成長できる `IGrowable` と、追加リスト `growthExtraBlocks` に書いたブロック）、**機械**（しゃがんで両手が空のまま右クリックを押しっぱなし。`ITickable` の TE と、予約された tick で動くレッドストーンの部品 `RightClickTargets.isScheduledMachine` = `BlockRedstoneDiode` / `BlockObserver` / `BlockDispenser`）。耐久回復は採掘だけが対象。節目は採掘・種類ごと・合計。

- `common/`: Minecraft に依存しない純粋な計算。クラスの一覧は `common/` を見る。単体テストは主にここにある（ほかに `compat/`・`config/` の golden テスト、`resources/` のファイルの揃い具合のテスト、ルートの `HeldItemsTest`）。
- `RightClickTargets`（両側）: 右クリックの弱点の対象判定。クライアントとサーバーで同じ条件（同期した設定）を使う。
  - 成長の対象（`isGrowable`）: 設定 `growthExcludedBlocks`（除外リスト。草ブロック・草などは初期値で外す。キノコは対象）になく、追加リスト `growthExtraBlocks`（サーバーの値を同期する）にあるブロックは、書いた状態の条件（`common/BlockFilter` / `GrowthFilters`。1行は `modid:block` か `modid:block[prop=pattern,...]`、pattern は `a-b` の数の範囲・`*` を含む形・完全一致。同じブロックの複数行はどれか。条件なしの行はいつでも。ただし `GrowthFilters.DEFAULT_CONDITIONS` の初期の条件 = ネザーウォート `age=0-2`・`ic2:rubber_wood` `state=dry_*`）を満たすとき。追加リストにない `IGrowable` は `canGrow` が true のとき（追加リストのほうを優先）。読めない行は無視して `warnIfMisconfigured` でログに警告。条件の判定は IC2 などのクラスに依存せず、状態のプロパティの名前と値の名前（`IProperty#getName`）で行う。`SyncedSettings.growthFilters()` が読んだものを使い回す。
  - **自動の対象（`RightClickTargets.isAutoGrowable`）**: `getTickRandomly()` が true で、`IGrowable` でなく、追加リストにも対象外リストにもないブロック（Random Things の Time in a Bottle と同じ考え方）。`classify` で機械・成長・収穫のあと、**しゃがんでいるとき**だけ `GROWTH`（サーバーはヒットごとに `classify` で確かめるので、しゃがみ続ける）。サーバーとクライアントの両方が 1.11.2 以上のときだけ（クライアントは `proxy.serverSince`＝`ServerFeatures.since`、サーバーは `PlayerText.clientSince`。版が分からないときは true）。「まだ対象か」（`isGone`・`grow` のくり返し）は `isGrowthTarget` = `isGrowable` か `isAutoGrowable`。自動の対象には `GrowthWarnings` を呼ばない。ゲームルール `randomTickSpeed` が 0 以下なら、自動の対象には効果をかけない（`RightClickHits.grow`。IC2 の `BlockFoam.randomTick` はそのとき `IllegalStateException` を投げる）。
  - 柱の植物（`RightClickTargets.COLUMN_BLOCKS` = サトウキビ・サボテン）は、追加リストの条件に加えて、柱の高さ < 3 で一番上のすぐ上が空気（高さ1のサトウキビは土台 `BlockReed#canBlockStay` も）をコードで判定する。バニラの `updateTick` の条件と同じ。育つのは柱の一番上の節だけなので、サーバーの効果は `growthTarget` で柱の一番上にかける。効果は、どのブロックも `randomTick` の追加（IC2 のゴムの木は、IC2 の `randomTick` が 1/7 で `dry_*` を `wet_*` に戻す）。弱点の面は、当たり判定の箱が1マス全体なら照準の面（木の幹は上面が隠れるため）、それ以外は一番大きい面。成長バーは `age` / `stage` の整数のプロパティがあるときだけ（既知の問題として `doc/play.md` に書いた）。対象を条件どおりに右クリックしたら、`RightClickBlock` をメインハンドで SUCCESS にしてキャンセルし、通常動作（GUI、オフハンドの設置など）を止める。クライアントでキャンセルしてもバニラは右クリックのパケットを送るので、サーバーでも発火し、そこで「直前に右クリックした」ことを記録する。右クリックを押しっぱなしにすると、バニラは 4 tick ごとに右クリックする。
- `client/`（`@EventBusSubscriber(value = Side.CLIENT)`。専用サーバーではロードされない）: 弱点の状態、ヒット判定、描画、ヒット音、クライアント側のブースト。弱点は一度に1つ（`ClientWeakSpotHandler.spot`）。自分のブロックの弱点と当てたときの光る輪は、目との間に水・溶岩のブロックがあれば深度テストを切って描く（`WeakSpotRenderer.behindLiquid`。1.12.2 では水の面も深度を書くので、水面の後ろの弱点が隠れていた。照準の先のブロックは液体のほかにさえぎる物がないので、透けて見えることはない）。
  - ヒット判定は `RenderWorldLastEvent` で**毎フレーム**行う（tick 単位だと素早い照準移動を取りこぼす）。右クリックの押しっぱなしは `keyBindUseItem.isKeyDown()` で見る。成長の弱点は一番大きい面（多くは上面）に出し、照準がその面に当たっているときだけヒットにする。同じ大きさの側面が複数あるとき（サトウキビなど）は照準の側面を選び、今の面が見えている間は変えない（`FaceMath.growthFaceAxis`）。育って当たり判定の箱が変わったら出し直す。
  - ブーストの時間枠は `ClientTickEvent` START で増える `clientTick` で数える。`PlayerControllerMP` は tick ごとに進捗を積算するので、枠内の tick だけ倍率を掛ければよい。
  - ヒット音（`HitSounds`）: 楽器と音量は各自の設定（`myHitSound` / `myHitVolume`、`othersHitSound` / `othersHitVolume`。「プレイヤー」のカテゴリ）。自分の音と試聴は距離なし（`AttenuationType.NONE`）、他のプレイヤーの音はブロックの位置から。音の高さは連続ヒット数（`common/HitStreak`。`OwnHits.STREAK`。種類・ブロックをまたいで続き、一定時間ヒットがないとき・死亡・リスポーン・ディメンション移動・ワールドを出たときに 0 に戻る）から `HitPitch` が求める。音階は各自の設定（`hitScaleType` / `hitScaleDirection` / `hitScaleOctaves`）から `HitSounds.scale()` が `common/HitScale`（種類の半音の並び・往復の周期・2 オクターブなら度数 -n から）を作り、ヒット音・他プレイヤーの音・節目の駆け上がり（`oneOctave` / `twoOctave`）・途切れの音（`HitPitch.breakNotes`。`ClientWeakSpotHandler` が `HitStreak.expire` の結果を見て鳴らす）・落下の段階の音に使う（`HitPitch` の静的な関数は初期値 `HitScale.DEFAULT`）。和音（`HitPitch.forHit` / `chordOffsets`、`hitChordEnabled`）は、度数を選んだ音階の中で数え、旋律より下に重ねる（ピッチの上限 2.0 のため。0.5 より下はオクターブ上げる）。コンボの段階と累計の節目の音は `HitSounds.playAccent` / `accentRun` / `accentScale`。駆け上がりが鳴っている間は、音の時計 `soundTick` と `duckUntil` で自分の通常のヒット音を小さくする。「サウンド」タブ（`SoundTab`）: 音のプリセット（`config/SoundPreset`。最初から入っているもの `BUILT_IN` と、マイプリセットを設定 `soundPresets` に「番号=楽器,音階の種類,動き,音域,和音」で。音量とほかの人の音は入れない）を巡るボタン（バニラのボタンは右クリックを拾わないので `SoundTab.mouseClicked` で受ける）。表示する名前は今の設定から求め（`sameSound`。最初から入っているもの → マイプリセット → 「カスタム」）、選んだものは保存しない。保存・読み込みは `MyPresetsScreen`（中身の表示は `describe`）。ランダムは `SoundPreset.random`（楽器は打楽器を外した `RANDOM_SOUNDS` から。今と同じ組み合わせは引き直す）。
  - コンボの表示（`ComboHud`）: 同じ連続ヒット数を HUD（`RenderGameOverlayEvent.Post` の `ALL`。F1 で隠しているときは描かない）に出す。色の段階は `ComboTier`、節目は `ComboMilestones`、虹色の速さは `ComboDisplay.rainbowPeriodMs`。節目の音・花火・タイトルは `ComboEffects`（花火は `MilestoneEffects.comboFireworks` = `World#makeFireworks`、クライアントだけ。タイトルは自前で描き、`MilestoneEffects.lastShownTick` を見て累計の節目のタイトルを優先する）。時間は `clientTick`（一時停止中は止まる）。サーバーには何も送らない。**種類の表示**（`ComboHud.drawKindLabel`）: 直前にヒットした種類（`ComboHud.onHit` に種類も渡す）の弱点が今出ている間（採掘・機械は `ClientWeakSpotHandler.blockSpotActive`、収穫は収穫か成長（植え直した直後）の弱点、照準のまわりは `AimSpots.isShown`）だけ出す。掛け数を出す種類は `HitKind.usesComboFactor`（翻訳キー `weakspot.combo.kind`、種類名は `weakspot.kind.<key>`、数字は `String.valueOf`、色は `MarkerLook.color`）。機械の速さは `SyncedSettings` の `machineBoostMultiplier` / `machineBoostMaxMultiplier` から、サーバーと同じ `MachineComboBoost.multiplier` で求める（表示は `MachineComboBoost.speedLabel`）。ディスペンサー・ドロッパーは `ClientWeakSpotHandler.dispenserSpotActive` と `ScheduledBoost.dispenseCount(速さ, machineBoostMultiplier)`。**次の段階までのゲージ**（`ComboHud.drawFactorGauge`）: `ComboFactor.progressToNext` を、次の段階の数字の色（`ComboHud.colorOf(ComboFactor.nextStep)`）で描く。**ヒット音の和音**: 段階ごとの形は `HitPitch.chordOffsets`（sus4 の解決の音は `resolveFor`）。**初めて届いた段階の全員への知らせ**: `ServerStats.countStreak` で、ヒット前の累計の `maxStreak` を超えた数が段階（`ComboMilestones.isStep`）なら `MiningRewards.broadcastCombo`（翻訳キー `weakspot.milestone.broadcast.combo`、色は段階に近いチャットの 16 色）。
  - 統計画面（`StatsScreen`、K キー。共通の枠が `StatsScreen`、タブの中身が `StatsTab`・`SoundTab`・`KindsTab`（土台 `StatsScreenTab`））: 「統計」タブはサーバーから届いた数字を表示するだけ（開いたとき・設定画面から戻ったときに要求）。「サウンド」タブは楽器・音量・試聴で、`WeakSpotConfig.save()`（`ConfigManager.sync`）で `weakspot.cfg` に保存する。「設定画面を開く」は `WeakSpotGuiFactory.create`（Mods メニューと同じ `GuiConfig`。他人のサーバーに接続中は2行目に注意書き）。設定画面はファイルのカテゴリではなく `config/SettingGroups` のまとめ（種類・用途。サーバーとクライアントの項目を混ぜる）で組む（`ConfigManager` の `Configuration` の `Property` から `ConfigElement` を作り、`DummyCategoryElement` にまとめる。値の保存と反映は Forge の画面と同じ流れ）。`configVersion` と `lastSeenVersion` は出さない（`SettingGroups.HIDDEN`）。項目の名前は翻訳キー `weakspot.<カテゴリ>.<小文字のキー>`、まとめの名前は `weakspot.gui.<まとめ>`。「統計をリセット」（今回と累計の両方。`ServerStats.resetTotal`）。
  - 他のプレイヤーのマーク（`OtherMarkers`）: 自分の採掘・機械・成長・収穫（受け取る側は、機械・成長も採掘と同じブロックのマークとして描く。掘る前の採掘の弱点は送らない）と動物の弱点が出た・動いた・消えたときに送り（`markerSendMinIntervalTicks` で間引き、出ている間は 20 tick ごとに送り直す）、届いたマークは 60 tick 更新がなければ消す。描画は `WeakSpotRenderer` で、色と濃さは各自の設定。同じブロックの同じ面で位置が変わったマークは、前の `WeakSpot` を使い回して、最後に知っている位置から動かす（同じ位置の送り直しは動かさない）。
  - マーカーの表示位置と当たり判定の位置は別。`WeakSpot.u` / `v` は当たり判定の位置で、ヒットの瞬間に移動先へ変わる。表示位置は `WeakSpot.motion`（`common/MarkerMotion`）で、実時間（`Minecraft.getSystemTime()`）の 80 ms で ease-out に動き、通った道に残像を 4 個（150 ms で消える）残す。移動中の次のヒットは、前の移動先から動き直す。出し直し（新しい弱点、別の面・ブロック）はその場で切り替える。設定 `weakSpotTrailEnabled`（`[クライアント]`）でオフ。`WeakSpotRenderer` は表示位置に描き、送信（`OtherMarkers.sendOwn`）とヒット判定は当たり判定の位置を使う。
  - 耐久バー: 自分が掘っているブロックの残りの耐久（1 − 破壊の進み具合）を、採掘の弱点と同じ面の「下」の余白（下の辺から中心 0.05、太さ 0.06、面の幅の 80%。実際の当たり判定の箱の面）に、緑 `#3DDC84` と半透明の黒の背景で描く。側面は下の辺、上面・下面はプレイヤーに一番近い辺が「下」。左から伸び、プレイヤーの右手の側から縮む（形の計算は `common/BlockHealthBar`）。`WeakSpotRenderer` がマーカーより先に（下に）描く。出すのは、採掘の弱点がこのフレームの照準の面に出ていて、`PlayerControllerMP` が今そのブロックを掘っているときだけ（長押しをやめる・壊れると `getIsHittingBlock()` が false になり、すぐ消える）。設定 `blockHealthBarEnabled`（`[クライアント]`）。
    - 破壊の進み具合と掘っているブロックは、`client/MiningProgress` が `PlayerControllerMP` の非公開のフィールドを `Reflect.field` で読む（見つからなければバーを出さない）。進み具合は tick ごとに積まれるので、`ClientTickEvent` START（その tick の進捗の前）で前の値を覚え、フレームごとに補間する。
  - 成長バー（`GrowthBar`）: 成長の弱点が今出ている作物の足元に、黄 `#FFD23F` のバーを描く。値は名前が `age` の整数プロパティ（なければ `stage`）÷ 最大。柱（サトウキビ・サボテン）は `growthTarget` の一番上の節の年齢。**描き方は汎用の部品 `WorldBar.draw`（中心のワールド座標・幅・太さ・値・色を渡すと、プレイヤーの方を向いた水平のバーを、左から伸ばして描く。深度テストは切る）。動物の足元のバー（`AnimalBar`）が、これを流用している**。設定 `growthBarEnabled`。
  - 他のプレイヤーのマークの形: `common/MarkerShape`（CIRCLE / RING / DIAMOND / SQUARE。頂点数・回転・半径の倍率を持つ）。設定 `otherMarkerShape`（初期値 RING）。`WeakSpotRenderer.drawMarker` が形を受け取る。自分のマークは CIRCLE 固定。
  - 弱点の一時オフ（`ToggleKeyHandler`、HOME キー（J は JourneyMap と重なるため）、設定 `weakSpotsEnabled`）。オフの間に止める処理の一覧: ①弱点の表示・ヒット判定（`onRenderWorldLast` で `updateAim` を呼ばない）と通知（ヒットが起きないので `HitMessage` も出ない）、②自分のマークの送信（`spot` が null になり、`OtherMarkers.sendOwn` が「消えた」を送る）、③ブースト（`onBreakSpeed`、`boostPos`）、④耐久バー・成長バー（`onRenderWorldLast`）、⑤クライアント側の右クリックの抑止（`RightClickTargets.onRightClickBlock` が `world.isRemote` のときに返る）。まとめて `ClientWeakSpotHandler.stopOwnWeakSpots`。オン・オフはサーバーにも伝わる（`SwitchMessage`、C→S。ログイン時と、`weakSpotsEnabled` が変わったときに `ToggleKeyHandler.syncToServer` が毎 tick 比べて送る。設定画面での変更も拾う）。サーバーは `ServerSwitches`（オフのプレイヤーの `Set<UUID>`。届く前はオン）で、オフのプレイヤーについて、右クリックの抑止（`RightClickTargets`・`AnimalTargets`）、ヒットの受け付け（採掘・成長・機械・動物・釣り・弓・近接）、ブースト、マークの転送（オフにした瞬間に `MarkerRelay.onMarker(player, null)`）を止める。
  - 節目の演出（`MilestoneEffects`）: タイトル、チャット1行、花火、音階の駆け上がり。777 は虹色で派手にする。
  - ガイドの本（`GuideBook`（両側）・`server/GuideBookGiver`）: 表紙・目次 3 ページ（`ClickEvent.Action.CHANGE_PAGE` で飛ぶ）・本文（`GuideBook.CONTENT`。章 `Chapter` ごとに色 `DARK_BLUE` / `DARK_GREEN` / `DARK_RED` / `DARK_PURPLE` / `DARK_AQUA` / `GOLD`。題、小見出し `weakspot.guide.head.<名前>`（`DARK_GRAY`）と本文 `weakspot.guide.<ページ>.<名前>`、最後に「↩ 目次」）。NBT の `weakspotGuide`（`GuideBook.FORMAT` = 2）。記入済みの本の各ページは、翻訳キーの文章と、キーのページはキーバインドの文章（`TextComponentKeybind`）なので、読む人のクライアントの言語と操作設定で出る（`resolved` を付けて、サーバーが解決し直さないようにする）。初めてのログインで、永続データの `guideGiven` を見て1回だけ渡す（持ち物がいっぱいなら足元に落とす。設定 `giveGuideBook` はサーバーだけ）。統計画面の「ガイド」ボタンは、その場で作った本を `GuiScreenBook` で開く（サーバーには送らない）。
  - キーバインドの登録は `@SidedProxy`（`CommonProxy` / `client.ClientProxy`）の `init` で行う。
  - 小さい面の配置: `WeakSpotPlacer.layout` が、面の大きさに合わせて半径（下限 `weakSpotMinRadius`、上限は短い辺 × `weakSpotMaxRadiusRatio`。食い違うときは上限を優先）、縁の余白（min(`edgeMargin`, 短い辺 × 0.12)）、最小移動距離（min(`minMoveDistance`, 動ける範囲の対角線 × 0.6)）を決める。短い辺が `minFaceSize` 未満の面には出さない（`WeakSpot.spawn` などが null を返し、`spot` が null になるので、ヒット通知もマークの送信も起きない）。成長の弱点の下限は max(`growthMinRadius`, `weakSpotMinRadius`)。採掘・成長・機械・動物・他のプレイヤーのマークで、同じ計算を使う。

  - **ゴーストブロックの対策（issue #38）**: バニラ（`NetHandlerPlayServer.processPlayerDigging`）は、掘り終わり（STOP）と中断（ABORT）のあとはブロックが空気でなければ `SPacketBlockChange` を返すが、掘り始め（START）には返さない。クライアントの `PlayerControllerMP.clickBlock` は START を送ってから「1 tick で壊れるか」を判定し、壊れるならその場で壊す（STOP は送らない）。クライアントの採掘のブーストがクリックし直しても続くと、サーバーで戻ったブロックをクリックし直したとき、クライアントだけでその場で壊れ、サーバーには残る（見えない壁）。対策は 3 つ:
    - クライアント（`MiningBoost.onLeftClickBlock`）: 自分の `LeftClickBlock`（`clickBlock` の中、その場で壊れるかの判定より先）で、ブースト（`boostPos`・`boostHitTick`・`boostFactor`）を捨てる。サーバーもクリックのたびに `Mining` を作り直すので、同じになる。掘る前のヒット（`preHitPos`）と、待ちを 0 にするための `hitBlock` は残す。
    - サーバーの再送（`ServerBoostTracker.queueResend` / `onServerTick`）: 採掘の `LeftClickBlock` で、クリックした座標と前の `Mining` の座標を覚え、その tick の終わり（`ServerTickEvent` の END）に今の状態を `SPacketBlockChange` で本人にだけ送る（空気でも送る。クリエイティブ・採掘を受け付けないプレイヤーは送らない）。同じ状態を送るだけなので、掘っている最中に届いても何も変わらない。古いクライアントや、ほかの Mod で速さがずれたときのゴーストも、同じ tick のうちに戻る。
    - 保留中の破壊（`ServerBoostTracker.keepDelayed`・`DELAYED`）: バニラの `blockRemoving` は、進捗が 0.7 未満で掘り終わりが届くと、破壊を保留にする（`receivedFinishDiggingPacket` / `delayedDestroyPos`、SRG `field_73097_j` / `field_180241_i`。**1 枠だけ**で、埋まっていると次の不足は捨てられて STOP の返事でブロックが戻る）。保留中のブロックは `updateBlockRemoving` で「今の速さ × 経過 tick ≥ 1.0」になったら壊れる。違うブロックを掘り始めたとき、前の `Mining`（追加進捗があり、空気でない）がバニラの保留と同じ位置なら `DELAYED` に残し、`BreakSpeed` でその位置にも追加進捗を掛ける（経過 tick は、その `Mining` を掘り始めた tick から。バニラの保留も同じ）。保留が読めなければ、前の `Mining` をいつも残す（バニラが保留にしていなければ、そのブロックを誰も掘らない限り効かない）。保留中のブロックをクリックし直したら捨てる。保留のあとに壊れたら（`BreakEvent`）、今掘っているブロックと同じく統計・耐久回復に数える。
  - **掘る前のヒット**: クライアントは、掘っていない（`getIsHittingBlock()` が false）・右クリックを押していないときに、照準のブロックに採掘の弱点を出す（`ClientWeakSpotHandler.aimPreDig`、`WeakSpot.preview`。不透明度 0.4、照準が外れたら次の tick で消す、`OtherMarkers` に送らない。対象は `MiningBoost.isPreDigEligible` = 壊せる・空気でない・クリエイティブでない。1 tick で壊れるブロックも）。当たるのは左クリック（`keyBindAttack`）を押している間だけ（照準を合わせるだけで当たると、ブロックを交互に見るだけでヒット音とコンボの表示が増え続ける）。当てられるのは掘る前に 1 回（`MiningBoost.hasPreHit`。`BoostMath.PRE_DIG_TICKS` = 20 tick）。ヒット音・コンボの表示・`HitMessage` は当てた瞬間、ブーストは同じブロックを掘り始めたとき（`MiningBoost.onDigging`）。サーバーの `onHit` は、`Mining` がない・位置が違う・掘っていない（`PlayerInteractionManager` の非公開の `isDestroyingBlock`、SRG `field_73088_d`。読めなければ位置だけで見る）ヒットを、プレイヤーごとに 1 つの予約（`RESERVED`）にする（`HitGate.accept`・統計は呼ばない）。`onLeftClickBlock` で同じ位置を `PRE_DIG_TICKS` のうちに掘り始めたら、`Mining` を作った直後に `apply`（今の `onHit` の本体。間隔と `lastHitTick` は予約した tick で数える）で確定し、`eligible` を「壊せる・空気でない・クリエイティブでない」にする（1 tick で壊れるブロックは、バニラがこのイベントのあとに壊すので、統計・耐久回復に間に合う）。ログアウトで捨てる。
  - **次を掘るまでの待ち**: `MiningBoost` が当てたブロック（掘る前・掘っている途中）を覚え、`ClientTickEvent` の END でそこが空気になっていたら、`PlayerControllerMP` の非公開の `blockHitDelay`（SRG `field_78781_i`。バニラは壊した tick に 5 にする）を 0 にする。サーバーはこの待ちを確かめていない。待ちを 0 にすると、サーバーで戻ったブロックをすぐクリックし直しやすくなるが、クリックのたびにブーストを捨てるので、ゴーストにはならない（上の「ゴーストブロックの対策」）。
  - `RightClickHits`: 成長・機械ヒットの検証（直前 10 tick 以内にそのブロックを右クリックしたか、届く距離か、間隔、対象か）と効果（成長は `randomTick` を余分に呼ぶ。サトウキビ・サボテンは柱の一番上の節に。キノコ `BlockMushroom` は `randomTick` では広がるだけなので、代わりに確率 `mushroomGrowChance` で骨粉と同じ `grow` を呼ぶ）。育たないときの知らせ（`server/GrowthWarnings`・`common/GrowthStuck`）: 効果の前後で、叩いたブロックと `growthTarget` の `IBlockState` を比べ、暗い（`BlockCrops` / `BlockStem` / `BlockSapling` ですぐ上の `getLightFromNeighbors` < 9）なら最初のヒットで、そうでなければ `growthStuckHits` 回続けて変わらなかったらチャット（翻訳キー `weakspot.growth.dark` / `.stuck`、黄色）で知らせる。同じブロックは 600 tick、どれでも 100 tick に1回まで。設定 `growthWarnings` / `growthStuckHits` はサーバーだけ。
  - `MachineAccelerator`: 機械の倍率は `common/MachineComboBoost` で min(`machineBoostMultiplier` × コンボの掛け数, `machineBoostMaxMultiplier`)。コンボはサーバーの連続ヒット数で、`HitGate.accept` が `ServerStats.countStreak` を呼び、返したコンボ数を `RightClickHits` が `MachineAccelerator.hit` に渡す。機械ヒットの位置と残り時間をメモリにだけ持ち、`WorldTickEvent` END で `update()` を余分に呼ぶ（Time in a Bottle と同じ方式）。加速中は、同じ END で機械のまわりに色つきの粉の粒子（`EnumParticleTypes.REDSTONE`、数 0 で色を渡す。`common/MachineParticles`。色は掛け数 = 倍率 ÷ `machineBoostMultiplier` の段階、量は 1 tick に倍率 ÷ 8 個で端数は `MachineBoost.nextParticles` が持ち越す。設定 `machineBoostParticles` はサーバーだけ）を出す。例外はあえて捕まえない（ユーザーの判断。クラッシュレポートで機械を特定し、`excludedBlocks` に足してもらう）。レッドストーンの部品（`server/ScheduledTicks`・`common/ScheduledBoost`）は、同じ END で、予約（`WorldServer#isUpdateScheduled` があるときだけ `getPendingBlockUpdates(StructureBoundingBox, true)` で取り出す。X と Z だけで絞り込むので、同じ列のほかの予約は `scheduleBlockUpdate` で元の時刻・優先度のまま入れ直す）の残り時間を余分の tick だけ前倒しし、0 以下なら `updateTick` を今呼ぶ（1 tick に1回まで）。ディスペンサー・ドロッパーは予約があれば今動かし、非公開の `dispense`（SRG `func_176439_d`、`Reflect.method` の引数の型つきの版）で余分に発射する（回数 = min(5, floor(1 + 倍率 ÷ `machineBoostMultiplier`))）。余分の発射は、位置ごとの残り（`ScheduledTicks.BURSTS`）に持ち、`ScheduledBoost.BURST_INTERVAL_TICKS`（2）ごとに 1 発ずつ出す（同じブロックでなくなったら捨てる。次の前倒しで出し直す。`MachineAccelerator.clear` で捨てる）。
  - `ServerStats`: 統計。平均ヒット数は、壊したブロックへのヒット数 `hitsOnBrokenBlocks`（`recordBlockBroken` で足す。保存のキーも同じ名前で、なければ 0 から）÷ 壊した数。累計はプレイヤーの永続データ（`PlayerPersisted` の `weakspot`。死亡・ディメンション移動で引き継がれる）に、「今回」はメモリに持つ。節目は累計の採掘ヒット数で数える（リセットで受け取り直せる。古いキー `rewardHits` は読んだときに消す）。
  - `MiningRewards`: 耐久回復と節目の報酬。節目はヒットごと（`ServerStats.record` で増えたあとの累計の `hits`）に判定する。耐久回復はヒットのときではなく、ブロックを壊したときに精算する（`common/RepairSettlement`）。
    - 採掘ヒットは `ServerBoostTracker.Mining.hits` に未確定として持つ。`BreakEvent`（LOWEST、キャンセルされていないもの）でそのブロックと一致したときだけ確定し、`MiningRewards.onBlockBroken` に渡す。長押しをやめた（ABORT には Forge のイベントがない）・別のブロックに移ったときは、次の `LeftClickBlock` で `Mining` が作り直されるので、未確定のヒットは捨てられる。ただし、バニラが破壊を保留にしたブロックは `DELAYED` に残り、保留のあとに壊れたら確定する。
    - `BreakEvent` はツールの耐久が減る前（`tryHarvestBlock` の先頭）に来るので、回復してから壊れる（耐久が残り1でもツールが残る）。
    - 回復の数え方の余りはメモリだけに持つ（ログアウトで 0）。1回の破壊での回復は `maxRepairPerBreak`（サーバーだけが使う。送らない）まで。
  - `VersionCheck`: ログインの 40 tick 後に、接続のときに Forge が受け取ったクライアントの Mod の一覧（`NetworkDispatcher#getModList`）の `weakspot` の版を `WeakSpotMod.VERSION` と比べ（`common/ModVersions`）、違えば本人・OP 権限を持つほかのプレイヤー（`PlayerList#canSendCommands`）のチャット（黄色）とログ（WARN）に出す。文は翻訳キーと値（`TextComponentTranslation`）で送り、クライアントが自分の今の言語で文にする。パッチで足したキー（今は 1.11.1 の `weakspot.target.updateGift`）は `server/PlayerText.of` を通し、相手のクライアントがそのキーを足した版（`since`）より古いときだけ、`server/ServerLang` が Mod の jar の言語ファイルと、プレイヤーの言語（`EntityPlayerMP` の非公開の `language`、SRG `field_71148_cg`。読めなければ `en_us`）から文章を作って `TextComponentString` で送る。相手の版は `PlayerText.clientVersion`（Forge の Mod の一覧）、比べ方は `ModVersions.hasKeysSince`。
  - `SettingsSync` / `MarkerRelay`: 設定の送信、弱点マークの転送（毎 tick、マークから `markerShareRange` 以内のプレイヤーを計算し直し、入った人に現在の状態、出た人に「消えた」を送る）。

## クライアントを信じる範囲

不正対策の方針（ユーザーの判断）。

- **サーバーが正**: コンボの数（掛け数・節目・告知・進捗）、統計、間隔、種類ごとの条件、的当ての時間。クライアントから来た数（`HitMessage` の `streak` など）は、ほかの人の音の高さと、ずれの確認（`ComboRelay.checkOwn`）にしか使わず、サーバーの数をそれに合わせない。
- **クライアントを信じている所**: 「照準が弱点に合った」こと（全種類）。改造クライアントなら、合わせずに当てたと送れる。ただし間隔と条件はサーバーが確かめるので（間隔は 4 回分まで貯められる `HitBudget`）、得られるのは普通に当て続けたときと同じまで（最初の 4 回分を一度に使える程度）で、バニラ用のチートツールでもできる程度。**塞がない**。
- **的当て**: 当てた・✕ もクライアントの申告なので、ハズレを無視して記録・順位・告知を荒らせる。対策（弱点の位置をサーバーが決めて向きを確かめる。[roadmap.md](roadmap.md) の案 A）は、公開サーバーで遊ぶ予定が出るまで保留。
- サーバーからクライアントへ送るものは間引く（1 人あたりの送信の間隔を決める）。でたらめな通知を大量に送られても、サーバーの送信が増えないように。
- 接続のときの Mod の一覧の版（`PlayerText.clientVersion`）は改造クライアントなら書き換えられる。これで機能を切り替えてよいのは、ごまかしても本人だけが困るものに限る。

## 重要: サーバー側のブーストは時間枠ではない

1.12.2 のサーバー（`PlayerInteractionManager#blockRemoving`）は進捗を積算せず、破壊完了の通知を受けた瞬間に「**現在の**破壊速度 × (経過tick+1) ≥ 0.7」で判定する。そのため、仕様どおりサーバー側でも時間枠の間だけ倍率を掛けると、判定の瞬間が枠外のときにブーストが効かない。そうなるとブロックが戻り、後から通常速度で壊れる。
そこでサーバーは、ヒットごとに追加進捗 `(倍率-1)×継続tick×コンボの掛け数`（`BoostMath.extraTicksPerHit`）を貯め、そのブロックの `BreakSpeed` に `1 + 追加tick/(経過tick+1)` を掛ける（`BoostMath`）。こうすると積算した場合と同じ結果になる。破壊速度まわりを変えるときは、クライアント（積算）とサーバー（瞬間判定）の両方で結果が一致するかを確認すること。

- ヒット間隔の制限は、クライアントが `minHitIntervalTicks`（成長・機械はそれぞれの設定）、サーバーは `HitBudget`（4 回分まで貯められる）。サーバーがヒットを拒否してクライアントだけブーストされると、ブロックが一度戻って見える。
- 保留の破壊: 進捗が 0.7 未満で掘り終わりが届くと、バニラは破壊を保留にし（1 枠）、「今の速さ × 経過 tick ≥ 1.0」で壊す。別のブロックへ移ったあとも、保留中のブロックにはそのブロックの追加進捗を掛け続ける（`DELAYED`。上の「ゴーストブロックの対策」）。
- クライアントとサーバーは、どちらもクリックのたびにブーストを捨てる。クライアントだけ持ち越すと、クリックし直したときにクライアントだけでその場で壊れる（START だけ送るので、サーバーは何も返さない）。
- 採掘のコンボ倍率: クライアントは時間枠の中の速さに `1 + (倍率-1)×掛け数`（`BoostMath.clientMultiplier`）を掛ける。掛け数はヒットのときの自分のコンボ数から `MiningBoost.comboFactor`。サーバーは `HitGate.accept` が返すコンボ数から。境目で一瞬ずれても、サーバーは進み具合 70% で壊れたことを認めるので吸収される。
- ブーストの目安: H tick ごとにヒットすると、速度は通常の `1 + (倍率-1)×継続×掛け数/H` 倍。初期値なら `1 + 12f/H` で、約 0.6 秒ごとのヒットで2倍、`minHitIntervalTicks=6` で最大3倍（コンボ 300 の ×4 で 9 倍、1000 の ×7.5 で 16 倍）。

## 設定

`@Config`（`config/weakspot.cfg`）。カテゴリは 2 段: 上の段が `server`（`ServerConfig`）／`client`（`ClientConfig`）、その下が種類・用途（`ServerConfig.Mining` などの入れ子のクラス。Forge の決まりで、入れ子の項目は static ではないインスタンスのフィールド）。`throw` は Java の予約語なので、フィールドは `throwing`（`@Config.Name("throw")`）。根の `general` には `configVersion` だけを置く。項目の名前は、カテゴリを分ける前と同じ。名前から項目を探すときは `WeakSpotConfig.setting(名前)`（カテゴリ・フィールド・値。`settings()` で全部）。`[サーバー]` / `[クライアント]` の扱いと設定の足し方は [CLAUDE.md](../CLAUDE.md) の「設定の約束事」、項目の一覧は [config.md](config.md)。
- 設定ファイルの移行: `WeakSpotConfig.migrate` を `serverStarting` で呼び、`configVersion` が古ければ1回だけ直して保存する。6 = 今の設定にない項目（1.7.x の `meleeWeakSpotScale` など）を `weakspot.cfg` から消す（`ConfigManager` の `Configuration` の `general` から、`WeakSpotConfig` に同じ名前の static フィールドがない項目を `remove`。Forge は自分では消さない）。`preInit` の間の `ConfigManager.sync` は「読み込み」（ファイルの値でフィールドを上書きする）になるので、そこでは保存できない。7 = `general` に並んでいた項目を、新しいカテゴリの同じ名前の項目へ移す（`moveToCategories`。値は `Property` に書き、今の設定にない項目は消す）。`Property` に書いてから `sync` するので、`AVAILABLE` より前（「読み込み」の間）でも動く。クライアントだけで遊ぶときも移るように、`init` でも呼ぶ（何度呼んでもよい）。移行は `ConfigMigrationTest`（1.9.x の形の `weakspot.cfg` → 新しい形）で確かめる。
- 設定の読み直し: 起動後の `ConfigManager.sync` は、`Property#hasChanged` の項目だけファイル → フィールド、ほかはフィールド → ファイルの向きに動く。`reloadFromFile` は、`ConfigManager` の非公開の `CONFIGS` から `Configuration` を取り出して `load()` し、全項目を同じ値で `set` し直して（「変わった」の印）から `sync` する。
