`SPEC_v1.3.md`（Mod 1.3.0）と、そのパッチ `SPEC_v1.3.1.md`〜`SPEC_v1.3.7.md`（Mod 1.3.1〜1.3.7）に対する変更。ここに書かれていないことは、それらと現行実装のままとする。
仕様書は、リポジトリの `doc/` ディレクトリに置く（この仕様書は `doc/SPEC_v1.4.md`）。
仕様と食い違う実装をする場合は、`CLAUDE.md` のリリースの流れ（止まる条件）に従う。

- 対象: Minecraft Java Edition 1.12.2 / Forge 14.23.5.2860
- 前提: 1.3.7 がリリース済み。1.3.7 の内容を土台にする
- 内容: 成長の弱点の追加リスト `growthExtraBlocks` を、**ブロックごとの個別対応から、汎用の書き方**（ブロック名と、状態の条件）に変える。リストに書いたブロックは、ランダムな tick を余分に呼んで早める
- この仕様書の内容は、Mod のバージョン **1.4.0** として、リリースする

## 0. バージョン（v1.4.0）

- 設定 `growthExtraBlocks` の意味が変わる（今までは、コードの表にないブロックを書いても無視した。1.4.0 からは、書いたブロックが対象になる）。`CLAUDE.md` のバージョンの方針（設定キーの意味の変更）に従い、**マイナーを上げる**
- バージョンは 1.3.7 → **1.4.0**（`build.gradle` の `version` と `WeakSpotMod.VERSION` の2か所を、そろえて変える）
- `WeakSpotMod.ACCEPTED_VERSIONS` を、`[1.3,1.4)` から **`[1.4,1.5)`** に書き換える
- 1.3.x とは接続できなくなる。サーバーと全員のクライアントを、1.4.0 に同時に更新する（README の更新履歴に書く）
- パケット・`SyncedSettings` の形・保存データは変えない（`growthExtraBlocks` は今までどおり文字列のリストで送る）

## 1. 追加リストの書き方

`growthExtraBlocks` の1行に、次のどちらかを書く。

```
modid:block
modid:block[property=pattern,property=pattern]
```

- `property` は、ブロックの状態のプロパティの名前（F3 の画面の右に出る名前）。`pattern` は、そのプロパティの値の条件
  - 数の範囲 `a-b`（例: `age=0-6`）。値が整数で、a 以上 b 以下のとき
  - `*` を含む形（例: `state=dry_*`）。`*` は任意の文字列
  - それ以外は、値と完全に一致するとき（例: `half=lower`）
- 条件を複数書いたときは、すべてを満たすとき。同じブロックを複数行に書いたときは、どれかの行を満たすとき
- 条件を書かないときは、**そのブロックにいつでも**弱点を出す。ただし、次のブロックには、条件を書かないときの初期の条件がある（今までの個別対応と同じ動き）

| ブロック | 条件を書かないときの動き |
|---|---|
| `minecraft:reeds`、`minecraft:cactus` | 柱の高さが 3 未満で、一番上のすぐ上が空気（コードで判定。1.1.2 と同じ）。条件を書いたときは、それも満たすとき |
| `minecraft:nether_wart` | `age=0-2`（育ちきっていない） |
| `ic2:rubber_wood` | `state=dry_*`（乾いた樹液の穴。1.3.7 と同じ） |

- 読めない行（`[` の閉じ忘れ、`=` がないなど）は無視し、サーバーの起動時と設定の読み直し（`/weakspot reload`）のときに、ログに警告を出す
- 除外リスト `growthExcludedBlocks`（ブロック名）は、今までどおり追加リストにも効く
- 追加リストに書いたブロックは、`IGrowable`（骨粉が効くブロック）でも、追加リストの条件で判定する（書いたほうを優先する）

## 2. 効果と弱点の出方

- 効果は、今までの成長の弱点と同じ: 1 ヒットで、そのブロックの `randomTick` を `growthTicksPerHit` 回余分に呼ぶ（柱の植物は、柱の一番上の節に）。途中で条件を満たさなくなったら、そこでやめる
- 弱点を出す面
  - 当たり判定の箱が**1マス全体**（普通のブロック。ゴムの木の幹など）のときは、**照準が当たっている面**（上面は、木の中では隠れていることが多いため）。1.3.7 の「樹液の穴の面」の個別対応は、これに置き換える
  - それ以外は、今までどおり、一番大きい面（多くは上面。サトウキビなどは側面）
- 条件を満たさなくなったら、弱点は消える（ほかの成長の弱点と同じ）

## 3. 注意（README に書く）

- ランダムな tick は、成長以外にも使われている。次のようなブロックを追加リストに書くと、困ることが起きる: 葉（離れていると早く消える）、草ブロック・菌糸（広がる）、耕地（水がないと土に戻る）、氷・雪（溶ける）、火（燃え広がる）
- **既知の問題**: 成長バー（1.1.6）は、`age` か `stage` という数のプロパティを持つブロックにだけ出る。それ以外のブロック（ゴムの木など）には、進み具合のバーが出ない

## 4. 単体テスト（`common/` の純粋な計算）

- 書き方の読み取り: ブロック名だけ、条件1つ、条件複数、空白を含む行、読めない行（`[` の閉じ忘れ、`=` がない、ブロック名が空）
- 条件の判定: 数の範囲（範囲の端、範囲外、数でない値）、`*` を含む形（前、後ろ、途中）、完全一致、プロパティがないとき
- 同じブロックの複数行（どれかを満たせばよい）、初期の条件（条件を書かないとき）

## 5. README に書くこと

- 成長の弱点の説明に、追加リストの書き方（§1）、例、注意（§3）を足す。個別対応（サトウキビ・サボテン・ネザーウォート・ゴムの木）の説明を、初期の条件の表に直す
- 設定表の `growthExtraBlocks` の説明を直す
- 「インストール」と「更新するとき」の、接続できるバージョンの説明を 1.4.x に合わせる。1.3.x とは接続できないことを書く
- 「最新版」の行を 1.4.0 にし、「更新履歴」に 1.4.0 を追加する
- README の「開発」の節の仕様書へのリンクと、`CLAUDE.md` の「仕様の正本」の一覧に、`doc/SPEC_v1.4.md` を足す

## 6. ユーザーに確認してもらうこと

- 今までの対象（作物、苗木、サトウキビ、サボテン、ネザーウォート、IC2 のゴムの木の乾いた穴）が、今までどおり動くこと。ゴムの木は、照準を当てた面に弱点が出ること
- Mod の植物（`IGrowable` を持たないもの）を `growthExtraBlocks` に書くと、弱点が出て、当てると早く育つこと。条件（`[age=0-6]` など）を書くと、条件を満たすときだけ出ること
- 読めない行を書くと、サーバーのログに警告が出ること
- 1.3.x のクライアントで、1.4.0 のサーバーに、接続できないこと
