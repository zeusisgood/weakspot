## 0. バージョンと互換性

- バージョンは 1.7.1 → **1.8.0**（`build.gradle` の `version` と `WeakSpotMod.VERSION`）
- **通信内容が変わる**（`HitKind.MELEE` のヒットの意味が変わる。`SyncedSettings` から `meleeWeakSpotScale` を外し、`meleeChargePerHit` / `meleeChargeMax` を足す）。そのため 1.7.x とは接続できない
  - `WeakSpotMod.ACCEPTED_VERSIONS` を `[1.8,1.9)` にする
  - README の更新履歴に、1.7.x とは接続できないこと（サーバーとクライアントを同時に更新すること）を書く
- 設定 `meleeWeakSpotScale` をなくす（設定キーの削除。マイナーなのでよい。古いファイルに残った行は、Forge がそのまま残すが使わない）

## 1. 近接の弱点を「溜めて、次の攻撃を強化する」形に置き換える

### 1.1 背景

- 今の近接の弱点（1.3.0〜。敵の体の箱の面に出た弱点を、攻撃のゲージが溜まった状態でクリックすると、クリティカル）は、「敵の体の小さな円を狙う」と「ゲージを待つ」が同時に要り、難しい（ユーザーの指摘）
- 弓・投げる物と同じく、**照準のまわりの弱点に照準を合わせて溜め、次の攻撃を強化する**形にする。敵の体の弱点はやめる（置き換え。ユーザーの判断）

### 1.2 出すとき（クライアント、`client/MeleeSpot`）

- 次のすべてを満たす間（ユーザーの判断: 武器を持っていて、近くに敵がいる間）
  - メインハンドに**剣か斧**（`ItemSword` / `ItemAxe` と、それを継承した Mod の武器）を持っている
  - **16 ブロック以内に敵**がいる（今の `MeleeTargets.isTarget`。`IMob` の生き物、プレイヤーを除く。壁越しでもよい）
  - 何かを使っていない（弓・食事・盾など）、クリエイティブ・スペクテイターでない、弱点の一時オフ・この種類のオフでない、`meleeWeakSpotEnabled`
  - 馬・豚に乗っていない（乗り物の弱点の上下と重ならないように。トロッコ・ボートでは出す）
- 弓と同じく、**HUD に画面上で一定の大きさの円**で出し（`client/HudSpot`）、**照準を合わせるだけでヒット**
- 向きは**照準の左右だけ**（yaw を 10〜20 度ずらし、pitch は毎フレームの視線に合わせる。`HudSpot` に「左右だけ」の出し方を足す。計算は `BowMath.nextHorizontalYaw`）
  - 走りの弱点（上下だけ）と同時に出ても、位置で見分けられるようにするため（ユーザーの判断）
- 色は**銀 `#D0D8E0`**（走りの赤 `#FF5A5F`・弓の橙 `#FF8C42` と見分けやすい）
- ヒットの間隔は `meleeMinHitIntervalTicks`（今のまま。初期値 4）

### 1.3 溜め（`MeleeCharge`、両側。投げる物の `ThrowCharge` と同じ形）

- 1 ヒットごとに、溜めが `meleeChargePerHit`（初期値 **0.25**）× コンボの掛け数（`MachineComboBoost.factor`）だけ増える
- 溜めは、**持ち替えるまで残る**（選んでいるスロットか、メインハンドの物の種類が変わったら 0）。死亡・ディメンション移動・ワールドを出たときも 0
- 上限は初期値ではなし。設定 `meleeChargeMax`（初期値 **0 = 上限なし**）に数を書くと、その溜めで止まる（コンボを重ねると、ボスも一撃で倒せるようになるため、止めたい人向け）
- クライアントもサーバーの返事を待たずに溜める（ゲージのため）

### 1.4 次の攻撃の強化（サーバー、`server/MeleeHits`）

- 溜めがあるときの**次の 1 回の攻撃**（左クリックで生き物を殴ったとき）で、溜めを使い切る
  - その攻撃を**クリティカル**にし（`CriticalHitEvent` を ALLOW。クリティカルの粒子と音が出る）、ダメージの倍率を **1.5 × (1 + 溜め)** にする
  - 攻撃のゲージ（クールダウン）によるダメージの減り方は、バニラのまま
  - 走りながらの攻撃（ノックバック）、剣の範囲攻撃（なぎ払い）は、バニラのまま
- 使い切るのは、生き物への攻撃が当たったとき（`CriticalHitEvent` が来たとき）。空振り・ブロックを殴ったときは残る
- クライアントも、攻撃したときに自分の溜めを 0 にする
- 耐久の回復（今の `critsPerRepair` / `critRepairPerStep`）は、**溜めた攻撃が当たった回数**で数える（5 回ごとに 1 回復。今のクリティカルの回数の代わり）

### 1.5 ゲージ（クライアント）

- 照準の下に、弓・投げる物と同じ位置・大きさで出す（弓・投げる物とは同時に起きない）。溜めが 0 なら出さない
- ゲージの 1 本分 = 溜め 1.0（×2）。越えた分は、赤 `#FF4D4D` の目盛りを 1.0 ごとに 1 つ（5 つを越えたら「×n」の数字）。右に今の倍率「×2.0」（クリティカルの 1.5 倍を除いた、溜めの分）
- 色は銀 `#D0D8E0`（「弱点」タブで変えた色に合わせる）
- 設定 `meleeChargeBarEnabled`（**[クライアント]**、初期値 true）
- ゲージと溜めの計算（1 本分、目盛りの数、倍率の表示）は、投げる物と共通の部品にしてよい

### 1.6 通信・検証

- ヒットは `HitMessage`（種類 `MELEE`、**対象なし**。`HitMessage.withoutTarget`）。1.7.x までは敵のエンティティ ID を運んでいた
- サーバーは、オン・オフ（`ServerSwitches.isEnabled(player, MELEE)`）、`meleeWeakSpotEnabled`、クリエイティブ・スペクテイターでない、メインハンドが剣か斧、16 ブロック以内に敵がいる（サーバーのワールドで数える。少し甘く 20 ブロック）、間隔（2 tick 甘く）を確かめて受け付ける
- 受け付けたら `ServerStats.countStreak`、溜めを足す、統計、`ServerBoostTracker.notifyNearbyPlayers`（鳴らす位置はプレイヤー）
- 他のプレイヤーには見せない（今までどおり）

### 1.7 やめるもの

- 敵の体の箱の面に出す近接の弱点（`WeakSpot.spawnOnEntity(HitKind.MELEE, …)`、`client/MeleeSight`、`common/MeleeArea`、`MouseEvent` でのヒット、攻撃のゲージが溜まるまでの薄い表示、敵への透かし）
- 設定 `meleeWeakSpotScale`（弱点の大きさの倍率）
- 1.7.x までの「照準の先の敵」の検証（`MeleeHits` の `AttackEntityEvent` での対象の照合）

### 1.8 統計・節目

- 統計の「クリティカル数」を「**近接ヒット数**」（近接の弱点に当てた回数）にする。保存のキーは `critHits` のまま（古い数はそのまま引き継ぐ）。種類ごとの節目も、この数で数える
- 翻訳キー `weakspot.stats.critHits` の文章を直す（キーはそのまま）

### 1.9 設定

| キー | 種類 | 初期値 | 説明 |
|---|---|---|---|
| `meleeWeakSpotEnabled` | [サーバー]（同期） | true | 近接の弱点のオン・オフ（今のまま。説明を直す） |
| `meleeMinHitIntervalTicks` | [サーバー]（同期） | 4 | ヒットの最小間隔（今のまま） |
| `meleeChargePerHit` | [サーバー]（同期） | 0.25 | 1 ヒットで溜まる量（攻撃の倍率に足す。コンボで上乗せ）。0.05〜10.0 |
| `meleeChargeMax` | [サーバー]（同期） | 0 | 溜めの上限。0 = 上限なし |
| `critsPerRepair` / `critRepairPerStep` | [サーバー]（サーバーだけ） | 5 / 1 | 溜めた攻撃が当たった回数で数える（説明を直す） |
| `meleeChargeBarEnabled` | [クライアント] | true | 溜めのゲージを出すか |
| ~~`meleeWeakSpotScale`~~ | | | なくす |

## 2. 走りの弱点との兼ね合い（まとめ）

- 近接の弱点は**左右だけ**、走りの弱点は**上下だけ**に出るので、走りながら敵に近づいたときは、両方が同時に出ることがある。どちらも当てられ、それぞれの効果が出る（ヒットの間隔は種類ごと）
- 近接の弱点を狙って左右を向くと、走っている向きも少しぶれる（戦闘中は敵を追って向きを変えるので、そのままとする）
- ゲージは、走りが照準の上、近接が照準の下なので重ならない

## 5. ユーザーに確認してもらうこと

- 剣か斧を持って敵（ゾンビなど）に近づくと、照準の左か右に銀色の弱点が出ること。敵がいないとき・武器を持っていないとき・馬に乗っているときは出ないこと
- 当てるたびに照準の下のゲージが溜まり、敵を殴るとクリティカル（粒子）になって、溜めた分だけ強くなること。殴るとゲージが空になること。空振りでは消えないこと。持ち替えると消えること
- 走りながら敵に近づくと、走りの弱点（上下）と近接の弱点（左右）が同時に出て、どちらも当てられること
- 溜めた攻撃を 5 回当てると、剣の耐久が 1 回復すること
- `meleeChargeMax` に 2 などを書くと、溜めがそこで止まること
- 統計の「近接ヒット数」が、弱点に当てた回数で増えること
- 1.7.x のサーバー・クライアントとは接続できないこと

## 6. おまかせで決めたこと（違えば言ってください）

- 数字: 1 ヒット +0.25（×1.25）、ゲージ 1 本 = ×2、溜めた攻撃はクリティカル 1.5 倍 × (1 + 溜め)
- 馬・豚に乗っているときは出さない（乗り物の弱点が上下に出ているため）
- 敵は壁越しでも数える（戦う前に溜められるように）
- 色は銀 `#D0D8E0`
