# 弱点破壊 Mod 追加仕様書（v1.11.6）

`SPEC_v1.11.5.md`（Mod 1.11.5）に対する**パッチ**の仕様。ここに書かれていないことは、それと現行実装のままとする。
この仕様書は `doc/spec/SPEC_v1.11.6.md`。

- 対象: Minecraft Java Edition 1.12.2 / Forge 14.23.5.2860
- 前提: 1.11.5 がリリース済み
- この仕様書の内容は、Mod のバージョン **1.11.6** として、リリースする
- issue #38（弱点ヒットで採掘するとゴーストブロックが発生する（マルチ））への対応

---

## 0. バージョンと互換性

- バージョンは 1.11.5 → **1.11.6**（`build.gradle` の `version` と `WeakSpotMod.VERSION`）
- 通信内容は変わらない（Mod のメッセージは足さない・変えない。再送はバニラの `SPacketBlockChange`）。設定の項目は足さない。`configVersion` は上げない。保存データも変えない
- 内容は 4 つ:
  1. ヒットの間隔の判定を、まとめて届いても数回分は受け付ける形にし、全種類で共通にする（§2）
  2. クライアントの採掘のブーストを、クリックのたびに捨てる（サーバーと同じにする。ゴーストの直接の原因。§3）
  3. 採掘でクリックするたびに、そのブロックの状態を本人に送り直す（§4）
  4. サーバーで保留中の破壊にも、採掘のブーストを効かせ続ける（§5）

## 1. 調べたこと（原因）

バニラ 1.12.2（Forge 14.23.5.2860 の MCP 名の jar を逆アセンブル）で確かめた。

- `PlayerInteractionManager.blockRemoving`（掘り終わりの通知 STOP）: 進捗（今の速さ × (経過 tick + 1)）が 0.7 以上なら壊す。0.7 未満なら、保留（`receivedFinishDiggingPacket` / `delayedDestroyPos`）が空いていれば保留にし、**埋まっていれば何もしない**（保留は 1 枠）
- `updateBlockRemoving`（毎 tick）: 保留中のブロックは、今の速さ × 経過 tick が 1.0 以上になったら壊す
- `NetHandlerPlayServer.processPlayerDigging`: STOP・ABORT のあと、ブロックが空気でなければ `SPacketBlockChange` を返す。**START（掘り始め）では返さない**（`onBlockClicked` は、1 tick で壊れないなら掘り始めの状態にするだけ）
- `PlayerControllerMP.clickBlock`（クライアント）: Forge の `LeftClickBlock` → START を送る → `getPlayerRelativeBlockHardness` が 1 以上ならその場で壊す（START だけで、STOP は送らない）

ここから:

| 経路 | 起きること |
|---|---|
| サーバーがヒットを間隔で拒否する | サーバーの進捗が足りない → 保留、または（保留が埋まっていれば）STOP の返事でブロックが戻る（**ロールバック**） |
| 保留中に次のブロックへ移る | `ServerBoostTracker` の `Mining` が次のブロックに置き換わり、保留中のブロックにブーストが効かなくなる → 普通の速さで壊れるまで残る（**遅延**） |
| **戻ったブロックをすぐクリックし直す** | クライアントのブーストはクリックし直しても続く（`boostPos`・残り時間）ので、その場で壊れる（START だけ）。サーバーはクリックのたびにブーストを 0 に戻すので壊さず、何も返さない → **ゴースト** |

次を掘るまでの待ちを 0 にしている（`blockHitDelay`、1.11.2）ことは、戻ったブロックをブーストが残っている間にクリックし直しやすくしているが、原因ではない。§3・§4 で直るので、待ちを 0 にするのはやめない。

## 2. ヒットの間隔（全種類で共通。`common/HitBudget`）

- 今は、最後に受け付けた tick と比べて「設定の間隔 − 2 tick」（`HitGate.intervalOk`・`ready`）。ラグでヒットの通知がまとめて届くと、正しく当てたヒットでも落ちる
- **まとめて届いても 4 回分までは受け付ける**判定にする。4 回分まで貯められ、設定の間隔（`SyncedSettings.minHitInterval(kind)`）ごとに 1 回分戻る。最初は 4 回分ある。平均の速さの上限は今と同じ（間隔ごとに 1 回）
- 4 回分は全種類で同じ定数（`HitBudget.BURST` = 4）。設定は足さない
- `common/HitBudget`（Minecraft に依存しない）: 「使えるか（`ok(now, interval)`）」と「使った（`use(now, interval)`）」。実装の目安は、次に 1 回分が戻る時刻を 1 つの `long` で持つ形（「次の時刻 − (4 − 1) × 間隔 ≤ 今」なら使える。使ったら「max(次の時刻, 今) + 間隔」）。間隔が 0 ならいつでも使える。今より前の tick で使ってもよい（掘る前のヒットの予約は、予約した tick で数える）
- 置き換える所:
  - `HitGate.ready` / `mark`（動物・弓・近接・乗り物・食事・睡眠・投げる物・エンチャント・ゲート）: 中身を `HitBudget` に。呼ぶ側は変えない
  - 採掘（`ServerBoostTracker`。今は `Mining.lastHitTick` を次の `Mining` に引き継いでいる）・右クリック（`RightClickHits.Clicking.lastHitTick`。成長・機械・収穫）・釣り（`FishingHits.Track.lastHitTick`）・移動（`MoveHits` の `lastHit`）: `long` の最後の tick を `HitBudget` に
  - 持ち主が変わらないこと（プレイヤーごと・種類ごと、捨てるきっかけ）は今のまま
- `HitGate.intervalOk` と、2 tick の甘さ（`INTERVAL_JITTER_TICKS`）は消す
- クライアントの間隔（`OwnHits.canHit`）は今のまま（普通に遊んでいれば、サーバーで貯めた分は減らない）
- 単体テスト（`HitBudgetTest`）: 最初に 4 回続けて使える・5 回目は使えない・間隔ごとに 1 回分戻る・長く止まっていても 4 回分より多く貯まらない・間隔 0 はいつでも使える・前の tick で使える

## 3. クライアントの採掘のブーストを、クリックのたびに捨てる（`MiningBoost`）

- サーバーは、ブロックをクリックするたびに（`LeftClickBlock`）`Mining` を作り直し、ブーストを 0 から数え直している。クライアントは `boostPos` と残り時間を持ち越すので、クリックし直したときだけクライアントの方が速い
- クライアントの `PlayerInteractEvent.LeftClickBlock`（自分・クライアントのワールド）で、採掘のブースト（`boostPos`・`boostHitTick`・`boostFactor`）を捨てる。このイベントは `clickBlock` の中で、その場で壊れるかの判定より先に来るので、ブーストでその場で壊れることがなくなる
- 掘る前のヒット（`preHitPos`）と、待ちを 0 にするための当てたブロック（`hitBlock`）は捨てない（掘る前のヒットは、今どおり掘り始めてから `onDigging` でブーストになる）
- サーバーの版にかかわらずこの動きにする（古いサーバーも、クリックのたびに数え直している）

## 4. クリックのたびに、ブロックの状態を送り直す（サーバー。`ServerBoostTracker`）

- 採掘の `LeftClickBlock`（サーバー）で、次の座標を覚える:
  - 今クリックした座標
  - 前の `Mining` の座標（違うブロックへ移ったとき）
- そのプレイヤーについて、その tick の終わり（`ServerTickEvent` の END）に、覚えた座標の今の状態を `SPacketBlockChange` で**本人にだけ**送る（空気でも送る。同じ状態を送るだけなので、掘っている最中に届いても何も変わらない）
- 対象は、採掘のヒットを受け付けるプレイヤー（`HitGate.allowed(player, MINING)`・クリエイティブでない）だけ。ログアウトなどで捨てる（`forget`）
- これで、クライアントだけでその場で壊れたブロック（START だけ）も、同じ tick のうちに元に戻る。古いクライアント（1.11.5 以前。§3 がない）や、ほかの Mod で速さがずれたときも直る
- 送る量は 1 クリックに 1〜2 個（でたらめにクリックを送られても、クリック 1 回につき 2 個まで）

## 5. 保留中の破壊にも、採掘のブーストを効かせ続ける（サーバー。`ServerBoostTracker`）

- 違うブロックを掘り始めたとき、前の `Mining`（まだ壊れていない・追加進捗がある）を「保留」として 1 つ残す
- 残すのは、バニラの保留（`PlayerInteractionManager` の非公開の `receivedFinishDiggingPacket` / `delayedDestroyPos`。リフレクションで MCP 名 → SRG 名。SRG 名は実装のときに調べる）と同じ位置のときだけ。今残している保留がバニラの保留と同じ位置なら、そのまま残す。読めないときは、前の `Mining` を残す（バニラの保留と違う位置でも、そのブロックを誰も掘らなければ効かないので害はない）
- `BreakSpeed` で、位置が保留の `Mining` と同じなら、保留の追加進捗と経過 tick（保留の `Mining` を掘り始めた tick から。バニラの保留も、その掘り始めから数える）で `BoostMath.serverSpeedFactor` を掛ける
- 保留中のブロックが壊れたら（`BreakEvent`）、今掘っているブロックと同じく、統計（壊したブロック数・ヒット数）と耐久回復の精算に数える（今は数えずに捨てている）。壊れた・空気になった・ログアウトで捨てる
- これで、保留中のブロックが、クライアントで壊れた頃にサーバーでもすぐ壊れる（遅延が減る）。保留がすぐ空くので、2 つ目のブロックが捨てられて戻ることも減る

## 6. 改造クライアントへの備え

- 間隔: 平均の速さの上限は今と同じ。改造クライアントで得られるのは、最初の 4 回分を一度に使えることだけ（`doc/architecture.md` の「クライアントを信じる範囲」は変えない。「間隔」の説明を「4 回分まで貯められる」に直す）
- 再送: 1 クリックに 2 個まで（§4）

## 7. 古い版との組み合わせ

- 1.11.6 のクライアント + 古いサーバー: §3 でゴーストにならない。ロールバック・遅延は今のまま
- 古いクライアント + 1.11.6 のサーバー: クライアントだけその場で壊れることは残るが、§4 で同じ tick のうちに戻る。§2・§5 は効く

## 10. ユーザーに確認してもらうこと

- マルチで、弱点に当てながら連続で掘っても、見えない壁（すり抜けられないブロック）が残らない
- 掘ったブロックが一瞬戻ってからまた消えること（ロールバック）が減る。戻っても、すぐ壊れる
- ラグがあるサーバー（遠いサーバー・重いとき）でも、当てたのに効かないことが減る
- ほかの種類（成長・機械・動物・弓・釣りなど）を普通に当て続けたときの速さが今と同じ
- 掘る前の採掘の弱点（当ててから掘り始める）が今どおり効く
- 古いクライアント（1.11.5）で 1.11.6 のサーバーに入っても、ゴーストが残らない
