## 1. 小さいブロックの弱点の配置

### 1.1 症状
ボタンやハーフブロックなど、当たり判定が1ブロックより小さいブロックで、次の症状が出る。

1. 弱点が小さすぎて、当てられない
2. 弱点がほとんど動かず、同じ場所に出続ける

### 1.2 原因
今の配置の数値（半径は面の短い辺 × `weakSpotRadiusRatio`（0.14）、縁の余白 `edgeMargin`（0.1）、最小移動距離 `minMoveDistance`（0.4））を、小さい面にそのまま当てはめているため。

| 面 | 半径 | 弱点の中心が動ける範囲（縦 / 横） | 最小移動距離 0.4 |
|---|---|---|---|
| ふつうのブロック（1 × 1） | 0.14 | 0.52 / 0.52 | 届く |
| ハーフブロックの側面（1 × 0.5） | 0.07 | 0.16 / 0.66 | 縦方向は届かない |
| ボタンの正面（約 0.375 × 0.25） | 0.035 | なし（−0.02） / 0.105 | まったく届かない |

- 半径が面に比例して小さくなるので、ボタンの弱点の直径が約0.07ブロック（1ピクセルほど）になる（症状1）
- 縁の余白が固定なので、小さい面では、中心が動ける範囲がほとんど残らない（症状2）

### 1.3 直し方
ふつうのブロックの動きは変えない。小さい面のときだけ、次の4つを効かせる。

1. **半径に、下限と上限を付ける**: 半径 = 面の短い辺 × `weakSpotRadiusRatio`（今のまま）を、下限 `weakSpotMinRadius`（0.08 ブロック）以上、上限（面の短い辺 × `weakSpotMaxRadiusRatio`（0.35））以下に収める。下限と上限が食い違うとき（面が小さくて、上限が下限を下回るとき）は、**上限を優先する**（弱点が面からはみ出さないように）
2. **縁の余白を、面に合わせる**: 余白 = min(`edgeMargin`、面の短い辺 × 0.12)。面が大きければ、今までと同じ 0.1 のまま
3. **最小移動距離を、動ける範囲に合わせる**: 最小移動距離 = min(`minMoveDistance`、動ける範囲の対角線 × 0.6)。範囲が広ければ、今までと同じ 0.4 のまま
4. **極端に小さい面には、弱点を出さない**: 面の短い辺が `minFaceSize`（0.15 ブロック）より小さいときは、その面に弱点を出さず、通常の破壊のままにする（カーペットの側面、ボタンの側面など）

効果（上の数値で計算）:

| 面 | 半径 | 動ける範囲（縦 / 横） | 最小移動距離 |
|---|---|---|---|
| ふつうのブロック | 0.14（変わらず） | 0.52 / 0.52（変わらず） | 0.4（変わらず） |
| ハーフブロックの側面 | 0.07 → **0.08** | 0.16 / 0.66 → **0.22 / 0.72** | 0.4（変わらず） |
| ボタンの正面 | 0.035 → **0.08** | なし / 0.105 → **0.03 / 0.155** | 届かない → **約0.095** |

- ボタンは、縦にはほとんど動けず、横に動く形になる
- 半径 0.08 は、直径で約2.6ピクセル。ボタン自体が小さいので、これ以上大きくすると、動ける範囲が消える

### 1.4 設定にする値（サーバーの値。同期する）

| キー | 初期値 | 説明 |
|---|---|---|
| `weakSpotMinRadius` | 0.08 | 弱点の半径の下限（ブロック） |
| `weakSpotMaxRadiusRatio` | 0.35 | 弱点の半径の上限（面の短い辺に対する比率） |
| `minFaceSize` | 0.15 | 弱点を出す面の、短い辺の最小の長さ（ブロック）。これより小さい面には、弱点を出さない |

- 上の3つは、`SyncedSettings` に足して、サーバーから全員のクライアントへ送る（弱点の大きさなど、当てやすさに関わる項目と同じ扱い）
- 余白の割合（0.12）と、最小移動距離の割合（0.6）は、コード内の定数のままにする（設定に出さない）
- `CLAUDE.md` の設定のルールを守る: `[サーバー]` の項目として `weakspot.cfg` に足し、**受け取った値を `WeakSpotConfig` の static フィールドに書き込まない**（書き込むと、サーバーの値がクライアントの `weakspot.cfg` に保存されてしまう）。クライアントは、接続中は `ClientSettings.get()` を読む
- README の設定表（サーバーの値に従う項目）に、3つの項目を足す
- 既存の `weakspot.cfg` には、次に起動したときに、初期値で追加される

### 1.5 適用範囲
- 採掘の弱点（左クリック）と、右クリックの弱点（成長・機械）の両方に、同じ配置の計算を使う
- 成長の弱点は「一番大きい面にだけ出す」ままにする。その面の大きさに、上の直しを効かせる
- 複数の箱でできたブロック（階段、フェンスなど）は、今回の直しでは扱わない（弱点が、実際にはブロックがない空間に出る問題は、別に扱う）
- 弱点を出さない面では、ヒットが起きないので、サーバーへのヒット通知も、他のプレイヤーへのマークの送信も、起きない。サーバー側の判定（「弱点が出るブロックか」）は変えない

### 1.6 単体テスト
`common/` の配置の計算（`WeakSpotPlacerTest`）に、次を追加する。
- ふつうのブロック（1 × 1）の結果が、変更前と同じであること
- ハーフブロックの側面（1 × 0.5）で、半径が下限と上限に収まり、最小移動距離が満たされること
- ボタンの正面（約 0.375 × 0.25）で、弱点が置け、ヒット後に、動ける範囲の中で離れた場所へ動くこと
- 面が小さくて、上限が下限を下回るとき、上限が優先されること
- 面の短い辺が `minFaceSize` 未満のときは、弱点が置かれないこと
- 設定値（下限、上限、`minFaceSize`）を変えたときに、結果が変わること

### 1.7 成長促進の追加リストを設定にする（1.1.2 の固定リストを、設定へ）

`SPEC_v1.1.2.md` で、コード内の固定のリストにした「追加リスト」を、設定にする。「除外リスト」（`growthExcludedBlocks`）は、1.1.0 からすでに設定（サーバーの値。同期済み）なので、新しく足さない。

| キー | 初期値 | 説明 |
|---|---|---|
| `growthExtraBlocks` | `minecraft:reeds`、`minecraft:cactus`、`minecraft:nether_wart` | `IGrowable` を持たない植物のうち、成長促進の対象にするブロックの登録名（`SPEC_v1.1.2.md` §2.2） |

- `growthExtraBlocks` を、`SyncedSettings` に足して、サーバーから全員のクライアントへ送る（クライアントも、弱点を出すかどうかの判定に使うため）
- `growthExcludedBlocks` は、既存の設定のまま。1.1.2 から、追加リストのブロックにも効いている
- 追加リストに、育つ条件（「育てる余地」）が決まっていないブロックを足しても、弱点が出ないだけで、エラーにはしない。追加リストで対応できるのは、`SPEC_v1.1.2.md` §2.4 で判定を決めたブロック（サトウキビ、サボテン、ネザーウォート）だけ
- `CLAUDE.md` の設定のルールを守る（§1.4 と同じ）
- README の設定表（サーバーの値に従う項目）に、2つの項目を足す

### 1.8 統計に「最大連続ヒット数」を足す

コンボ（`SPEC_v1.1.3.md`）の最大値を、統計画面に足す。

- サーバーが、コンボと**同じ条件**で、連続ヒットを数える: 採掘・成長・機械のヒットをすべて数え、種類とブロックをまたいで続き、40 tick ヒットがないと途切れる
- 数え方は、`SPEC_v1.1.3.md` §4.1 で `common/` に置いた純粋な計算を、サーバーでも使う（サーバーの tick で数える）
- 統計画面の表に、「最大連続ヒット数」を1行足す。「今回」（ワールドやサーバーに入ってから出るまで。メモリだけに持つ）と、「累計」（そのワールド・サーバーでの最大値）を出す
- 累計は、プレイヤーの永続データ（`PlayerPersisted` の `weakspot`）に、新しいキーとして足して保存する。古い版は、このキーを無視するだけなので、保存データの読み込みには、影響しない
- 統計画面の「累計をリセット」で、この項目もリセットされる。節目と耐久回復の数え方（`rewardHits`）には、影響しない
- 表の説明に、「種類を問わない連続ヒットの最大」と書く（「弱点ヒット数」は、採掘だけの数なので、数え方が違う）
- クライアントに表示されるコンボと、サーバーが数える値は、ネットワークの遅れで、40 tick の境界のヒットのときだけ、ずれることがある（統計は、目安）
- 通信: `StatsMessage` に、項目を足す（§2）
- 単体テスト: 連続ヒットの数え方と、最大値の更新（`common/`）。既存の `MiningStats` のテストに追加してよい

### 1.9 動物の弱点（子どもの成長、繁殖の待ち時間、羊毛、卵、村人の取引上限）

動物（エンティティ）にも、弱点を出す。当てると、動物のタイマーが進む。

#### 1.9.1 対象と効果

| 対象 | 対象の動物 | 弱点が出る条件 | 効果（目安のヒット数） |
|---|---|---|---|
| 子どもの成長 | 年齢を持つ動物（`EntityAnimal`。MOD の動物を含む）と村人 | 子どものとき | 40ヒットで大人になる |
| 繁殖の待ち時間 | 同上 | 繁殖したあとの待ち時間中 | 10ヒットで待ち時間が終わる |
| 羊毛の再生 | バニラの羊 | 毛を刈られているとき | 10ヒットで毛が生える |
| 卵 | バニラのニワトリ（大人。ニワトリ騎手を除く） | いつも（大人のニワトリは、次の卵までのタイマーが常に動いている） | 15ヒットで次の卵を産む |
| 取引上限のリセット | バニラの村人（大人） | ロック（×印）された取引があるとき | 10ヒットでロックを解除する |

- **弱点が出る条件**: 上の条件のどれかを満たす（加速できるタイマーが動いている）ときだけ出す。何もなければ出さない（普通の大人の牛など）
- **複数のタイマー**: 1ヒットで、動いているタイマーを**すべて同時に**進める（例: 繁殖の待ち時間中の大人のニワトリは、繁殖の待ち時間と、次の卵までの両方が進む）
- **1ヒットの量**: 「1ヒット = 30秒分（600 tick）」を基準にする。設定は「目安のヒット数」で持ち、コードの中で「本来の時間 ÷ ヒット数」で換算する
  - 子どもの成長: 24000 tick ÷ 40 = 600 tick。成長の値を 0 に向けて進める（0 を超えない）
  - 繁殖の待ち時間: 6000 tick ÷ 10 = 600 tick。待ち時間を 0 に向けて減らす
  - 卵: 平均 9000 tick ÷ 15 = 600 tick。次の卵までの時間を減らし、0 以下になったら、バニラと同じ処理で卵を産む（音も同じ）
  - 待ち時間が途中まで進んでいれば、残りの分だけなので、ヒット数は少なくて済む
- **羊毛**: タイマーがないので、羊ごとにヒット数を数え、10ヒットで毛を生やす。**草は要らない**（草を食べさせない。足元の草ブロックも土にならない）。毛の色は、そのまま
- **取引上限のリセット**: 村人ごとにヒット数を数え、10ヒットで、ロックされた取引の使用回数の上限を増やして、ロックを解除する。上限の増え方は、バニラの補充と同じ
  - 初期値では、**ロックの解除だけ**を行い、新しい取引の段階は解放しない
  - 設定 `villagerResetUnlocksNewTier`（初期値 オフ）をオンにすると、バニラの補充と同じく、新しい取引の段階も解放する
- 羊毛と取引のヒット数は、サーバーのメモリだけに持つ（保存しない。動物がアンロードされたら消えてよい）

#### 1.9.2 操作
- **素手**（メインハンドが空）で、動物に向かって**右クリックを押しっぱなし**にすると、弱点が出る（餌を持った右クリックは「繁殖・餌やり」なので、弱点は出さない）
- 素手の右クリックに、バニラの別の動作がある動物は、**しゃがみ+素手**のときだけ弱点を出す（「何かの動作と競合するなら、しゃがみを条件にする」ルール）
  - 馬・ロバ・ラバ・ラマなど（`AbstractHorse` の仲間）: 乗る、持ち物の画面を開く
  - 飼いならしたオオカミ・ネコ・オウム（飼いならした `EntityTameable`）: 座る・立つ
  - サドルを付けた豚: 乗る
  - 村人（子どもを含むすべて）: 取引の画面を開く
  - MOD の動物で、同じように競合するもの: 設定 `animalSneakRequiredEntities` に、エンティティの ID を足す
- 弱点が出る条件（§1.9.1）を満たしているときは、そのバニラの動作（乗る、持ち物の画面、座る、取引の画面）を止める。クライアントとサーバーの両方で止める
  - 条件を満たしていないとき、または、しゃがまずに右クリックしたときは、今までどおりの動作になる
  - 例: 大人の馬で競合するのは、繁殖したあとの約5分間の、しゃがみ+素手の右クリック（持ち物の画面）だけ

#### 1.9.3 サーバーへの問い合わせ（クライアントが知らない情報）
次の情報は、クライアントに届いていない（サーバーだけが持っている）。

| 情報 | クライアント |
|---|---|
| 子どもかどうか、羊が刈られているか | 知っている |
| 子どもの成長の進み具合、繁殖の待ち時間、次の卵までの時間 | 知らない |
| 村人の取引のロック | 知らない（取引の画面を開いたときだけ届く） |

- 右クリックを押しっぱなしで動物に照準を合わせたとき、クライアントは、サーバーに、その動物の状態を問い合わせる
- サーバーは、動いているタイマーの種類と、それぞれの進み具合（0.0〜1.0）を返す
- 押しっぱなしの間は、数 tick ごと（例: 5 tick ごと）と、ヒットのたびに、状態を更新する
- クライアントは、返事で「動いているタイマーがある」ときだけ、弱点を出す。返事が来るまでは、弱点を出さない
- 実装時に、本当にクライアントに届いていないかを確認する（届いていれば、問い合わせを省いてよい。§4）

#### 1.9.4 弱点の位置
- 動物の当たり判定の箱の、**照準が当たっている面**に出す
- 弱点の位置は、箱の面の中の位置として持つ。動物が動いても、マーカーは一緒に動く
- 照準が別の面に移ったときは、ヒットで弱点が動くとき、または出し直すときに、面を選び直す（面がちらつかないように）
- 小さい動物（子どものニワトリなど）は、§1.3 の小さい面のルール（最小半径など）に従う
- 1.1.4 の移動の残像、1.1.6 の他のプレイヤーのマークの形は、そのまま使う

#### 1.9.5 サーバーでの確認（ヒット）
- 届く距離か（右クリックで動物に触れられる距離）
- ヒットの間隔（`animalMinHitIntervalTicks`）
- 素手か。しゃがみが必要な動物では、しゃがんでいるか
- 対象の動物か（対象外の設定 `animalExcludedEntities` に入っていないか）、弱点が出る条件を満たしているか

#### 1.9.6 足元のバー
- 弱点が出ている動物の足元に、進み具合のバーを出す。1.1.6 の作物の成長バーの部品を流用する（黄 `#FFD23F`、背景 黒 `#1E1E1E` 半透明、プレイヤーの方を向く）
- 大きさは、動物の幅に合わせる（例: 幅の 80%。小さすぎる・大きすぎる場合の上限と下限は、実装で決めてよい）
- 値は、サーバーの返事（§1.9.3）の進み具合を使う
- タイマーが複数あるときは、1本だけ出す。表示の順番: **子どもの成長 → 羊毛 → 取引上限 → 繁殖の待ち時間 → 卵**
- 羊毛と取引上限の進み具合は、「ヒット数 ÷ 必要なヒット数」
- 弱点が消えたら、すぐに消す。1.1.6 の一時オフの間は出さない

#### 1.9.7 他のプレイヤーへの表示
- 動物の弱点マークも、他のプレイヤーに見せる（ブロックの弱点と同じ見た目・色・形）
- マークの通知に、対象の種類（ブロックか、動物か）と、動物の番号（エンティティ ID）を足す（§2）
- 足元のバーは、他のプレイヤーには見せない

#### 1.9.8 数え方
- 統計に「**動物ヒット数**」（今回・累計）を足す
- ヒット音とコンボには、数える
- 節目と耐久回復には、数えない（成長・機械と同じ）

#### 1.9.9 設定（サーバーの値。同期する。ただし `villagerResetUnlocksNewTier` はサーバーだけ）

| キー | 初期値 | 説明 |
|---|---|---|
| `animalBabyEnabled` | `true` | 子どもの成長の加速 |

#### 1.9.10 単体テスト（`common/` の純粋な計算）
- ヒット数からの換算: 本来の時間 ÷ ヒット数（24000 ÷ 40 = 600 など）。ヒット数が 0 以下の設定のときは、その対象を無効として扱うこと

- 羊毛・取引のヒット数の数え方: 必要なヒット数で、1回だけ効果が出て、数え直しになること
- バーの表示の順番: タイマーの組み合わせから、表示する1本が正しく選ばれること
- しゃがみが必要かの判定の純粋な部分（種類の一覧からの判定）

### 1.10 釣りの弱点

釣り竿の浮きが水に入って、魚を待っている間に、弱点を出す。当てると、魚が寄ってくるまでの待ち時間が短くなる。

#### 1.10.1 対象と効果
- 対象: **自分の**釣り竿の浮きが、水に入って、魚が寄ってくるのを待っている最中（バニラの「待ち時間」の段階）
- 1ヒットごとに、魚が寄ってくるまでの待ち時間を減らす
  - 設定は「最長の待ち時間（600 tick）を何ヒットで 0 にするか」で持ち、初期値は **6ヒット**（1ヒット = 100 tick = 5秒分）
  - 待ち時間は平均 17 秒ほどなので、平均 4ヒット前後で魚が寄ってくる
- 魚が寄ってきたあと（泡の筋が近づく段階）と、食いついたあとは、短くしない。弱点を消す。食いつきの判定と、巻き上げは、バニラのまま
- 弱点を叩かなくても、今までどおり釣れる（放置の釣りは壊さない）
- 雨・入れ食いのエンチャントなど、バニラの待ち時間の仕組みは、そのまま

#### 1.10.2 操作
- 釣り竿を持って、弱点に照準が重なっているときに、**左クリック**で叩く（右クリックは「投げる・巻く」なので使わない）
- 弱点に照準が重なっているときの左クリックは、弱点のヒットだけにして、Minecraft の通常の左クリック（照準の先のブロックを掘る、動物を攻撃する）は止める
- 弱点から外れているときの左クリックは、今までどおり
- 釣り竿は、メインハンドとオフハンドの、どちらで持っていてもよい（浮きがあるほう）。実装で扱いを決めてよい

#### 1.10.3 弱点の位置と描き方（浮きに追従する HUD）
- 弱点の位置は、ワールドの中の1点で決める: 浮きのまわり**半径1ブロック**の水面の上の点
- ヒットのたびに、前の位置から一定以上（例: 0.5 ブロック）離れた点へ移る
- 描くときは、その点を**画面上の位置に変換**して、**画面上で一定の大きさ**の円として描く（初期は半径 **12ピクセル**。GUI の拡大率に合わせる）。浮きが遠くても近くても、同じ大きさに見える
- 浮きが画面の外や、後ろにあるときは、弱点を出さない
- 1.1.4 の移動の残像は、画面上でそのまま使う
- 自分の弱点と同じ見た目（塗りつぶした円）

#### 1.10.4 当たり判定
- 「視線の向き」と「目から弱点の点への向き」の角度の差が、許す角度より小さいときに、照準が重なっているとする
- 許す角度は、画面上の円の半径（ピクセル）と、視野角（FOV）と、画面の高さから求める（画面上で円の中に照準があるのと同じになるように）
- 水面への当たり判定の計算は使わない

#### 1.10.5 サーバーへの問い合わせ
- 待ち時間のタイマーは、サーバーだけが持っている（クライアントは知らない）
- 浮きが水に入ったら、クライアントは、サーバーに状態を問い合わせる。サーバーは「待ち時間の段階か」と、待ち時間の進み具合（0.0〜1.0）を返す
- 浮きが水にある間は、数 tick ごとと、ヒットのたびに、状態を更新する
- 「待ち時間の段階」のときだけ、弱点を出す
- 進み具合を出すため、サーバーは、待ち時間が始まったときの長さを、浮きごとにメモリに持つ（保存しない）

#### 1.10.6 サーバーでの確認（ヒット）
- そのプレイヤーの浮きがあり、水に入っていて、待ち時間の段階か
- ヒットの間隔（`fishingMinHitIntervalTicks`）
- 照準の角度は、サーバーでは確かめない（クライアントを信用する。ほかの弱点と同じ程度の確認）

#### 1.10.7 浮きのバー
- 浮きの下に、魚が寄ってくるまでの進み具合のバーを、**画面上で一定の大きさ**で出す（色は、動物のバーと同じ 黄 `#FFD23F`、背景 黒 `#1E1E1E` 半透明）
- 値は、サーバーの返事（§1.10.5）の進み具合
- 待ち時間の段階が終わったら、消す。一時オフ（1.1.6）の間は出さない

#### 1.10.8 他のプレイヤーへの表示
- 釣りの弱点は、他のプレイヤーに**見せない**（自分だけ）

#### 1.10.9 数え方
- 統計に「**釣りヒット数**」（今回・累計）を足す
- ヒット音とコンボには、数える
- 節目と耐久回復には、数えない

#### 1.10.10 設定（サーバーの値。同期する）

| キー | 初期値 | 説明 |
|---|---|---|
| `fishingWeakSpotEnabled` | `true` | 釣りの弱点のオンオフ |
| `fishingHits` | 6 | 最長の待ち時間（600 tick）を 0 にするまでのヒット数 |
| `fishingMinHitIntervalTicks` | 要調整 | 釣りのヒットを受け付ける最小間隔（tick） |

- 画面上の弱点の大きさ（12ピクセル）、動く範囲（半径1ブロック）、最小の移動距離（0.5 ブロック）は、コード内の定数にする

#### 1.10.11 単体テスト（`common/` の純粋な計算）
- ヒット数からの換算: 600 ÷ 6 = 100 tick。待ち時間が 0 を下回らないこと
- 許す角度の計算: 画面の高さ、FOV、半径から、角度が求まること。画面の中央から半径ちょうどの点が、境界になること
- 弱点の次の位置: 浮きから半径1ブロック以内で、前の位置から最小の移動距離以上離れること
- 進み具合: 待ち時間の最初の長さと、残りから、0.0〜1.0 になること

### 1.11 弱点の一時オフを、サーバーにも伝える（1.1.6 の制限の解消）

1.1.6 の一時オフ（J キー）は、クライアントだけの機能だった。サーバーはオフを知らないので、サーバー側の右クリックの抑止が残り、オフにしても、しゃがみ+素手の右クリックで機械の GUI が開かない、という制限があった（1.1.6 の README と `CLAUDE.md` に記載済み）。1.2.0 は通信内容が変わるので、ここで解消する。

- クライアントは、オン・オフの状態を、サーバーに伝える
  - ワールドやサーバーに入ったとき（ログイン時）
  - J キーで切り替えたとき
- サーバーは、プレイヤーごとに状態を持つ（メモリだけ。ログアウトで消えてよい。ログインのたびにクライアントから届く）。届く前は、オンとして扱う
- オフのプレイヤーについて、サーバーは次を止める
  - 右クリックの抑止（機械の GUI、成長の右クリック、動物のバニラの動作。§1.9.2）
  - 釣りの左クリックの抑止（§1.10.2）
  - そのプレイヤーからのヒットの受け付け（採掘・成長・機械・動物・釣り）と、ブースト
  - 他のプレイヤーへの、そのプレイヤーの弱点マークの転送（オフにした瞬間に、出ていたマークを消す）
- 1.1.6 の README と `CLAUDE.md` に書いた制限の記述を、消す（または「1.1.6 のみ」と書き直す）
- 単体テスト: サーバー側の状態の持ち方（届く前はオン、切り替えの反映）の純粋な部分

## 6. アイデア（1.2.0 には含めない。決まったら、追加するか、別のバージョンにする）

**エンチャント「弱点拡大」（判定サイズを大きくする）**
- 弱点の半径が大きくなり、当てやすくなる。最大レベルは3（半径にレベルごとの倍率を掛ける。例: +30%ずつ）。倍率は、サーバーの設定で変えられるようにする
- つけられる道具は、ブロックを壊す道具（ツルハシ、シャベル、斧など）。エンチャントテーブル、金床、エンチャントの本で入手できる
- 小さいブロックの救済にもなる（エンチャントがあるとき、半径の上限を少し緩める、など）
- 採掘（左クリック）にだけ効く。右クリックの弱点は、素手で行うので、エンチャントは効かない
- 決めておきたい点: 見た目も大きくするか（判定だけか）、他のプレイヤーのマークにどう反映するか（最初は、基本の大きさで表示する形が簡単）、統計や節目の数え方（変えない）

**組み合わせの案**
- 「精密」（逆の効果）: 弱点は小さくなるが、ヒット1回で進む量が増える。「拡大」と同時につけられないようにする
- 「残光」: 弱点が、長押しをやめたあとに残る時間が長くなる
- 「吸着」: 見た目は変えず、判定だけを、照準の近くで緩める（エイム補助）

## 7. ユーザーに確認してもらうこと（クライアントの見た目・操作は、Claude Code が確認できない）

ビルドした jar を、ホストの Minecraft で試す。

- ふつうのブロック（土、石）: 今までと変わらないこと
- ハーフブロック: 上面と側面で、弱点が出て、当てられ、当てると動くこと
- ボタン（石、木）: 正面で弱点が出て、当てられ、横に動くこと
- カーペット、感圧板: 上面には弱点が出て、側面には出ないこと
- 階段、フェンス: 動きを確認する（弱点が空中に出ても、今回は直さない）
- 設定: 専用サーバーの `weakspot.cfg` の値を変えて再起動し、クライアント側の弱点の大きさや出る面が変わること（クライアントの `weakspot.cfg` を書き換えていないこと）
