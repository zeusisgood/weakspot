# 弱点破壊 Mod 追加仕様書（v1.13.2）

`SPEC_v1.13.1.md`（Mod 1.13.1）に対する**パッチ**の仕様（`/weakspot bug` のリンクの確認画面でボタンが押せない不具合の修正）。ここに書かれていないことは、それと現行実装のままとする。
この仕様書は `doc/spec/SPEC_v1.13.2.md`。

- 対象: Minecraft 1.12.2 / Forge・1.20.1 / Forge・1.21.1 / NeoForge の 3 つ（決まりどおり同じ PR で直す）
- 前提: 1.13.1 が `main` に取り込み済み
- 経緯: 1.21.1 で「Mod が多いと、`[GitHub で issue を作成]` を押したときの確認画面に URL がびっしり出て、ボタンが画面の外に押し出され、押せない。スクロールもできない」との報告（スクリーンショットあり）。1.20.1 でも同じ
- ユーザーとの相談で決まったこと:
  - リンクを、バニラの確認画面を通さず、**クライアントのコマンドで直接ブラウザーで開く**形にする（案 C）
  - URL の上限も 6000 → **4000** 字に下げる
  - 1.12.2 も同じ作りに揃える
  - 上限を約 1000 字まで下げるだけの案、一覧をいつも URL から外す案、確認画面を自作する案は採らない

---

## 0. バージョンと互換性

- バージョンを 1.13.1 → **1.13.2**（パッチ）。版を書く 6 か所を揃える
- 通信内容・保存データ・設定は変わらない。1.13.0・1.13.1 と接続できる（範囲 `"[1.13,1.14)"`・`PROTOCOL` `"1.13"` のまま）
- クライアントだけの変更（`/weakspot bug` は自分のクライアントのコマンド）なので `ServerFeatures.since` は要らない

## 1. 原因

- `BugReport.issueUrlFitting` は、URL が 6000 字までなら Mod の一覧を URL に入れる
- 1.20.1・1.21.1 の確認画面（バニラの `ConfirmLinkScreen`）は URL の全文を折り返して表示する。日本語の見出しは 1 字が 9 字（`%E6%A6%82` など）になるので、Mod が数十個あると URL が数千字になり、ボタンが画面の外に出る。画面はスクロールできない
- 1.12.2 の `GuiConfirmOpenLink` は URL を 1 行だけ表示するので、この症状は出ない見込み（未確認）。ただし作りを揃えるため同じように直す

## 2. 修正

### 2.1 確認画面を通さずに開く

- `[GitHub で issue を作成]` のクリックを `OPEN_URL` から `RUN_COMMAND` の **`/weakspot bug open`** に変える（`/weakspot skipupdate` と同じ「チャットのクリックで動く」クライアントのコマンド）
- `/weakspot bug open` は、`/weakspot bug` と同じ手順で URL を作り直し（中身は同じ）、ブラウザーで直接開く
  - URL をコマンドの引数で渡さない（チャットの長さの上限に当たるため）。状態も持たない
  - 開く方法: 1.20.1・1.21.1 は `Util.getPlatform().openUri`（バニラの確認画面が「はい」のあとに使うもの）。1.12.2 はバニラの `GuiScreen.openWebLink` と同じ方法（`java.awt.Desktop` の `browse`。非公開のメソッドなので、呼べなければ同じ処理を自分で書く）
  - 開けなかったら（例外）、チャットに「[WeakSpot] ブラウザーを開けませんでした。GitHub の issue の画面から報告してください」（新しい翻訳キー `weakspot.bug.openFailed`。日英）
  - （注: 実装では、1.20.1・1.21.1 の `openUri` は失敗をログに書くだけで例外にならないため、このメッセージは 1.12.2 でだけ出る。開かないときの案内は `doc/play.md` に書いた）
- 直接打っても動く（害はない）。補完には出さなくてよい（1.20.1・1.21.1 の brigadier で出てしまうのは構わない）
- バニラの「チャットのリンク」の設定や「リンクを開く前に確認」の設定は通らない。本人が打ったコマンドの結果を本人がクリックしたときだけ開き、行き先は固定の GitHub なので問題ないとする
- `/weakspot bug` で環境情報をクリップボードにコピーするのは、今までどおり（`open` ではコピーし直さない）

### 2.2 URL の上限を下げる

- `BugReport.MAX_URL_LENGTH` を 6000 → **4000**（GitHub・ブラウザーが受け付ける長さに余裕を持たせる）。超えたら今までどおり一覧を外し、「クリップボードから貼り付けてください」と書く

## 5. ユーザーに確認してもらうこと

- 3 つの版で、Mod を多く入れた状態で `/weakspot bug` → `[GitHub で issue を作成]` をクリックすると、確認画面なしでブラウザーが開き、環境情報が入った issue の画面になること
- Mod がとても多いとき（URL が 4000 字を超えるとき）は、本文に一覧の代わりに「貼り付けてください」と出て、クリップボードから貼れること
- 1.20.1 で、今まで確認画面のボタンが押せなかった環境で押せる（直接開く）こと
