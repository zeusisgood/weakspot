# 弱点破壊 Mod 追加仕様書（v1.1.5）

`SPEC_v1.1.md`（Mod 1.1.0）から `SPEC_v1.1.4.md`（Mod 1.1.4）までに対する**パッチ**の仕様。ここに書かれていないことは、それらと現行実装のままとする。
仕様書は、リポジトリの `doc/` ディレクトリに置く（この仕様書は `doc/spec/SPEC_v1.1.5.md`）。
仕様と食い違う実装をする場合は、`CLAUDE.md` のリリースの流れ（止まる条件）に従う。

- 対象: Minecraft Java Edition 1.12.2 / Forge 14.23.5.2860
- 前提: **1.1.4 がリリースされたあと**に、この仕様書の作業を始める（1.1.4 の内容を土台にする）
- 内容: **掘っているブロックの残りの耐久を、緑のバーで表示する**（Fortnite の、破壊対象の耐久バーに近いもの）。単純なバーで、ヒットの演出は付けない
- この仕様書の内容は、Mod のバージョン **1.1.5** として、リリースする

---

## 0. バージョンとパッチの制約

- バージョンは 1.1.4 → **1.1.5**（`build.gradle` の `version` と `WeakSpotMod.VERSION` の2か所を、そろえて変える）
- `WeakSpotMod.ACCEPTED_VERSIONS`（`[1.1,1.2)`）は、変えない。1.1.x 同士は、互いに接続できる
- **パッチなので、互換性を破る変更を入れない**（`SPEC_v1.1.md` §0 のバージョンの方針）
  - パケットの追加・削除・中身の変更をしない。`SyncedSettings` に、項目を足さない
  - サーバーが保存するデータの形式を変えない
  - 設定キーの削除や、意味の変更をしない
- この仕様書の変更は、**クライアントだけ**。サーバーは変えない

## 1. 表示する値

- **残りの耐久** = 1 − 自分の破壊の進み具合（0.0〜1.0 に収める）
- 破壊の進み具合は、クライアントが持っている値（`PlayerControllerMP` の、現在の破壊の進み具合）を使う。弱点のブーストは、クライアントとサーバーの両方に掛かっているので、クライアントの値で、実際の進み具合と一致する
- この値は、Minecraft の内部の非公開の値なので、リフレクションなどで読む（方法は、実装時に確認する。§6）
- 数値や % は、表示しない（バーだけ）

## 2. 表示の場所と形

### 2.1 場所
- 今掘っている面（照準が当たっている面）の、**下の余白の帯**に描く
- 弱点の円は、縁の余白（`edgeMargin`。初期値 0.1 ブロック）の内側にしか出ないので、面の一番下の帯には、弱点が入ってこない。そこにバーを置く
- 面の上に少し浮かせて描く（弱点のマーカーと同じ描き方を流用する）。今掘っている面は、プレイヤーから見えているので、ほかのブロックに隠れない

### 2.2 「下」の決め方
- **側面**（東西南北の面）: 面の下の辺
- **上面・下面**（床や天井を掘るとき）: 面の4つの辺のうち、**プレイヤーに一番近い辺**。画面では、手前（下側）に見える

### 2.3 形と大きさ
- 横長の細いバー
- 太さ: **0.06 ブロック**
- 位置: 下の辺から、少し内側（バーの中心が、下の辺から 0.05 ブロック）。余白の帯（0.1 ブロック）に収まる
- 長さ: 面の幅の **80%**。面の中央にそろえる
- 面の大きさは、1ブロックの面ではなく、**実際の当たり判定の箱の面**を使う（ハーフブロックなど）

### 2.4 色

| 部分 | 色 |
|---|---|
| 残りの耐久 | 緑 `#3DDC84` |
| 背景（減った部分を含む、バーの全体） | 黒 `#1E1E1E`（半透明。透明度 50% 程度） |

- 残りの耐久は、バーの**左から**伸びる形にし、減ると右端から縮む（プレイヤーから見て左右。上面・下面では、プレイヤーの向きから左右を決める）

### 2.5 動き
- ヒットの演出（削れた部分の強調など）は、**付けない**。弱点に当てたときも、バーが普通に減るだけ（ブーストで、減り方が速くなる）
- 破壊の進み具合は tick ごとに更新されるので、描画のフレームごとに、前の tick の値と今の値の間を補間して、滑らかに縮める

### 2.6 重なり
- 弱点のマーカー（1.1.4 の移動の演出を含む）と重なったときは、マーカーを上に描く
- サーバーの設定で `edgeMargin` が小さいときや、小さいブロック（1.2.0 で、小さい面の余白が狭くなる）では、バーが弱点に少し重なることがある。見た目だけの問題なので、許容する

## 3. 表示する条件

- 自分が、左クリックの長押しでブロックを掘っている間
- そのブロックが、採掘の弱点が出るブロックであること（瞬間破壊のブロック、壊せないブロックには出さない）
- クリエイティブモードでは出さない（弱点と同じ）
- 次のときは、**すぐに消す**
  - 長押しをやめたとき（Minecraft 側で、進み具合が 0 に戻る）
  - ブロックが壊れたとき
  - 別のブロック、または別の面に照準が移ったとき（別の面に移ったら、その面に出し直す。進み具合は Minecraft の動きに従う）
- F1 で HUD を隠したときの扱いは、弱点のマーカーと同じにする

## 4. 対象外

- 成長・機械の弱点（右クリック）には、出さない
- 他のプレイヤーが掘っているブロックには、出さない（自分の分だけ）
- ヒットの演出、数値や % の表示

## 5. 設定（クライアント）

`weakspot.cfg` の `[クライアント]` の項目として足す。見た目だけに関わるので、各自の設定で、サーバーとは同期しない。

| キー | 初期値 | 説明 |
|---|---|---|
| `blockHealthBarEnabled` | `true` | 掘っているブロックの残りの耐久バーの表示のオンオフ |

- 太さ、位置、長さ、色は、**コード内の定数**にする（設定には出さない）
- `CLAUDE.md` の設定のルールを守る: `[クライアント]` の項目は、`WeakSpotConfig` をそのまま読む。README の設定表（クライアントの項目）にも足す
- 設定の説明の文字列は、`en_us.lang` と `ja_jp.lang` の両方に足す
- 既存の `weakspot.cfg` には、次に起動したときに、初期値で追加される

## 6. 実装時に確認すること

- クライアントの破壊の進み具合（`PlayerControllerMP` の非公開の値）の読み方。リフレクション（SRG 名での取得）か、アクセストランスフォーマーか。開発環境と、実際の環境（難読化された名前）の両方で動くこと
- 今掘っているブロックの位置（`PlayerControllerMP` が持っている位置）と、照準が当たっている位置・面が一致しているか。一致しないときは、表示しない
- 弱点のマーカーの描画（`WeakSpotRenderer` など）の、面の上に浮かせて描く仕組みを流用できるか
- 上面・下面で、プレイヤーに一番近い辺と、左右の向きの決め方

## 7. 単体テスト

バーの形の計算は、Minecraft に依存しない純粋な計算として `common/` に置き、テストを書く。
- 残りの耐久: 進み具合 0 → 1.0、0.25 → 0.75、1 → 0。範囲外の値は、0.0〜1.0 に収めること
- バーの位置と大きさ: 1 × 1 の側面で、太さ 0.06、長さ 0.8、下の辺から中心 0.05 になること。ハーフブロックの側面など、面の大きさが違うときに、長さが面の幅の 80% になること
- 上面・下面の「下」の辺: プレイヤーの位置を変えたときに、一番近い辺が選ばれること（東西南北の4方向）
- 補間: 前の tick の値と今の値の間を、フレームの割合で補間すること

## 9. 未決事項（仮置きで進めてよい）

- バーの太さ（0.06）、位置（下の辺から 0.05）、長さ（80%）、色と透明度。遊びながら調整する
- 斜めから見にくい場合に、画面（HUD）に表示する方式へ切り替える設定（後のバージョン）
- 成長の弱点で、作物の成長段階をバーで出す案（後のバージョン）

## 10. ユーザーに確認してもらうこと（クライアントの見た目は、Claude Code が確認できない）

ビルドした jar を、ホストの Minecraft で試す。

- 壁のブロック（石など）を掘ると、面の下の辺のあたりに、緑のバーが出て、掘るにつれて右から縮むこと
- 弱点に当てると、バーの縮み方が速くなること
- 床を掘るとき、手前の辺にバーが出ること。天井を掘るときも、同じであること
- ハーフブロックの側面で、バーが面の大きさに合うこと
- 弱点のマーカーと、バーが重ならないこと（重なったときは、マーカーが上）
- 長押しをやめたとき、ブロックが壊れたとき、別のブロックに照準を移したとき、バーがすぐ消えること
- 土など、瞬間破壊に近いブロックや、クリエイティブモードでは出ないこと
- 設定 `blockHealthBarEnabled` をオフにすると、出ないこと
- 1.1.4 のサーバー（またはクライアント）と、1.1.5 のクライアント（またはサーバー）で、接続できること
