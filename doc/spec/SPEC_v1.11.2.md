# 弱点破壊 Mod 追加仕様書（v1.11.2）

`SPEC_v1.11.1.md`（Mod 1.11.1）に対する**パッチ**の仕様。ここに書かれていないことは、それと現行実装のままとする。
この仕様書は `doc/spec/SPEC_v1.11.2.md`。

- 対象: Minecraft Java Edition 1.12.2 / Forge 14.23.5.2860
- 前提: 1.11.1 がリリース済み
- この仕様書の内容は、Mod のバージョン **1.11.2** として、リリースする
- **下書き**（ユーザーが「実装」と言うまで実装しない）

---

## 0. バージョンと互換性

- バージョンは 1.11.1 → **1.11.2**（`build.gradle` の `version` と `WeakSpotMod.VERSION`）
- 通信内容は変わらない（掘る前のヒットも今の `HitMessage` で送る。§7）。設定の項目は足さない（どちらの機能もオン・オフの設定は作らない。ユーザーの判断）。`configVersion` は上げない
- サーバーとクライアントの両方が要る機能なので、クライアント側は `ServerFeatures.since("1.11.2")` で囲む。サーバー側は、1.11.2 より古いクライアントには自動の対象を使わない（§3）
- 内容は 2 つ: 成長の弱点の自動の対象（§1〜§5）と、掘る前から出る採掘の弱点（§6〜§9）

## 1. やりたいこと（ユーザーの判断）

- 成長の弱点の対象を、追加リスト（`growthExtraBlocks`）に書かなくても、**ランダム tick を受け取るブロック（`Block#getTickRandomly()`）なら自動で拾う**（相談: 追加リストのホワイトリストをやめて似た仕組みのものに自動対応。IC2 の建築用フォームが固まるのを早めたい、から）
- 考え方は Random Things の「Time in a Bottle」と同じ（1.12.2 版のソースで確認: ブロックの種類を問わず、ブラックリストもなく、`getTickRandomly()` なら `randomTick` を呼ぶ）。放っておけば起きることを早めるだけ
- **案 A3**: 自動で拾ったブロックは、**しゃがんで右クリックを押しっぱなし**にしたときだけ弱点を出す（通常の右クリックを横取りしない。機械の弱点と同じ操作）
- 除外は今の `growthExcludedBlocks` だけで行う。**初期値は増やさない**（草ブロック・草・背の高い草花のまま。葉・耕地・氷なども対象になる）
- しゃがんだときに機械とも自動の対象とも取れるブロックは、**機械を優先**（今の判定の順のまま）

## 2. 対象の判定（`RightClickTargets`）

- 自動の対象（仮に `isAutoGrowable`）: 次をすべて満たすブロック
  - `getTickRandomly()` が true
  - `growthExcludedBlocks` にない
  - 追加リストにない（追加リストにあるブロックは、書いた条件だけで決める。条件を満たさないときに自動で拾い直さない）
  - `IGrowable` でない（`IGrowable` は今どおり `canGrow` で決める。育ちきった作物を自動で拾い直さない）
- `classify` の順: 機械（しゃがんで両手が空）→ 成長（今の判定）→ 収穫 → **自動の成長（しゃがんでいて、メインハンドが空 = `HeldItems.isFree`）**。種類は `HitKind.GROWTH`（統計・コンボ・設定・種類のオン・オフは成長と共通）
- しゃがむのは弱点を**出すとき**の条件。出たあとの「まだ対象か」の確認（クライアントの弱点の取り消し、サーバーの `grow` のくり返し）は、しゃがみを見ずに `isGrowable` か `isAutoGrowable` で見る（押しっぱなしの途中でしゃがみをやめても消えない。消したほうがよければ実装のときに相談）
- 固まって別のブロックになり、それがランダム tick を受け取らなければ（IC2 のフォーム → 壁 の想定）、そこで弱点は消える。受け取り続けるブロックは、押しっぱなしの間ずっと出る（「育ちきった」を判定しない）

## 3. 古い版との組み合わせ

- 1.11.2 のクライアント + 古いサーバー: `ServerFeatures.since("1.11.2")` が false なら、クライアントは自動の対象を使わない（右クリックも止めない）
- 古いクライアント + 1.11.2 のサーバー: サーバーは `PlayerText.clientVersion(player)` が 1.11.2 未満（または不明）なら自動の対象を使わない（クライアントが止めていない右クリックを、サーバーだけで止めない）

## 4. 効果と知らせ

- 効果は今の成長と同じ（1 ヒットで `growthTicksPerHit` 回 `randomTick`。弱点の面も同じ: 1 マス全体なら照準の面、それ以外は一番大きい面）
- 自動の対象には「育たない」の知らせ（`GrowthWarnings` の暗い・`growthStuckHits`）を出さない（変わらないことがあるブロックも多いため）
- 成長バーは今どおり `age` / `stage` を持つときだけ

## 5. 設定の説明

- `growthExcludedBlocks` のコメントと日英の `.tooltip` に「しゃがんで右クリックで自動で拾うブロック（ランダム tick を受け取るもの）にも効く」を足す
- `growthExtraBlocks` のコメントと `.tooltip` に「書かなくても、ランダム tick を受け取るブロックは、しゃがんで右クリックすれば対象になる。書くと、しゃがまなくても出る・状態の条件を付けられる」を足す（「葉・草ブロック…は書かない」の注意は残す）

## 6. 掘る前から出る採掘の弱点（ユーザーの判断）

- 相談: 採掘が速いツール（効率強化・ビーコンの採掘速度上昇）を手に入れると、弱点を狙う前に壊れるので、この Mod の価値が下がる。ブロックに照準を合わせたら、掘る前から弱点を出す
- **A**: 当てたブロックを壊したら、次を掘り始めるまでの待ち（バニラの `PlayerControllerMP.blockHitDelay`、5 tick）を **0** にする（速さの得を「1 ブロックの中」から「ブロックとブロックの間」に移す。上限は付けない）
- **B**: 掘る前のヒットも、普通の採掘のヒットに数える（ブースト・コンボ・節目・統計・耐久回復）
- 掘る前の弱点は、照準が合った対象のブロックに**いつも出す**（オン・オフの設定は作らない。HOME キーの一時オフ・「弱点マーカー」タブの採掘のオフ・サーバーの `miningWeakSpotEnabled` のオフでは出ない）
- **1 tick で壊れるブロック**（素手の土・効率強化つきシャベルの土など。今は対象外）も、掘る前の弱点の対象にする
- 落とす物を増やす・まわりも壊す（相談の案 C・D）はしない

## 7. 掘る前の弱点の仕組み

### 7.1 クライアント（`ClientWeakSpotHandler`・`MiningBoost`）

- 出す条件: 掘っていない（`getIsHittingBlock()` が false）、照準がブロックに当たっている（`objectMouseOver` が BLOCK）、採掘の弱点を出せるブロック（今の条件から「1 tick で壊れない」を外したもの: 壊せる（硬さ ≥ 0）、空気でない、クリエイティブでない、`minFaceSize` 以上の面）。照準の面に、今と同じ配置（`WeakSpotPlacer`）で出す
- 見た目: 採掘の弱点の色（初期値 `#FF5926`、「弱点マーカー」タブの色）を**不透明度 40%** で描く（いつも出ているので控えめに）。掘り始めたら今の濃さに戻す
- 当てられるのは**掘る前に 1 回まで**。当てたら弱点はその場で止まり（動かさない）、掘り始めるまで次のヒットを受け付けない。当てた瞬間に、ヒット音・コンボの表示（`ComboHud.onHit`）・`OwnHits` の連続ヒットは今のヒットと同じに出す
- 照準が別のブロック・別の面に移ったら、そのブロックの弱点に出し直す（掘る前のヒットは、当てたブロックに残る。§7.2 の時間で捨てる）
- 掘り始めたら、その面の弱点を今の採掘の弱点として続ける（掘る前に当てていれば、当てたあとの位置から）。耐久バーは今どおり掘っている間だけ
- 掘る前の弱点は、**ほかのプレイヤーに見せない**（`OtherMarkers.sendOwn` に送らない）。掘り始めてからは今どおり
- 1 tick で壊れるブロック: 今は `MiningBoost` が「瞬間破壊の判定中は自分のブーストを掛けない」。掘る前に当てていても、ブーストは関係ない（もともと 1 tick で壊れる）。ヒットとして数えることだけが得（B）

### 7.2 サーバー（`ServerBoostTracker`）

- 掘る前のヒットは、今の `HitMessage`（種類 MINING・ブロックの位置）で、**当てた瞬間に**送る（バニラの掘り始めのパケットより前に届く）
- `onHit` で、今掘っているブロック（`Mining.pos`）と違う位置のヒットは、今は捨てている。これを**予約**としてプレイヤーごとに 1 つだけ持つ（位置・受け取った tick・streak。新しい予約は古い予約を上書き）。予約の時点では `HitGate.accept`・統計・節目を呼ばない（掘らずに当て続けてコンボを稼げないように）
- `onLeftClickBlock` で、予約と同じ位置を掘り始めたら、`Mining` を作った直後に予約を今の `onHit` と同じ処理で確定する（間隔の確認 `intervalOk`・`HitGate.accept`・追加進捗・`hits++`・`recordHit`・`onMiningHit`）。予約は使ったら消す
- 予約は **20 tick**（1 秒）のうちに掘り始めなければ捨てる（実装の目安。照準を合わせてから掘り始めるまでの時間を、試してもらって決め直す）。ログアウトでも捨てる（`forget`）
- **1 tick で壊れるブロック**: バニラの `onBlockClicked` は `LeftClickBlock` のあとに壊すので、予約の確定は `BreakEvent` より先になる。今の `Mining.eligible`（統計の「壊したブロック数」と耐久回復の精算に数えるか）は「1 tick で壊れない」ことを条件にしているので、**予約を確定したブロックは eligible にする**（当てずに壊した 1 tick のブロックは今どおり数えない）
- 古いクライアント（1.11.2 未満）は掘る前のヒットを送らないので、予約は起きない。古いサーバーは、違う位置のヒットを今どおり捨てる（クライアントは `ServerFeatures.since("1.11.2")` が false なら掘る前の弱点を出さない）

## 8. 次を掘るまでの待ちを 0 に（A。`MiningBoost` など、クライアント）

- 壊したブロックに **1 回でも当てていた**（掘る前・掘っている途中のどちらでも）なら、壊した直後に `PlayerControllerMP` の `blockHitDelay` を 0 にする（遅いツールでも 5 tick 速くなる）
- 非公開のフィールドなので `Reflect`（MCP 名 `blockHitDelay` → SRG 名。SRG 名は実装のときに `doc/development.md` の方法で調べて、両環境で確かめる）。読めなかったら何もしない（ログに 1 回だけ警告）
- 壊れたことは、クライアントで掘っていたブロックが空気になった・`getIsHittingBlock()` が false になった時点で見る（バニラが待ちを 5 にした直後に 0 に戻す。実装で一番確実な場所を選ぶ）
- サーバーはこの待ちを確かめていない（破壊の完了は「今の速さ × (経過 tick + 1) ≥ 0.7」だけ）ので、ずれない
- クリエイティブには関係しない（採掘の弱点が出ない）

## 12. ユーザーに確認してもらうこと

- IC2 の建築用フォームに、しゃがんで素手で右クリック長押しで弱点が出て、当てると早く固まる。固まると消える
- しゃがまなければ出ない（フォームなど、追加リストにないブロック）。作物・サトウキビ・ゴムの木は今どおりしゃがまなくても出る
- しゃがんで機械に右クリックしたときは、今どおり機械の弱点
- 葉・耕地などにも出る（初期値で除外しない判断のまま困らないか）
- 照準を合わせると、掘る前から採掘の弱点が薄く出る（`#FF5926` の 40%）。掘り始めると濃くなる。邪魔に感じないか
- 掘る前に 1 回当ててから掘り始めると、コンボが続き、当てたブロックを壊すと次をすぐ掘り始められる（効率強化 V のツルハシで石を掘り進めて、速くなったと感じるか）
- 当てたあと、掘らずに別のブロックへ移っても、コンボが増えない
- 素手の土・効率強化つきシャベルの土など、1 tick で壊れるブロックにも掘る前の弱点が出て、当ててから壊すとヒットに数えられる（耐久回復も進む）
- 予約の時間（1 秒）が短すぎないか（照準を合わせて当ててから、少し間を置いて掘り始めても数えられるか）
- ほかのプレイヤーには、掘る前の弱点が見えない
