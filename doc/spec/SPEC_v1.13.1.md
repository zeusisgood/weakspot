# 弱点破壊 Mod 追加仕様書（v1.13.1）

`SPEC_v1.13.0.md`（Mod 1.13.0）に対する**パッチ**の仕様（釣りの弱点のちらつきの修正）。ここに書かれていないことは、それと現行実装のままとする。
この仕様書は `doc/spec/SPEC_v1.13.1.md`。

- 対象: Minecraft 1.12.2 / Forge・1.20.1 / Forge・1.21.1 / NeoForge の 3 つ（決まりどおり同じ PR で直す）
- 前提: 1.13.0 が `main` に取り込み済み
- 経緯: 1.21.1 で「広い水源で釣りをすると、弱点が周期的に消えたり出たりする」との報告
- ユーザーとの相談で決まったこと:
  - クライアントが弱点を出す条件のうち、浮きが水にあるかの判定を、**サーバーと同じ判定**（浮きのブロックが水で、液体の高さ > 0）に置き換える（案 1）
  - 外れても数 tick 残す案（走りなどと同じ）、クライアントの水の条件を外してサーバーの返事だけで決める案は採らない

---

## 0. バージョンと互換性

- バージョンを 1.13.0 → **1.13.1**（パッチ）。版を書く 6 か所を揃える
- 通信内容・保存データ・設定は変わらない。1.13.0 と接続できる（範囲 `"[1.13,1.14)"`・`PROTOCOL` `"1.13"` のまま）
- クライアントだけの修正なので `ServerFeatures.since` は要らない（1.13.0 のサーバーでも直る）

## 1. 原因

- クライアントの `FishingSpot.activeHook` は、浮きが水にあるかを `hook.isInWater()`（当たり判定の箱の下端が水面より下か）で見ている
- サーバーの `FishingHits.isWaiting` は、浮きのブロックが水で液体の高さ > 0 か（バニラが待ち時間を減らす条件）で見ている
- 水源の水面は高さ 8/9 で、浮きはちょうどその高さを狙って上下に揺れる（揺れが小さくなると ±0.1 を足して揺らし続ける）。そのため、箱の下端が水面より上に出る tick が約半分あり、`isInWater()` が 1 秒前後の周期で false になる（1.21.1 のバニラの浮きの式で再現して確かめた）
- false になるたびに、クライアントは弱点を消して状態を消去し（`clear()`）、戻るとサーバーの返事を待ち直してから**新しい位置**に出す。表示がちらつき、位置も飛ぶ
- サーバーはこの間も待っていると判定しているので、待ち時間の減り方（魚が来るまでの時間）には影響していない

## 2. 修正

- 3 つの版のクライアントの `FishingSpot.activeHook` で、`hook.isInWater()` を、サーバーの `FishingHits.inWaterBlock` と同じ判定に置き換える
  - 判定は 1 か所に書き、サーバーとクライアントの両方から使う（両側がずれないように）。クライアントとサーバーの両方で読み込まれる場所に置く（`server/` のクラスをクライアントから呼ぶ形にはしない）
  - 1.12.2: `Material.WATER` かつ `BlockLiquid.getBlockLiquidHeight > 0`。1.20.1・1.21.1: `FluidTags.WATER` かつ `getHeight > 0`（今のサーバーの判定のまま）
- 浮きが本当に水から出たとき（縁に引っかかる・陸に落ちる）は、今までどおり弱点が消える（サーバーの判定と同じになるだけ）
- 1.12.2・1.20.1 でちらつきが起きるかは確かめていないが、判定の考え方を揃えるため同じように直す

## 5. ユーザーに確認してもらうこと

- 3 つの版で、広い水源で釣りをして、浮きが揺れている間も弱点が消えずに出続けること（当てると別の場所に移るのは今までどおり）
- 浮きをブロックの縁に引っかけたときや陸に落としたときは、弱点が出ないこと
- 魚が掛かるまでの時間が、当てた分だけ短くなること（今までどおり）
