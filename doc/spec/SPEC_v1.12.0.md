# 弱点破壊 Mod 追加仕様書（v1.12.0）

`SPEC_v1.11.12.md`（Mod 1.11.12）に対する**マイナー**の仕様（Minecraft 1.21.1 + NeoForge への移植）。ここに書かれていないことは、それと現行実装のままとする。
この仕様書は `doc/spec/SPEC_v1.12.0.md`。

- 対象:
  - **Minecraft Java Edition 1.21.1 / NeoForge 21.1.x**（新規。`mc1.21.1/`）
  - Minecraft Java Edition 1.12.2 / Forge 14.23.5.2860（今まで。`mc1.12.2/`）
- 前提: 1.11.12（下ごしらえ: `common/`・`mc1.12.2/`・`lang/*.json`・版ごとのリリースの流れ）が `main` に取り込み済み
- ユーザーとの相談で決まったこと:
  - 移植先は **1.21.1 + NeoForge**（Modpack での採用が多い版にしたい。All the Mods 10 など、上位の Modpack が 1.21.1 + NeoForge）
  - リポジトリ・CurseForge・Modrinth のプロジェクトは分けない。1 つの版に、Minecraft の版ごとの jar を並べる
  - 移植のあとも、1.12.2 版と**機能を揃え続ける**。片方の版だけを直したときも、**両方の jar を同じ番号で出す**
  - **全種類が揃ってから出す**。PR と版は 1 つ（1.12.0）。コミットは種類ごと（採掘のみ、など）に分けてよい
  - Modrinth の審査が済むのを待たずに出す

---

## 0. バージョンと互換性

- バージョンを 1.11.12 → **1.12.0** にする。版を書く場所は、`mc1.12.2/build.gradle`・`WeakSpotMod.VERSION`（1.12.2）と、`mc1.21.1/gradle.properties` の `mod_version`・1.21.1 の `WeakSpotMod.VERSION` の 4 か所。必ず揃える（`ReleaseFilesTest` で確かめる）
- **マイナーにする理由**: 新しい Minecraft の版に対応する節目のため（ユーザーの判断）。1.12.2 版どうしの通信内容は変わらないが、決まりどおり接続できる範囲を新しいマイナーにする
- 1.12.2 版: `ACCEPTED_VERSIONS` を `"[1.12,1.13)"` にする。1.11.x とは接続できない（`CHANGELOG.md` に書く）
- 1.21.1 版と 1.12.2 版は、もともと Minecraft の版が違うので接続できない（Mod の側では何もしない）
- マイナーを上げたときの決まりどおり、1.12.2 版で次を片付ける:
  - `PlayerText.of` の `since` が 1.12.0 以下のもの → `TextComponentTranslation`（今は全部 1.11.x なので、全部）
  - `ServerFeatures.since("1.11.x")`・`PlayerText.clientSince(player, "1.11.x")` → 下限が 1.12 になり、いつも true なので、条件を消す
  - 仕組み（`ServerFeatures`・`PlayerText`・`ServerLang`）そのものは残す（1.12.x のパッチで使う）
- 1.11.x の仕様書（`doc/spec/SPEC_v1.11.*.md`）を消す（`doc/development.md` の「リリースの手順」の 2.。消す前に、そこにしか書いていない今の挙動を `doc/play.md`・`doc/config.md`・`doc/architecture.md` に移す）

## 1. 1.21.1 版の土台

- ディレクトリ `mc1.21.1/`。**Java 21**・**Gradle 8**・NeoForge の **ModDevGradle**（NeoForge が 1.21.1 で勧めているプラグイン）。名前は Mojang の名前（Parchment の引数名は使ってよい）
- NeoForge は 21.1.x の、実装の時点で最新の安定版。決めた版を `doc/development.md` と README の「対応する版」に書く
- Mod の ID は `weakspot`、パッケージは `io.github.zeusisgood.weakspot`（1.12.2 と同じ）。クラスの分け方（`client/`・`server/`・`config/`・`network/`）も、できるだけ 1.12.2 と同じ名前にする（読み比べやすくするため）
- `../common/src/main/java` と `../common/src/test/java` をソースに足す。翻訳は `../lang/*.json` をそのまま `assets/weakspot/lang/` に入れる
- `neoforge.mods.toml`: 名前・説明・ロゴ・ライセンス（MIT）・`updateJSONURL`（1.12.2 と同じ `update.json`）・クライアントとサーバーの両方に必要
- jar は `weakspot-1.21.1-<版>.jar`（注: 1.12.2 から `weakspot-1.21.1-neoforge-<版>.jar`。`doc/development.md` の「版の表記」）。`LICENSE` を `LICENSE_weakspot` として入れる（1.12.2 と同じ）
- **非公開のフィールド・メソッド**: 1.21.1 は動いているときも Mojang の名前なので、SRG 名を探す必要がない。**アクセストランスフォーマー（`accesstransformer.cfg`）を使う**（名前の間違いがビルドで分かるため）。1.12.2 の「アクセストランスフォーマーではなくリフレクション」の決まりは 1.12.2 版だけのものにする
- クライアントだけのクラスは `Dist.CLIENT` のイベントの購読にする。パケットのハンドラーから直接クライアントのクラスに触らない（専用サーバーで読み込まれないように。1.12.2 の `proxy.onXxx` と同じ考え）

### 2.1 1.21.1 で増えたものの扱い

決まり: **1.12.2 版の判定の条件（「毎 tick 動くブロックエンティティ」「登れるブロック」など）にそのまま当てはまるものは、条件どおり対象になる**。名前で並べている対象（乗り物・投擲物・作物など）に 1.21.1 の新しい物を足すかは、下の表で決める（ユーザーと相談して決めた）。表にないもので迷ったら足さずに、PR の本文に一覧で書く。1.21.1 にしかない物が 1.21.1 版でだけ対象になるのは、「機能を揃え続ける」に反しない（遊び方の仕組みを揃える、という意味のため）。

| 種類 | 1.21.1 で増えた物 | 扱い |
|---|---|---|
| 採掘 | なし（ブロックの種類が増えるだけ） | 条件どおり |
| 成長 | 竹・ピッチャー・トーチフラワー・洞窟のツタなど | 条件どおり（成長する作物・苗木の判定に当てはまるもの） |
| 成長（しゃがんで、時間で変わるブロック全般） | 銅の錆び・アメジストの芽・鍾乳石など（ランダム tick で変わるブロック） | **条件どおり入れる**（1.12.2 版と同じ仕組みのまま。銅を錆びさせる・アメジストを育てるのも速くなる。ユーザーの判断） |
| 機械 | 燻製器・溶鉱炉・焚き火など（毎 tick 動くブロックエンティティ） | 条件どおり。ただし**試練のスポナー・宝物庫（Vault）は対象外**（報酬を早く何度も得られてしまうため）。対象外の一覧（宝箱など）に、樽・クラフター・デコレーションポットなど GUI・中身を持つものを足すかは、毎 tick 動くかで決まるので足さなくてよい |
| レッドストーン部品 | クラフター | 足さない（`doc/roadmap.md` の「1.21.1 の新しい物（のちの相談）」） |
| 動物 | 新しい動物（ラクダ・ヤギ・カエルなど） | 条件どおり（繁殖できる動物）。繁殖のアイテムは 1.21.1 の `isFood` で判定する |
| 動物 | アルマジロのウロコ（時間で落とす） | **足す**。ニワトリの卵と同じく、次に落とすまでのタイマーを縮める（`AnimalTimers` にウロコのタイマーを足す。1.21.1 版だけ。ユーザーの判断）（注: 実装では、間隔が卵と同じなので、設定の項目は足さずに卵の設定 `chickenEggEnabled`・`chickenEggHits` を使う。村人の繁殖の案内は、1.21.1 に村と扉の仕組みがないので、1.14 以降のバニラの条件（空いているベッド・食べ物の点数）で出す） |
| 釣り | なし | 条件どおり |
| 弓 | クロスボウ | 足さない（`doc/roadmap.md` の「1.21.1 の新しい物（のちの相談）」） |
| 近接 | メイス | 足さない（「剣・斧」のまま。同上） |
| 乗り物 | ラクダ・ストライダー（歪んだキノコ付きの棒）・チェスト付きボート・いかだ | **足す**。ラクダは馬と同じ扱い、ストライダーは豚と同じ扱い（どちらも照準の真上か真下）、チェスト付きボート・いかだはボートと同じ |
| 飲食 | ハチミツ入りの瓶・怪しいシチューなど | 条件どおり（食べる・飲む動作のもの） |
| 睡眠 | なし | 条件どおり |
| はしご | 足場・ねじれツタ・しだれツタ・洞窟のツタ | 条件どおり（登れるブロック。足場も含む） |
| エリトラ | なし | 条件どおり |
| エンチャント | なし | 条件どおり |
| 収穫 | トーチフラワー・ピッチャー・スイートベリー・グロウベリー | 足さない（スイートベリー・グロウベリーはバニラで右クリックで収穫でき、ピッチャー・トーチフラワーは実ると別のブロックになるため）。小麦・ニンジン・ジャガイモ・ビートルート・ネザーウォート・カカオ豆と、Mod の作物（`CropBlock` を継いだもの）のまま |
| 投擲物 | ウィンドチャージ・トライデント | **ウィンドチャージは足す**（雪玉と同じ投げ方のため）。トライデントは足さない（同上） |
| ダッシュ | なし | 条件どおり |
| ネザーゲート | なし（1.21 で転移の待ちの仕組みが `PortalProcessor` に変わった） | 待ち時間を縮める先を調べ直す。見た目（紫の揺らぎ）も同じだけ進める |
| 泳ぎ | 泳ぎの姿勢（ダッシュしながらの泳ぎ） | 条件どおり（泳ぎの姿勢でも、ただ水の中を動くときも出す） |
| 落下 | なし | 条件どおり |

- 「両手が空」の判定（`HeldItems`。右クリックで何もしないアイテムは空とみなす）は、決まりどおり 1.21.1 の右クリックで動くアイテムを調べ直す
- 1.12.2 の実装で、バニラの調べた結果に頼っている所（`doc/architecture.md` の「バニラの調べた結果」: 掘り終わりの保留・`blockRemoving` の判定式・エリトラの引き戻し・`processPlayerDigging` など）は、1.21.1 のバニラで調べ直し、違えば `doc/architecture.md` に版ごとに書く

## 3. 仕組みの置き換え（1.12.2 → 1.21.1）

決まりの考え方は 1.12.2 と同じ。置き換え先が見つからない・同じ動きにできないものは、止まる条件に当たる（§8）。

| 1.12.2 | 1.21.1（目安。実装で確かめる） |
|---|---|
| `RenderWorldLastEvent` で毎フレームのヒット判定 | `RenderLevelStageEvent`（最後の段）。毎フレームのまま |
| HUD（`RenderGameOverlayEvent`・`HudSpot.beginOverlay`） | `RegisterGuiLayersEvent` のレイヤーと `GuiGraphics`。カリング・ライティングの扱いは 1.21.1 で調べ直す |
| GUI の上（`DrawScreenEvent.Post`） | `ScreenEvent.Render.Post` |
| `SimpleNetworkWrapper` のメッセージ | `CustomPacketPayload` と `StreamCodec`（`RegisterPayloadHandlersEvent`）。メッセージごとに 1 つの種類（ID は `weakspot:<名前>`） |
| `@Config`（`weakspot.cfg`） | `ModConfigSpec`（TOML。§4） |
| 統計の保存（プレイヤーの NBT・ワールドの保存データ） | プレイヤーはデータアタッチメント（`AttachmentType`。死んでも残す）、ワールドは `SavedData`。NBT のキーの名前は 1.12.2 と同じにする |
| 進捗（`advancements/`） | `data/weakspot/advancement/`（1.21.1 の形式） |
| レシピ（`recipes/`）・アイテムのモデル | `data/weakspot/recipe/`・1.21.1 の形式 |
| アイテムの NBT（的・ガイドの本） | データコンポーネント（ガイドの本は `WRITTEN_BOOK_CONTENT`、的は Mod のコンポーネント） |
| リフレクション（`Reflect`） | アクセストランスフォーマー（§1） |
| Forge の更新確認（`@Mod` の `updateJSON`） | `neoforge.mods.toml` の `updateJSONURL` と `VersionChecker` |
| 相手のクライアントの版（`NetworkDispatcher#getModList`） | NeoForge では読めないので、**接続直後にクライアントが自分の版を送るメッセージを足す**（1.21.1 版だけ。1.21.1 は 1.12.0 から始まるので、互換性の問題はない）。サーバーの版は今と同じく `SyncedSettings.serverVersion` |

- ヒットの間隔（`HitBudget`）・採掘のブーストを捨てる決まり・採掘のヒットの予約と確定・コンボはサーバーの数が正（`ComboSync`）・サーバーはクライアントから来た数を正にしない、は 1.21.1 でも同じ決まり（`CLAUDE.md` の「アーキテクチャの約束事」）
- **採掘の破壊速度**: クライアント（積算）とサーバー（瞬間判定）の結果が一致するかを、1.21.1 のバニラ（`ServerPlayerGameMode`）で確かめ直す。見えない壁（1.11.6）が出ないことを確かめる

## 4. 設定

- 設定の**項目の名前・カテゴリ・初期値・範囲・説明（翻訳）は 1.12.2 と同じ**（`server.mining.boostMultiplier` の形）
- ファイル:
  - サーバーの項目 → `config/weakspot-server.toml`（`ModConfig.Type.COMMON` に、この名前で登録する。ワールドごとの `serverconfig/` には置かない。1.12.2 の `config/weakspot.cfg` と同じく、Modpack の作者・サーバーの管理者が 1 か所で直せるようにするため）
  - クライアントの項目 → `config/weakspot-client.toml`（`ModConfig.Type.CLIENT`）
- 1.12.2 の `weakspot.cfg` から 1.21.1 の TOML への移行はしない（同じワールド・同じ設定を持ち越す場面がないため）。`configVersion`・`WeakSpotConfig.migrate` は 1.21.1 版には作らない
- `SyncedSettings`（サーバーの項目でクライアントが使うもの）は同じ項目・同じ意味で送る。受け取った値を設定のファイルに書き込まない決まりも同じ
- 設定画面は、NeoForge の標準の設定画面ではなく、1.12.2 と同じ `SettingGroups` のまとめの画面を作る（Mod の一覧の「設定」ボタンから開く）
- `doc/config.md` に、版ごとのファイルの名前を書く（項目の表は共通）

- CurseForge: 同じプロジェクト（ID 1714015）に、ファイルを 2 つ。1.21.1 の版の ID は 1.21.1・NeoForge・Java 21（あれば Client・Server も）

## 8. 進め方

- PR は 1 つ（「1.12.0」）。`main` から `claude/port-1.21.1-1.12.0` を切る
- コミットの順（目安）:
  1. 「Add the spec for 1.12.0」（この仕様書がまだ `main` になければ）
  2. 土台: `mc1.21.1/` のビルド・Mod のクラス・設定・通信・`common/` の読み込み・翻訳・CI の matrix
  3. 種類ごと: 「Port mining to 1.21.1」→ 成長 → 機械 → … → 落下（1 種類 1 コミット以上）
  4. 種類をまたぐもの: コンボ・節目・音・他プレイヤーの表示・統計の画面・的当て・ガイドの本・設定画面・コマンド・お知らせ
  5. 1.12.2 版のマイナーの片付け（§0）
  6. 「Release 1.12.0: …」（版・README・CHANGELOG.md・doc・CLAUDE.md・1.11.x の仕様書の削除）
- 途中のコミットを push してよい（PR は全部が揃ってから作る。ビルドが通らない途中の状態で PR を作らない）
- **止まる条件**（push と PR をせずに報告する）: 決まりどおり（互換性を破る変更が要る、仕様の意図が読み取れない、ビルドやテストが通らない、runServer が起動しない）に加えて、**ある種類を 1.21.1 で同じ動きにできない**と分かったとき（どの種類の何が、なぜできないか、代わりの案を添える）
- **ネットワーク**: クラウドの環境のネットワーク設定で、`maven.neoforged.net` と Mojang の配布（`piston-meta.mojang.com`・`piston-data.mojang.com`・`libraries.minecraft.net`・`resources.download.minecraft.net`）を許可しておく（拒否されたら、ホストの名前を報告して止まる）
- runServer: 1.21.1 版がクラウドで起動できれば、クラウドでも確かめる（起動できなければ、devcontainer で）。1.12.2 版は今までどおり

## 10. `CLAUDE.md` に書くこと

- 「プロジェクト概要」の対象: 1.12.2 / Forge 14.23.5.2860 と 1.21.1 / NeoForge 21.1.x の 2 つ
- 「開発環境・コマンド」: 版ごとのビルドのコマンド・JDK（1.12.2 は 8、1.21.1 は 21）・許可するホスト
- 「バージョン」: 版を書く 4 か所。いつも両方の jar を同じ番号で出す。現行は 1.12.0、範囲は `"[1.12,1.13)"`
- 「アーキテクチャの約束事」:
  - 機能を足す・直すときは、**両方の版で同じ PR で**行う（揃え続ける）。版に依存しない部分は先に `common/` に書く
  - リフレクションの決まり（MCP 名 → SRG 名・`Reflect`）は 1.12.2 版のもの。1.21.1 版はアクセストランスフォーマー
  - `RenderWorldLastEvent`・`HudSpot.beginOverlay`・`DrawScreenEvent.Post`・`proxy.onXxx` など、1.12.2 の API の名前が出てくる決まりに、1.21.1 で対応するものを書き足す
  - 相手のクライアントの版を知る方法（1.21.1 は接続直後のメッセージ）
- 「次の作業」: 1.12.0 のあと

## 11. ユーザーに確認してもらうこと

- **1.21.1 版**（`weakspot-1.21.1-1.12.0.jar`。NeoForge 21.1.x を入れた 1.21.1 で）:
  - 19 種類の弱点が全部出て、当たると効くこと（`doc/play.md` の順に。特に、採掘で見えない壁が出ないこと・エリトラ・落下・泳ぎ）
  - 1.21.1 で足した物: ラクダ・ストライダー・チェスト付きボート・いかだの乗り物、ウィンドチャージの投擲物、足場のはしご、燻製器・溶鉱炉の機械（進行度のバー）
  - 試練のスポナー・宝物庫が機械の対象にならないこと
  - コンボ・節目・音・統計の画面（K キー）・的当て・ガイドの本・設定画面
  - マルチプレイ（専用サーバー）: 他プレイヤーのマーク・設定がサーバーの値になること
  - Modpack と一緒に入れても動くこと（入れられれば。All the Mods 10 など）
- **1.12.2 版**（`weakspot-1.12.2-1.12.0.jar`）: 今までどおり動くこと。1.11.x のサーバーにはつながらないこと
- Merge のあと: Release に jar が 2 つ、Modrinth に 2 つ、CurseForge に 2 つ上がること。CurseForge・Modrinth のページで 1.21.1・NeoForge が選べること
- §2.1 の表の「足す」「足さない」（相談で決めた。実装のあと、1.21.1 版で足した物が動くか）
