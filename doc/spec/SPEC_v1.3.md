## 1. 弓の弱点

### 1.1 対象と効果
- 対象: 弓を**引いている最中**のプレイヤー（使用中のアイテムが `ItemBow`。**Mod の弓も、`ItemBow` を継承していれば対象**）
- 1ヒットごとに、弓の引きを **`bowHitTicks`（初期値 5）tick 分**進める（バニラの弓は 20 tick で引き切る）
- 引き切ったら、弱点を消す。引き切ったあとは、それ以上進めない（矢の威力は、バニラと同じく引き切りが上限。過剰チャージはしない）
- 弱点を当てなくても、今までどおり引いて撃てる
- 矢を放った・引くのをやめた・持ち替えたら、弱点を消す
- クリエイティブ・スペクテイターでは弱点を出さない（ほかの弱点と同じ。引きゲージは出す）

### 1.2 操作
- 弓を引いている間（右クリックを押しっぱなし）に、**照準を弱点に合わせるだけでヒット**（クリックは要らない。採掘の弱点と同じ）
- 同じ弱点は、1回当てると次の位置に移る。ヒットの間隔は `bowMinHitIntervalTicks` 以上あける

### 1.3 弱点の位置と描き方（照準の近くの HUD）
- 弱点の位置は、**向き**（yaw / pitch）で持つ。プレイヤーが歩いても、その向きのまま（目の位置からその向きの先に描く）
- 出る位置: 弓を引き始めた瞬間の視線から、**3〜8度**ずれた向き（方向はランダム）
- ヒットのたびに、今の視線から 3〜8度ずれた、前の向きから一定以上（例: 4度）離れた向きへ移る
- 描き方は、釣りの弱点（1.2.0 §1.10.3）と同じ: 画面上の位置に変換して、**画面上で一定の大きさ**の円（半径 **12ピクセル**。GUI の拡大率に合わせる）。自分の弱点と同じ見た目（塗りつぶした円）。1.1.4 の移動の残像もそのまま使う
- 画面の外や後ろにあるときは、描かない（当たり判定もしない）

### 1.4 当たり判定
- 釣りと同じ（`common/FishingMath.allowedAngle`）: 「視線の向き」と「弱点の向き」の角度の差が、画面上の円の半径・視野角・画面の高さから求めた角度より小さいとき
- 判定は、毎フレーム（`RenderWorldLastEvent`）行う

### 1.5 引きの進め方
- 弓の引き具合は、使用中のアイテムの残り時間（`activeItemStackUseCount`）で決まる。ヒットのたびに、これを `bowHitTicks` 減らす
- **サーバーとクライアントの両方で**減らす
  - サーバー: 矢の威力は、サーバーの残り時間から計算される。サーバーで減らさないと効かない
  - クライアント: 弓の見た目（`pull`）と引きゲージは、クライアントの値で描かれる。ヒットの瞬間に、クライアントでも減らす（サーバーの返事を待たない）
- 引き切り（引いた時間 20 tick）を超えて減らさない
- 減らし方は実装で決めてよい（Forge の `LivingEntityUseItemEvent.Tick` の `setDuration`、またはリフレクション。§5）

### 1.6 サーバーでの確認（ヒット）
- そのプレイヤーが弓を引いている最中か（`isHandActive` で、使用中のアイテムが `ItemBow`）
- まだ引き切っていないか
- ヒットの間隔（`bowMinHitIntervalTicks`。ほかの弱点と同じく、2 tick 甘くする）
- 一時オフのプレイヤーでないこと、`bowWeakSpotEnabled` がオンのこと
- 照準の角度は、サーバーでは確かめない（クライアントを信用する。釣りと同じ程度の確認）

### 1.7 引きゲージ
- 弓を引いている間、照準の下に、引き具合のバーを HUD で出す（今までの耐久バー・成長バーと同じ扱い）
  - 大きさ: 幅 **40ピクセル**、太さ **3ピクセル**、照準の中心から **12ピクセル**下（GUI の拡大率に合わせる）
  - 値: 引いた時間 ÷ 20（0.0〜1.0。バニラの弓の引き切りを基準にする。Mod の弓で引き切りの時間が違っても、この計算のまま）
  - 色: 引いている途中は オレンジ `#FF8C42`、引き切ったら 黄 `#FFD23F`。背景は 黒 `#1E1E1E` 半透明（ほかのバーと同じ）
  - 左から伸ばす
- 弱点の設定がオフ（`bowWeakSpotEnabled`）でも、一時オフ（J キー）の間でも、ゲージを出すかどうかは、`bowDrawBarEnabled`（クライアント）で決める（弱点がなくても、引き具合がわかると便利なため）
- F1 で HUD を隠しているときは出さない

### 1.8 他のプレイヤーへの表示
- 弓の弱点は、他のプレイヤーに**見せない**（自分だけ。マークも、ヒット音の転送もしない）

### 1.9 数え方
- 統計に「**弓ヒット数**」（今回・累計）を足す（保存は `PlayerPersisted` の `weakspot` の新しいキー）
- ヒット音・連続ヒット数・コンボの表示・統計の「最大連続ヒット数」には、数える
- 節目と耐久回復には、数えない

### 1.10 一時オフ（J キー）
- オフの間は、弓の弱点の表示・ヒット判定・ヒットの受け付けを止める（1.1.6・1.2.0 §1.11 の一覧に足す）

### 1.11 設定

サーバーの値（同期する）:

| キー | 初期値 | 説明 |
|---|---|---|
| `bowWeakSpotEnabled` | `true` | 弓の弱点のオンオフ |
| `bowHitTicks` | 5 | 1ヒットで進める引きの tick 数（バニラの弓は 20 tick で引き切る） |
| `bowMinHitIntervalTicks` | 4（要調整） | 弓のヒットを受け付ける最小間隔（tick） |

クライアントの値:

| キー | 初期値 | 説明 |
|---|---|---|
| `bowDrawBarEnabled` | `true` | 弓の引きゲージを出すか |

- 画面上の弱点の大きさ（12ピクセル）、出る角度（3〜8度）、最小の移動角度（4度）、ゲージの大きさは、コード内の定数にする
- `bowDrawBarEnabled` の説明は、`weakspot.general.bowdrawbarenabled.tooltip` を `en_us.lang` と `ja_jp.lang` の両方に足す

### 1.12 単体テスト（`common/` の純粋な計算）
- 次の弱点の向き: 今の視線から 3〜8度の範囲で、前の向きから最小の移動角度以上離れること
- 引きの進め方: 引いた時間に `bowHitTicks` を足しても、20 tick を超えないこと
- ゲージの値: 引いた時間 ÷ 20 が 0.0〜1.0 に収まること。引き切りで色が切り替わること

## 2. 近接の弱点

### 2.1 対象と効果
- 対象: **敵**（モンスター。`IMob` を持つ生き物。ゾンビ、スケルトン、クモ、スライムなど）。動物・村人・プレイヤーは対象外
- 攻撃が届く距離で敵に照準を合わせると、敵の当たり判定の箱の、照準が当たっている面に弱点が出る（動物の弱点と同じ出し方。面は、見えている間は変えない）
- 照準が弱点に重なった状態で左クリックで攻撃すると、**クリティカルヒット**になる
  - 威力は、ジャンプ攻撃のクリティカルと同じ **1.5 倍**。ジャンプ攻撃と重ねても 1.5 倍のまま
  - バニラのクリティカルの星のパーティクルと音も、そのまま出る
- ヒットすると、弱点は同じ面の別の位置へ移る
- 弱点から外れた攻撃は、今までどおりの普通の攻撃

### 2.2 攻撃のクールダウン
- 攻撃のゲージが溜まっている（バニラのクリティカルと同じ、90% を超えている）ときだけ、ヒットにする
- 溜まっていない間は、弱点を**薄く**（濃さ 0.35 倍）表示する。その間に弱点に当てても、普通の攻撃（ヒットにも数えない）

### 2.3 弱点を出す条件
- 何を持っていても出す（素手を含む）
- 右クリックを押しているとき（弓を引いている、動物の弱点を出しているなど）と、ブロックを掘っているときは出さない
- クリエイティブ・スペクテイターでは出さない（ほかの弱点と同じ）

### 2.4 サーバーでの確認と、クリティカルの付け方
- クライアントは、照準が弱点に重なった左クリックで、攻撃のパケットより**先に**ヒット通知（敵のエンティティ ID）を送る
- サーバーは、ヒット通知で次を確かめて、「このプレイヤーのこの敵への次の攻撃（5 tick 以内）はクリティカル」と覚える
  - 敵がいて、生きていて、対象（§2.1）であること
  - 届く距離（バニラの攻撃と同じ、6 ブロック以内）
  - ヒットの間隔（`meleeMinHitIntervalTicks`。2 tick 甘くする）
  - 一時オフのプレイヤーでないこと、`meleeWeakSpotEnabled` がオンのこと
- 続いて届いた、その敵への攻撃で、攻撃のゲージが溜まっていれば（2 tick 甘くする）、Forge の `CriticalHitEvent` を許可して、倍率を 1.5 にする
- 照準の位置は、サーバーでは確かめない（クライアントを信用する。ほかの弱点と同じ程度の確認）

### 2.5 他のプレイヤーへの表示
- 近接の弱点は、他のプレイヤーに**見せない**（自分だけ。マークも、ヒット音の転送もしない）

### 2.6 数え方
- 統計に「**クリティカル数**」（今回・累計）を足す。サーバーが実際にクリティカルにした回数を数える
- ヒット音・連続ヒット数・コンボの表示・統計の「最大連続ヒット数」には、数える
- 節目と耐久回復には、数えない

### 2.7 透かし
- 自分の近接の弱点も、動物の弱点と同じく、体に隠れた部分を薄く透かす（ゾンビの腕など）。設定 `animalSpotSeeThrough` に従う（説明を「動物・敵」に直す）

### 2.8 一時オフ（J キー）
- オフの間は、近接の弱点の表示・ヒット判定・ヒットの受け付け・クリティカルを止める

### 2.9 設定（サーバーの値。同期する）

| キー | 初期値 | 説明 |
|---|---|---|
| `meleeWeakSpotEnabled` | `true` | 近接の弱点のオンオフ |
| `meleeMinHitIntervalTicks` | 4 | 近接のヒットを受け付ける最小間隔（tick）。攻撃のゲージの条件もあるので、短めにする |

- クリティカルの倍率（1.5）、覚えておく時間（5 tick）、薄くする濃さ（0.35）は、コード内の定数にする

## 5. 実装時に確認すること

- Forge 14.23.5.2860 の `LivingEntityUseItemEvent.Tick` が、クライアントとサーバーの両方で毎 tick 発火し、`setDuration` で残り時間を変えられるか。使えなければ、`EntityLivingBase` の非公開の `activeItemStackUseCount` を `Reflect` で書く（MCP 名 → SRG 名。開発環境と reobf 後の両方で解決することを確かめる）
- 弓を引いている間の左クリックが、バニラで攻撃にならないこと（照準を合わせるだけのヒットなので、左クリックは使わないが、影響がないことを確かめる）
- クライアントで先に減らした残り時間と、サーバーの残り時間が、ヒットを拒否されたときにずれる場合の扱い（ずれても、矢の威力はサーバーの値で決まる。見た目のずれが目立つなら、報告する）
- 画面上の位置への変換と当たり判定は、`client/FishingSpot` の処理を共通化して使い回せるか
- 近接: ヒット通知と攻撃のパケットが、送った順にサーバーで処理されること（どちらもサーバーのスレッドの予定に積まれる）
- 近接: `CriticalHitEvent` の前に、バニラが攻撃のゲージを 0 に戻す（`resetCooldown`）ので、ゲージは `AttackEntityEvent` の時点で確かめる

## 6. ユーザーに確認してもらうこと（クライアントの見た目・操作は、Claude Code が確認できない）

ビルドした jar を、ホストの Minecraft で試す。

- 弓を引くと、照準の近くに弱点が出て、照準を合わせると当たり、別の位置に移ること
- 当てると、弓の見た目の引きと、ゲージが早く進むこと。約2〜3ヒットで引き切れること
- 引き切ったら弱点が消え、ゲージが黄色になること
- 当てて引き切った矢が、普通に引き切った矢と同じ威力・飛距離で飛ぶこと（サーバーでも進んでいること）
- 当てなくても、今までどおり撃てること
- Mod の弓（あれば）でも、弱点が出ること
- J キーでオフにすると、弓の弱点が出ないこと。`bowDrawBarEnabled` がオンなら、ゲージは出ること
- 統計の「弓ヒット数」が増えること。コンボとヒット音が続くこと
- 近接: ゾンビなどに照準を合わせると弱点が出ること。攻撃のゲージが溜まるまで薄いこと
- 近接: 溜まってから弱点を殴ると、クリティカルの星と音が出て、普通の攻撃より大きく減ること。弱点が別の位置に移ること
- 近接: 弱点から外れた攻撃・溜まる前の攻撃は、普通の攻撃のままであること
- 近接: 動物・村人には、近接の弱点が出ないこと
- 統計の「クリティカル数」が増えること
- 1.2.x のクライアントで、1.3.0 のサーバーに、接続できないこと
