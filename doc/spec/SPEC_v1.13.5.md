# 弱点破壊 Mod 追加仕様書（v1.13.5）

`SPEC_v1.13.4.md`（Mod 1.13.4）に対する**パッチ**の仕様（1.13.3 の点検で判断を保留した「動作に関わるもの」6 件の決定）。ここに書かれていないことは、それと現行実装のままとする。
この仕様書は `doc/spec/SPEC_v1.13.5.md`。

- 対象: Minecraft 1.12.2 / Forge・1.20.1 / Forge・1.21.1 / NeoForge の 3 つ（決まりどおり同じ PR で）
- 前提: 1.13.4 が `main` に取り込み済み
- 経緯: Issue #65「1.13.3 点検のフォローアップ」の「動作に関わるもの」の 6 件を相談して決めた
- 決めたこと:
  - §1 ボートの上限は外す（シングルプレイだけ外す案・今のまま書くだけの案はとらない。「速さの上限は付けない」方針どおり）
  - §2 ムーシュルームに対するボウルは、餌と同じく対象外にする
  - §3 収穫の幸運は、1.12.2 も利き手の道具の幸運を効かせる（バニラで壊すときと同じ）
  - §4〜§6 マーカーの形は、相談のおすすめどおり
  - マルチプレイでボートが速すぎて巻き戻されることを、遊ぶ人に知らせる仕組みは足さない（`doc/play.md` の記述のまま）

## 0. バージョンと互換性

- バージョンを 1.13.4 → **1.13.5**（パッチ）。版を書く 6 か所を揃える
- 通信内容・保存データ・設定の項目は変わらない。1.13.x 同士は接続できる（範囲 `"[1.13,1.14)"`・`PROTOCOL` `"1.13"` のまま）
- §1・§4・§5 はクライアントだけ、§3 はサーバーだけの変更。§2 は両方が同じ `HeldItems` で判定する（古い側と組み合わせても、片方が右クリックを止めるかどうかが変わるだけで、通信は変わらない）。`ServerFeatures.since`・`PlayerText.clientSince` は要らない

## 1. ボートの加速の上限を外す（3 つの版）

- 今: `client/VehicleSpot.tickEnd` は、ボートに足す 1 tick の移動を 8 ブロック（`MAX_BOAT_STEP`）までにしている（サーバーの「動きが速すぎる」の判定に引っかからないように）
- 調べたこと: サーバーは、乗り物が 1 回の通信（1 tick に 1 回）で 10 ブロックを超えて動くと元の位置に戻す（1.21.1 の `ServerGamePacketListenerImpl.handleMoveVehicle`）。シングルプレイの持ち主（LAN を開いた本人を含む）には、この判定がない。8 は足す分だけの上限なので、青氷の上ではバニラの分と合わせて 10 を超え、上限があってもマルチプレイでは巻き戻される
- 変更: 上限をなくす（`MAX_BOAT_STEP` を消す）。速さの上限は設定 `vehicleBoostMaxMultiplier`（初期値 0 = 上限なし）だけになる
- `doc/play.md` の乗り物の節の「非常に速いと、サーバーの『移動が速すぎる』判定で元の位置に戻される場合があります」は今のまま（マルチプレイのときだけと分かるように直す）

## 2. 繁殖待ち中のムーシュルームから、ボウルでシチューが取れない（3 つの版）

- 症状: ムーシュルームに繁殖の待ち時間（動物の弱点のタイマー）があるとき、空のボウルを持って右クリックすると、弱点が出て右クリックが止まり、シチュー（1.12.2 はキノコシチュー）が取れない
- 原因: ボウルは右クリックの処理を持たないアイテムなので、`HeldItems.isFree` で「手が空いている」になる。バケツ・ハサミ・名札・鞍などは右クリックの処理を持つので対象外になっている
- 変更: `HeldItems.isFreeFor` で、ムーシュルーム（1.12.2 は `EntityMooshroom`、1.20.1・1.21.1 は `MushroomCow`）に対するボウルを、餌と同じく対象外にする
- `doc/play.md` の「動物では、さらに…も対象外です」に、ムーシュルームのボウルを足す

## 3. 1.12.2 の収穫でも幸運を効かせる

- 今: 1.20.1・1.21.1 は利き手の道具を渡して収穫物を決める（`Block.getDrops(…, player, tool)`）ので、幸運が効く。1.12.2 は幸運 0 で固定（`getDrops(…, 0)`・`fireBlockHarvesting(…, 0, …)`）
- 変更: 1.12.2 の `server/HarvestHits` で、利き手の道具の幸運の段階（`EnchantmentHelper.getEnchantmentLevel(Enchantments.FORTUNE, …)`）を `getDrops` と `fireBlockHarvesting` に渡す
- コンボの収穫量の増え方（`HarvestBonus`）は、幸運で増えたあとの数に掛かる（1.20.1・1.21.1 と同じ）
- `doc/play.md` の収穫の節に「利き手の道具の幸運が効く」と書く

## 4. ほかの人のマークの星は、的当ての銅を解放するまで輪（3 つの版）

- 今: 自分の弱点の星（`myMarkerShapes` の `star`）は、的当ての銅を解放していないワールドでは円で描く（`MarkerLook.shape`）。ほかの人のマーク（`otherMarkerShape`）は、解放していなくても星を選べて、星で描く
- 変更: ほかの人のマークも、銅を解放していなければ、星を初期値の輪（RING）で描く（`MarkerLook.otherShape` を足し、`WeakSpotRenderer` から使う）
- 設定画面の説明（`otherMarkerShape`）には今までどおり星を書かない（§6 と同じく、ご褒美はゲーム内では伏せる）

## 5. 自分の弱点の形の知らない名前は円（`common/` と 3 つの版）

- 今: `myMarkerShapes` に知らない形の名前（綴り違いなど）を書くと、輪（RING）になる（`MarkerShape.fromName` の既定）。何も書いていない種類は円
- 変更: `MarkerShape.fromName` は、知らない名前・空・null のとき円（CIRCLE）を返す（何も書いていないのと同じ）。`MarkerShapeTest` を直す
- `otherMarkerShape` は enum の設定なので、知らない値は読み込みのときに初期値（RING）になる。`fromName` は使わない（変わらない）

## 6. 形・色のご褒美の書き方（文書だけ）

- ゲーム内の説明（`myMarkerShapes`・`myMarkerColors` の `.tooltip`）は今のまま、ご褒美（星・銀・虹）を書かない
- `doc/config.md` の `myMarkerColors` に、`silver`・`rainbow`（的当ての銀・虹で解放）を書き足す（`myMarkerShapes` の `star` と揃える）

## 9. ユーザーに確認してもらうこと

- 3 つの版: 青氷の上をボートで走りながら乗り物の弱点に当て続け、シングルプレイでは速さが頭打ちにならないこと（コンボが続くほど速くなる）
- 3 つの版: ムーシュルームに繁殖させてすぐ（待ち時間中）、空のボウルを持って右クリックすると、シチューが取れること。素手で右クリックすると、今までどおり弱点が出ること
- 1.12.2: 幸運 III のツルハシを持って実ったジャガイモ・ニンジンを収穫の弱点で収穫すると、幸運なしより多く取れること
- 3 つの版: 的当ての銅を解放していないワールドで `otherMarkerShape` を STAR にすると、ほかの人のマークが輪で出ること（解放したワールドでは星）
- 3 つの版: `myMarkerShapes` に `bow=hexagon` のような知らない形を書くと、弓の弱点が円で出ること
