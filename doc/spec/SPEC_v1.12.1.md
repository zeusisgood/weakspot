# 弱点破壊 Mod 追加仕様書（v1.12.1）

`SPEC_v1.12.0.md`（Mod 1.12.0）に対する**パッチ**の仕様（表面の形が複雑なブロックや、パイプが刺さった機械でも、ブロックの弱点を当てやすくする）。ここに書かれていないことは、それと現行実装のままとする。
この仕様書は `doc/spec/SPEC_v1.12.1.md`。

- 対象: Minecraft Java Edition 1.12.2 / Forge 14.23.5.2860 と 1.21.1 / NeoForge 21.1.264（両方の版を同じ PR で直す）
- 前提: 1.12.0 が `main` に取り込み済み
- ユーザーの報告: Mekanism の機械など、表面の形が複雑なブロック（凹凸・出っ張りのあるもの）だと、ブロックの弱点が叩きづらい。パイプ（ケーブル）が刺さっている機械もやりづらい
- 原因（今の実装）:
  - 弱点（円）は、ブロックを包む**外枠の箱**（1.12.2 の `getSelectedBoundingBox`、1.21.1 の `getShape(...).bounds()`）の面に描く
  - 当たりは、照準が**実際に当たった点**（`objectMouseOver.hitVec` / `hitResult.getLocation()`）と、そのとき当たった**面の向き**（`sideHit` / `getDirection()`）で決めている
  - 照準が凹んだ所や出っ張りの横の面に当たると、面の向きが変わる。そのとき採掘では、弱点がその面に出し直されて飛び回る。右クリックの弱点（成長・収穫・機械）では、面の向きが合わず外れになる
  - パイプは、機械の面の手前の別のブロック。弱点の場所は面の上から無作為に選ぶので、パイプの真後ろに出ることがある。その円を狙うと、バニラの照準は手前のパイプを指すので、機械を狙っていないことになり当たらない（採掘ならパイプを掘ってしまう）
- ユーザーとの相談で決まったこと:
  - **案 A**: 当たりと面を、実際の形ではなく、外枠の箱と視線から決める（下の §1）
  - 対象はブロックの弱点の全種類（採掘・成長・収穫・機械）
  - パイプには**案 A**: 弱点を置く場所を選ぶとき、面の手前の隣のブロックの形を避ける（下の §1.4）。パイプ越しでも当たりにする案（B）は採らない（照準が手前のパイプに当たるので、採掘ではパイプを掘ってしまい、右クリックはパイプへ行く。サーバーの検証も変える必要がある）
  - 版は 1.12.1（パッチ）。両方の jar を出す

---

## 0. バージョンと互換性

- バージョンを 1.12.0 → **1.12.1** にする（版を書く 4 か所）
- 変えるのはクライアントの照準の判定だけ。通信内容・設定・保存データは変わらない（サーバーは今も、採掘ではブロックの位置と掘っているか、右クリックの弱点では対象のブロックと距離だけを確かめていて、当てた面・点は見ていない）。1.12.x 同士はそのまま接続できる。`ServerFeatures.since` も要らない

## 1. 当たりと面の決め方

ブロックの弱点（`WeakSpot` で、エンティティでないもの）に当てはめる。動物の弱点・照準のまわりの弱点・画面の上の弱点は変えない。

### 1.1 面

- 目の位置から視線の向きに伸ばした線（照準の線）が、外枠の箱に**入る面**を、その時点の照準の面とする（`common/` に計算を足す。下の §2）
- 今まで `sideHit` / `getDirection()` を使っていた所（採掘の弱点を出し直すかの判定、右クリックの弱点の「照準の面と弱点の面が同じか」）は、この面を使う
- 作物などの面の選び方（`growthFace`。同じ大きさの側面が複数あるとき、見えている間は変えない）は今のまま。そこへ渡す「照準の面」だけをこの面にする
- 照準の線が外枠の箱に入らない（箱の中に目がある・箱の縁をかすめるなど、バニラの照準はブロックに当たっているのに計算では外れる）ときは、今までどおり `sideHit` / `getDirection()` と当たった点を使う

### 1.2 当たり

- 照準の線と、弱点の面（外枠の箱の面の平面）が交わる点で当たりを決める（円の中か）。実際に当たった点は使わない
- 照準の線が、その面の平面と目の前で交わらないときは外れ
- ブロックへの照準そのもの（バニラの `objectMouseOver` / `hitResult` がそのブロックを指しているか、掘っているか、右クリックを押しているか）は今のまま。外枠の箱だけを見て、隣のブロックを狙っているのに当たる、ということはない

### 1.3 見た目

- 弱点の描き方・大きさ・出し直しの演出は変えない（円は今も外枠の箱の面に描いているので、凹んだ所では手前に浮いて見える。これは今と同じ）
- 普通の 1 マスのブロック（外枠の箱と実際の形が同じ）では、照準の線が入る面と当たった面、交わる点と当たった点が同じなので、動きは今と変わらない

### 1.4 手前のブロックを避けて置く

- 弱点を置く・出し直す（当てたあとに移る）場所を選ぶとき、面の真正面の隣のブロック（ブロックの位置 + 面の向き）が、空気でも 1 マスの立方体でもなければ、その形を面に写した長方形を避ける（円が長方形に少しでも重なる場所には置かない）
  - 形: 1.21.1 は外枠の形（`getShape`）の箱の一覧（`toAabbs`）、1.12.2 は当たり判定の箱の一覧（`addCollisionBoxToList`。なければ選択の枠 `getSelectedBoundingBox`）。パイプの本体と、つながった腕を別々の箱として避けられるように、1 つの外枠にまとめない
  - 隣のブロックが 1 マスの立方体なら、その面はそもそも見えず狙えないので、何もしない
- 避けると置ける場所がない（面がパイプでほぼ埋まっている）ときは、今の置き方に戻す（隠れることがある）
- 避けるのは、自分の弱点の場所を選ぶときだけ。ほかのプレイヤーから届いた弱点のマークの位置は、届いたまま描く
- 弱点の大きさは変えない

## 2. 置き場所

- 照準の線と箱が入る面・交わる点の計算は Minecraft に依存しないので、`common/`（`FaceMath` か、新しいクラス）に書き、テストを足す（両方の版で同じものを使う）
  - テストの例: 箱の正面から入る線は正面、斜め上から入る線は上面、箱の中から出る線・箱をかすめない線は「入らない」、面の平面との交点、目の後ろの交点は外れ
- §1.4 の避ける長方形は、`common/WeakSpotPlacer.place` に「避ける長方形の一覧」を足す（空なら今と同じ動き）。テストを足す
  - テストの例: 避ける長方形に重なる場所には置かない、置ける場所がなければ今と同じ候補から選ぶ、空の一覧では今と同じ
- 隣のブロックの箱を面の座標の長方形に写す計算も `common/`（`FaceMath`）に書く
- 両方の版の `client/ClientWeakSpotHandler`（`aimMining`・`aimPreDig`・`aimRightClick`）と `client/WeakSpot` を直す

## 5. ユーザーに確認してもらうこと

- Mekanism の機械など、表面の形が複雑なブロックで、採掘・機械（しゃがんで右クリック）の弱点が狙ったとおりに当たること。円が面の間を飛び回らないこと（両方の版。Mekanism は 1.12.2 にも 1.21.1 にもある）
- 普通のブロック・作物・サトウキビ・ハーフブロックなどで、今までと同じに当たること
- 隣のブロックを狙っているのに当たる、ということがないこと
- パイプ・ケーブルが刺さった機械で、弱点がパイプの後ろに出ないこと。パイプでほぼ埋まった面でも、弱点が出ること
