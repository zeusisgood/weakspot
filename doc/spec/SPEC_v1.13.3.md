## 1. 不具合の修正

### 1.1 設定画面で変えたサーバーの項目が保存されない（1.21.1。1.20.1 も同じ形）

- 症状: 1.21.1 版の設定画面（Mods → 設定）の 1 つのまとめで、クライアントの項目とサーバーの項目を両方変えて「完了」を押すと、サーバーの項目だけが元の値に戻る（ファイルにも書かれない）
- 原因:
  - 設定画面の「完了」は、変えた項目を全部フィールドに書いてから、クライアントのファイル → サーバーのファイルの順に保存する（`WeakSpotGuiFactory.SettingsScreen.onClose`）
  - NeoForge（FML 4.0.45）は、保存（`ModConfigSpec.save`）の中で、その場で `ModConfigEvent.Reloading` を出す（`LoadedConfig.save`。`javap` で確かめた）
  - `WeakSpotConfig.onLoad` は、どちらのファイルの読み直しでも**両方**のファイルの値をフィールドへ写していた。そのため、クライアントのファイルを保存した瞬間に、まだ保存していないサーバーの項目のフィールドが、ファイルの古い値に戻る
- 修正: 読み込み・読み直しのイベントでは、**そのファイル（server／client）の値だけ**をフィールドへ写す（1.20.1・1.21.1 の `WeakSpotConfig`）。`/weakspot reload`（`reloadFromFile`）は今までどおり両方を写す
- 1.20.1 版（Forge 47）は、読み直しの知らせがファイルの見張りのスレッドから遅れて届くので、ふつうは起きない。ただし同じ形（知らせが保存の合間に届けば同じことが起きる）なので、同じように直す
- 1.12.2 版は Forge の設定画面と `ConfigManager.sync` で、この形ではない（直さない）
- 1.21.1 版の `saveServer` は、保存の中の読み直しでも、そのあとでも全員へ送り直す（2 回送る）。害はないので、そのままにする（NeoForge の動きが変わっても送り漏れないように）

### 1.2 設定画面で、読めない値を入れたあとにページを送ると、その項目が保存されなくなる（1.20.1・1.21.1）

- 症状: 数の欄に読めない値（例 `3.0x`）を入れると欄と名前が赤くなる。そのままページを送って戻る（または画面の大きさを変える）と、欄には最後に読めた値が表示されるのに、名前は赤いままで、「完了」を押してもその項目は保存されない
- 原因: 欄を作り直すとき、欄には最後に読めた値を入れるが、「読めなかった」の印（`invalid`）を消していない
- 修正: 欄を作り直すときに、印を消す（表示している値がそのまま保存される）

### 1.3 1.20.1 版: 草に成長の弱点が出る

- 症状: 1.20.1 版で、手が空いた状態で草（短い草）を右クリック長押しすると、成長の弱点が出る（`doc/play.md` は「草ブロック・草・背の高い草花は、初期設定では対象外」）。当てても何も育たない
- 原因: `growthExcludedBlocks` の初期値の `minecraft:short_grass` は、Minecraft 1.20.3 からの登録名。1.20.1 の草の登録名は `minecraft:grass`（1.20.1 のバニラの jar のブロックの一覧で確かめた。初期値のほかの名前は 1.20.1・1.21.1 とも実在する）
- 修正（1.20.1 版だけ）:
  - 初期値の `minecraft:short_grass` を `minecraft:grass` にする（新しく作られる設定ファイル）
  - 一覧に `minecraft:short_grass` があれば、`minecraft:grass` も対象外として扱う（`SyncedSettings.fromConfig`）。1.13.2 までに作られた設定ファイルと、新しい Minecraft の名前で書いた一覧でも、草が外れるようにするため。設定ファイルは書き換えない
- 1.12.2 版（`minecraft:tallgrass`）・1.21.1 版（`minecraft:short_grass`）は正しいので、変えない

## 2. 整理（動作は変わらない）

### 2.1 使っていないコード・翻訳

- 使っていない import（1.12.2 の `BowDraw`・`client/EnchantSpot`・`client/WeakSpotRenderer`・`server/EnchantHits`・`server/FishingHits`、1.21.1 の `client/WeakSpotRenderer`・`server/ServerBoostTracker`）
- 使っていない定数: 1.20.1・1.21.1 の `client/Draw` の `LINES`・`LINE_STRIP`、1.21.1 の `ServerStats.TAG`（保存先がデータアタッチメントになって、使わなくなった）
- `client/FishingSpot` の `aimed`（3 つの版）: 代入したフレームの中でしか読まないので、フィールドをやめる
- 翻訳キー `weakspot.sound.chord`（日英）: どの版のコードからも使っていない（統計画面は `weakspot.sound.chordShort`）
- `ServerFeatures`・`PlayerText.of`／`clientSince`・`ServerLang` は、今は呼ぶ所がないが、1.13.0 の決定どおり仕組みとして残す

### 2.2 コードと合わなくなった説明

設定ファイルのコメント（`@Config.Comment`。3 つの版）と、設定画面の説明（`lang/*.json` の `.tooltip`。日英）を、今の動作に合わせる。

| 項目 | 前 | 今の動作に合わせた説明 |
|---|---|---|
| `hitChordEnabled` | コンボ 25 から 2 音、100 から 3 音 | コンボ 25 から 2 音になり、コンボの段階ごとに和音が厚くなる（`HitPitch.chordOffsets`: 50 で 3 音、75 で 4 音…） |
| `sleepWeakSpotEnabled` | クリックで当てると | カーソルを重ねると（1.10.1 から重ねるだけ） |
| `otherMarkerShape` | 自分のマークは円のまま | 自分の弱点の形は `myMarkerShapes` |
| `animalSpotSeeThrough` | 動物・敵の弱点、ニワトリやゾンビの腕 | 動物の弱点、ニワトリ（エンティティに出る弱点は動物と村人だけ） |
| `myHitSound`（コメントと日本語の説明） | 採掘・成長・機械で共通 | 全種類で共通 |

コードのコメントは、今の動作と違うものだけを直す（HOME キーなのに「J を押した」、コンボのタイトルは 300 からなのに「コンボの 1000」、`HitMessage` の entityId は動物・乗り物、など）。

## 6. ユーザーに確認してもらうこと

- 1.21.1（できれば 1.20.1 も）: シングルプレイで Mods → 弱点破壊 → 設定 →「採掘」などのまとめで、クライアントの項目（例: 耐久バーの表示）とサーバーの項目（例: 採掘の倍率）を両方変えて「完了」。開き直して、両方が変わったままであること（`config/weakspot-server.toml` と `weakspot-client.toml` にも書かれている）
- 1.20.1・1.21.1: 数の欄に `abc` と入れて赤くし、ページを送って戻ると、欄が元の値・名前が白に戻ること。そのあと別の値に変えて「完了」で保存されること
- 1.20.1: 手が空いた状態で草（短い草）を右クリック長押ししても、成長の弱点が出ないこと（1.13.2 までの設定ファイルのままで）。小麦・苗木には今までどおり出ること
- 3 つの版: 設定画面の説明（和音・睡眠・ほかの人のマークの形・隠れた弱点を透かす）が §2.2 のとおりになっていること。ほかの遊び方・見た目が 1.13.2 と同じであること
