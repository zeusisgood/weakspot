# 弱点破壊 Mod 追加仕様書（v1.1.4）

`SPEC_v1.1.md`（Mod 1.1.0）から `SPEC_v1.1.3.md`（Mod 1.1.3）までに対する**パッチ**の仕様。ここに書かれていないことは、それらと現行実装のままとする。
仕様書は、リポジトリの `doc/` ディレクトリに置く（この仕様書は `doc/spec/SPEC_v1.1.4.md`）。
仕様と食い違う実装をする場合は、`CLAUDE.md` のリリースの流れ（止まる条件）に従う。

- 対象: Minecraft Java Edition 1.12.2 / Forge 14.23.5.2860
- 前提: **1.1.3 がリリースされたあと**に、この仕様書の作業を始める（1.1.3 の内容を土台にする）
- 内容: **弱点が移動するときの残像演出**（Fortnite の、弱点が次の場所へ動く軌跡に近いもの）。**見た目だけ**で、当たり判定やヒットの間隔は変えない
- この仕様書の内容は、Mod のバージョン **1.1.4** として、リリースする

---

## 0. バージョンとパッチの制約

- バージョンは 1.1.3 → **1.1.4**（`build.gradle` の `version` と `WeakSpotMod.VERSION` の2か所を、そろえて変える）
- `WeakSpotMod.ACCEPTED_VERSIONS`（`[1.1,1.2)`）は、変えない。1.1.x 同士は、互いに接続できる
- **パッチなので、互換性を破る変更を入れない**（`SPEC_v1.1.md` §0 のバージョンの方針）
  - パケットの追加・削除・中身の変更をしない。`SyncedSettings` に、項目を足さない
  - サーバーが保存するデータの形式を変えない
  - 設定キーの削除や、意味の変更をしない
- この仕様書の変更は、**クライアントだけ**。サーバーは変えない

## 1. 方針

- **当たり判定は、移動先で即時**。ヒットした瞬間から、新しい弱点の位置で当たり判定を行う（今までどおり）。残像は見た目だけ
- **マーカーは、ごく短い時間で移動する**。残像は「どこへ動いたか」の手がかりとして、一応あるだけ。見た目の遅れは、最小限にする
- 演出のせいで、ヒットの間隔が延びたり、破壊が遅くなったりしてはいけない

## 2. 演出の内容

### 2.1 マーカーの移動
- ヒットしたら、マーカー（弱点の表示）を、古い位置から新しい位置へ、**約80ミリ秒**で動かす
- 動き方は、**ease-out**（最初に大きく動き、最後にゆっくり止まる）。前半で、ほとんどの距離を動かし終える。見た目の遅れを、最小限にするため
- 時間は、tick ではなく**実時間（ミリ秒）**で数える。サーバーの負荷（TPS の低下）やフレームレートに影響されないようにする
- 描画は、フレームごとに位置を補間する（滑らかに見せる）

### 2.2 残像
- マーカーが通った道に、**3〜4個**の残像を残す
- 残像は、弱点と同じ色で、**約150ミリ秒**かけて透明になって消える（古い残像ほど、先に消える）
- マーカーの先頭（動いている最中のマーカー）は、少し明るくしてよい（例: 白 `#FFFFFF` を重ねる）。移動が終わったら、通常のマーカーの見た目に戻る

### 2.3 移動中に次のヒットがあったとき
- 次のヒットの判定は、すでに新しい位置で行っているので、移動中でもヒットは成立する（今までどおり）
- 移動中に次のヒットがあったら、前の移動は打ち切り、**前の移動先（判定上の位置）**から、次の移動先へ、新しい移動を始める
- 前の移動の残像は、そのまま消えていく（途中で消さない）

### 2.4 残像を出さない場合（その場で切り替える）
- 弱点が初めて出たとき（前の位置がない）
- 弱点が、別の面、または別のブロックへ移るとき（面をまたぐ残像は、不自然なため）
- 弱点が消えたとき（長押しをやめて、残る時間が過ぎたときなど）
- 設定で、残像をオフにしたとき（§4）

## 3. 対象

- 採掘・成長・機械の、**すべての弱点**（同じ描画の仕組みを使う）
- **他のプレイヤーの弱点マーク**（`SPEC_v1.1.md` §8.5）にも、同じ演出を出す
  - 「動いた」通知を受けたとき、クライアントは、そのプレイヤーのマークの前の位置を知っているので、通信を変えずに、残像を出せる
  - 色は、他のプレイヤーのマークの色（初期値は水色 `#3FA9FF`）と透明度に従う
  - 送信の間隔の制限（`markerSendMinIntervalTicks`）で、途中の移動がまとめられて届くことがある。その場合は、最後に知っている位置から、届いた位置へ動かす
  - 前の位置と、面またはブロックが違うときは、残像を出さない（§2.4）

## 4. 設定（クライアント）

`weakspot.cfg` の `[クライアント]` の項目として足す。見た目だけに関わるので、各自の設定で、サーバーとは同期しない。

| キー | 初期値 | 説明 |
|---|---|---|
| `weakSpotTrailEnabled` | `true` | 弱点の移動の演出（移動と残像）のオンオフ。オフにすると、今までどおり、その場で切り替わる |

- 移動の時間（80ミリ秒）、残像の数（3〜4個）、残像が消える時間（150ミリ秒）は、**コード内の定数**にする（設定には出さない）
- `CLAUDE.md` の設定のルールを守る: `[クライアント]` の項目は、`WeakSpotConfig` をそのまま読む。README の設定表（クライアントの項目）にも足す
- 設定の説明の文字列は、`en_us.lang` と `ja_jp.lang` の両方に足す
- 既存の `weakspot.cfg` には、次に起動したときに、初期値で追加される

## 5. 実装の範囲

### 5.1 やること
- マーカーの表示位置を、判定上の位置とは別に持つ（判定上の位置は、今までどおり、ヒットの瞬間に更新する）
- 移動の演出（ease-out の補間、実時間、フレームごとの補間）と、残像の描画
- 他のプレイヤーのマークへの、同じ演出
- 設定の追加（§4）

### 5.2 やらないこと
- 当たり判定、ヒットの間隔、破壊の速さの変更
- サーバーの変更、通信内容の変更
- 面やブロックをまたぐ残像

### 5.3 単体テスト
移動と残像の計算は、Minecraft に依存しない純粋な計算として `common/` に置き、テストを書く。
- 補間: 経過時間 0 で古い位置、80ミリ秒以上で新しい位置になること。途中の値が、ease-out の形（前半で、半分より多く進む）になること
- 残像の透明度: 生まれた直後が最大で、150ミリ秒で 0 になること。0 未満にならないこと
- 移動中の打ち切り（§2.3）: 新しい移動の始点が、前の移動先になること
- 残像を出さない場合（§2.4）の判定: 前の位置がないとき、面またはブロックが違うときは、その場で切り替えること

### 5.4 描画の負荷
- 残像は、1つの弱点につき数個の四角形だけなので、負荷は小さい。消えた残像は、すぐに捨てる

## 6. 実装時に確認すること

- 現行のマーカーの描画（`WeakSpotRenderer` など）が、判定上の位置をそのまま描いているか。表示位置を別に持てるか
- 他のプレイヤーのマークの「動いた」通知の処理で、前の位置を参照できるか
- 実時間の取り方（描画のフレームで使える時計）

## 7. リリース

- README の「最新版」の行を 1.1.4 にし、「更新履歴」に 1.1.4 を追加する
- README の、弱点の説明（または、見た目の説明）に、移動の演出を書く。当たり判定は、移動先で即時であることも書く
- README の設定表（クライアントの項目）に、`weakSpotTrailEnabled` を足す
- `CLAUDE.md` の、マーカーの描画の記述に、表示位置と判定上の位置を分けたことを書く
- リリースの流れは、`CLAUDE.md` のリリースの流れ（承認を待たずに push まで進めるルール）に従う

**README の更新履歴の案（1.1.4）**

```markdown
### 1.1.4

- 弱点が移動するとき、古い位置から新しい位置へ、残像を引いて素早く動くようにした（目で追いやすくするため。見た目だけで、当たり判定は移動先で即時）
- 他のプレイヤーの弱点マークにも、同じ演出が出る
- 設定 `weakSpotTrailEnabled` で、オフにできる

```

## 8. 未決事項（仮置きで進めてよい）

- 移動の時間（80ミリ秒）、残像の数（3〜4個）、残像が消える時間（150ミリ秒）。遊びながら調整する
- 先頭を明るくするか、明るさの程度

## 9. ユーザーに確認してもらうこと（クライアントの見た目は、Claude Code が確認できない）

ビルドした jar を、ホストの Minecraft で試す。

- ヒットしたとき、マーカーが、古い位置から新しい位置へ素早く動き、残像が短く残ること
- 移動がほとんど待たされないこと（テンポよく連続ヒットできること）
- マーカーが動いている最中に、移動先を狙っても、ヒットすること
- 連続で素早くヒットしたとき、マーカーが飛び飛びにならず、次の移動先へ続けて動くこと
- 弱点が初めて出たとき、別の面に移ったときは、残像が出ないこと
- 他のプレイヤーのマークにも、同じ演出が出ること（水色）
- 設定 `weakSpotTrailEnabled` をオフにすると、今までどおり、その場で切り替わること
- 1.1.3 のサーバー（またはクライアント）と、1.1.4 のクライアント（またはサーバー）で、接続できること
