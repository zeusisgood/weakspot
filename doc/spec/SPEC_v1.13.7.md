# 弱点破壊 Mod 追加仕様書（v1.13.7）

`SPEC_v1.13.6.md`（Mod 1.13.6）に対する**パッチ**の仕様（1.13.3 の点検で判断を保留した「小さな無駄」6 件の決定）。ここに書かれていないことは、それと現行実装のままとする。
この仕様書は `doc/spec/SPEC_v1.13.7.md`。

- 対象: Minecraft 1.12.2 / Forge・1.20.1 / Forge・1.21.1 / NeoForge の 3 つ（決まりどおり同じ PR で）
- 前提: 1.13.6 が `main` に取り込み済み
- 経緯: Issue #65「1.13.3 点検のフォローアップ」の「小さな無駄」の 6 件を相談して決めた。仕様書の段階のレビューで、いったん直すと決めた 2 件（設定の送り直し・スポナーの位置）を見直して、今のままにした。これで Issue #65 の項目はすべて決まる
- 決めたこと:
  - 直す: 近接の敵の探索（§1）。あわせて、数字の書式（§2）と、的当ての段階の番号の守り（§3）も直す
  - 今のまま（直さない）:
    - 落下の着地点の探索（落下の弱点を出している間、1 フレームに 2 回ほど真下の列を探す）: 落ちている数秒の間だけで、量が小さい。1 tick の間使い回すと、tick の間の位置の補間とずれる心配が増える
    - ヒットのたびの統計の NBT の読み書き（累計 30 項目ほど）: ヒットの数は間隔の設定で抑えられていて、量が小さい。累計をメモリーに持つと、サーバーが落ちたときに統計が消える危なさが増える
    - 設定を保存したときに、つないでいる全員へ同じ設定を 2 回送る（1.20.1・1.21.1）: 人が設定画面で「完了」を押したときだけで、小さなメッセージが 1 回余分に出るだけ。同じ中身なら送らない形にすると、前に送った中身・サーバー停止のときの片付け・別のスレッドから呼ばれるときの気配り（1.20.1 は、設定画面のスレッドと Forge のファイルの見張りのスレッドから呼ばれる）が 3 つの版に増える。2 回目は、ローダーの読み直しの知らせ方が変わっても送り漏れないように残す（1.13.3 の決定のまま）
    - 機械のバーを出したスポナーの位置を、サーバーが止まるまで覚えている: 1 つ 100 バイトほどで、サーバーを止めれば消える。見なくなった位置を捨てる形にすると、位置ごとの時刻と片付けの処理が 3 つの版に増え、しばらく見なかったスポナーのバーが 0 から出直す、という新しい振る舞いも生まれる

## 0. バージョンと互換性

- バージョンを 1.13.6 → **1.13.7**（パッチ）。版を書く 6 か所を揃える
- 通信内容・保存データ・設定の項目は変わらない。1.13.x 同士は接続できる（範囲 `"[1.13,1.14)"`・`PROTOCOL` `"1.13"` のまま）
- 遊び方は変わらない。§2 で、OS の言語によっては数字の見た目が変わる（例: ドイツ語の OS で `1,5` → `1.5`）

## 1. 近接の敵の探索を、近接の弱点が使えるときだけにする（3 つの版）

- 今: `client/MeleeSpot.beforeTick` は、剣・斧（1.21.1 はメイスも）を持っている間、毎 tick 16 ブロック以内の敵を探す（`MeleeTargets.hasEnemyNear`）。近接の弱点がオフ（サーバーの設定・種類のオフ・HOME キーの一時オフ・的当ての最中など）でも探している
- 変更: 探す前に、その種類が使えるか（`AimSpotKind.allowed`）を確かめ、使えなければ探さずに「敵はいない」とする（`enemyNear = allowed(mc) && …` の 1 行）
- 弱点の出方は変わらない（`AimSpots` は `beforeTick` のすぐあとに同じ tick で `allowed` を見て、偽なら弱点を消す。`enemyNear` を読むのは `wanted` だけ）

## 2. 数字をいつも同じ書式で出す（3 つの版）

- 今: 次の所が `String.format` を地域の指定なしで使っていて、OS の言語の書式になる（ゲームの言語とは関係なく、たとえばドイツ語の OS なら `1,5`）
  - 統計画面の 1 ブロックあたりの平均と、短縮した時間（`client/StatsTab`。秒の `%.1f`、分・時間の `%02d` を含む）
  - 的当ての残り時間（`client/TargetPlay`）
  - `/weakspot stats` の平均と短縮した時間（`server/WeakSpotCommand`。サーバーの OS の書式になる）
- 変更: 上の `String.format` に `Locale.ROOT` を付け、ゲームの言語・OS の言語に関係なく、いつも `1.5`・`05` の形にする
- もう `Locale.ROOT` を付けている所（`ChargeGauge`・`MachineComboBoost`・`VillagerBreeding` など）は、そのまま
- 色の `String.format("#%06X", …)`（`MarkerLook`・`KindsTab`）は、16 進の書式が地域の書式を使わないので、変えない

## 3. 的当ての段階の番号を、上の端まで確かめる（3 つの版）

- 今: 的当ての終わりの知らせ（`client/TargetPlay`）で、取った段階を知らせるときに `TargetRules.Tier.values()[newTier]` を、`newTier > 0` だけ確かめて引いている。同じ所の少し下（取った段階を覚える所）は、`newTier < TargetRules.Tier.values().length` も確かめている
- 変更: 知らせる所も、`newTier < TargetRules.Tier.values().length` を確かめる（範囲の外なら知らせない）
- 今は段階の数が変わらないので起きない。あとのパッチで段階を足したとき、新しいサーバーにつないだ古いクライアントが落ちないための守り（同じマイナーの中では、パッチの違う版同士がつながる）
