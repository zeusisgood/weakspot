# 弱点破壊 Mod 追加仕様書（v1.13.7）

> **下書き**（ユーザーが「実装」と言うまで実装しない）

`SPEC_v1.13.6.md`（Mod 1.13.6）に対する**パッチ**の仕様（1.13.3 の点検で判断を保留した「小さな無駄」6 件の決定）。ここに書かれていないことは、それと現行実装のままとする。
この仕様書は `doc/spec/SPEC_v1.13.7.md`。

- 対象: Minecraft 1.12.2 / Forge・1.20.1 / Forge・1.21.1 / NeoForge の 3 つ（決まりどおり同じ PR で）
- 前提: 1.13.6 が `main` に取り込み済み
- 経緯: Issue #65「1.13.3 点検のフォローアップ」の「小さな無駄」の 6 件を相談して決めた。これで Issue #65 の項目はすべて決まる
- 決めたこと:
  - 直す: 近接の敵の探索（§1）、設定の送り直しの重なり（§2）、スポナーの位置の記憶（§3）、小数の書式（§4）、的当ての段階の番号（§5）
  - 今のまま（直さない）:
    - 落下の着地点の探索（落下の弱点を出している間、1 フレームに 2 回ほど真下の列を探す）: 落ちている数秒の間だけで、量が小さい。1 tick の間使い回すと、tick の間の位置の補間とずれる心配が増える
    - ヒットのたびの統計の NBT の読み書き（累計 30 項目ほど）: ヒットの数は間隔の設定で抑えられていて、量が小さい。累計をメモリーに持つと、サーバーが落ちたときに統計が消える危なさが増える

## 0. バージョンと互換性

- バージョンを 1.13.6 → **1.13.7**（パッチ）。版を書く 6 か所を揃える
- 通信内容・保存データ・設定の項目は変わらない。1.13.x 同士は接続できる（範囲 `"[1.13,1.14)"`・`PROTOCOL` `"1.13"` のまま）
- 遊び方は変わらない。§4 で、OS の言語によっては数字の見た目が変わる（例: ドイツ語の OS で `1,5` → `1.5`）

## 1. 近接の敵の探索を、近接の弱点が使えるときだけにする（3 つの版）

- 今: `client/MeleeSpot.beforeTick` は、剣・斧（1.21.1 はメイスも）を持っている間、毎 tick 16 ブロック以内の敵を探す（`MeleeTargets.hasEnemyNear`）。近接の弱点がオフ（サーバーの設定・種類のオフ・HOME キーの一時オフ・的当ての最中など）でも探している
- 変更: 探す前に、その種類が使えるか（`AimSpotKind.allowed`）を確かめ、使えなければ探さずに「敵はいない」とする
- 弱点の出方は変わらない（使えないときは、もともと `allowed` で弱点を出さない）

## 2. 設定の送り直しで、同じ中身を 2 回送らない（3 つの版）

- 今: サーバーの設定を設定画面から保存すると、1.20.1・1.21.1 は、つないでいる全員へ同じ設定（`SettingsMessage`）を 2 回送る
  - 1.21.1: NeoForge が保存の中で読み直しを知らせ（`ModConfigEvent.Reloading`）、そのとき送る。そのあと `WeakSpotConfig.saveServer` も送る
  - 1.20.1: `saveServer` が送り、そのあと Forge がファイルの見張りから少し遅れて読み直しを知らせ、そのときも送る
  - 2 回目は、ローダーの読み直しの知らせ方が変わっても送り漏れないように残している（1.13.3 の決定）ので、呼び出しは減らさない
- 変更: `server/SettingsSync.resendToAll` は、全員へ送る中身（`SyncedSettings.server()` を通信の形にしたバイト列）を覚えておき、前に全員へ送ったものと同じなら送らない
  - 新しく入ってきた人には、今までどおり入ったときに送る（`SettingsSync.onLogin`。覚えた中身とは関係なく送る）
  - 覚えた中身は、サーバーが止まるときに忘れる（次に起動したサーバーで、前のサーバーの中身と比べないように）
  - `/weakspot reload` も同じ道を通るので、ファイルの中身が変わっていなければ送らない
- 1.12.2 は今も 1 回だけだが、同じ形に揃える（3 つの版の `SettingsSync` の形を同じにするため）
- 実装のときに確かめること: 同じ中身かを比べるのに使うバイト列が、`SettingsMessage` が実際に書く形と同じになること（項目を足したときにずれないように、同じ書き方を使う）

## 3. 見なくなったスポナーの位置を捨てる（3 つの版）

- 今: `server/MachineStates` は、機械のバーを出したスポナーの位置と待ち時間（`MachineProgress.SpawnerDelay`）を、ディメンションごとに、サーバーが止まるまで覚えている。壊された・爆発で消えたスポナーの分も残る
- 変更: 位置ごとに最後に見たときのサーバーの tick を覚え、**5 分（6000 tick）**だれも見ていない位置を捨てる。片付けは、新しい位置を覚えるときに、そのディメンションの分をまとめて行う（毎 tick は見ない）
- 捨てた位置をまた見たときは、今までどおり新しく覚え直す（バーの進み方は、待ち時間の最初から数え直す。今の「初めて見たスポナー」と同じ）

## 4. 小数をいつも同じ書式で出す（3 つの版）

- 今: 次の所が `String.format("%.1f", …)`・`String.format("%.2f", …)` で、OS の言語の書式になる（ゲームの言語とは関係なく、ドイツ語の OS なら `1,5`）
  - 統計画面の 1 ブロックあたりの平均と、短縮した時間（`client/StatsTab`。秒・分・時間）
  - 的当ての残り時間（`client/TargetPlay`）
  - `/weakspot stats` の平均と短縮した時間（`server/WeakSpotCommand`。サーバーの OS の書式になる）
- 変更: 上の `String.format` に `Locale.ROOT` を付け、いつも `1.5` の形にする（Minecraft 本体も、デバッグ画面などの数字は `Locale.ROOT` で出している）
- 色の `String.format("#%06X", …)`（`MarkerLook`・`KindsTab`）は 16 進の数字だけなので、変えない

## 5. 的当ての段階の番号を、上の端まで確かめる（3 つの版）

- 今: 的当ての終わりの知らせ（`client/TargetPlay`）で、取った段階を知らせるときに `TargetRules.Tier.values()[newTier]` を、`newTier > 0` だけ確かめて引いている。同じ所の少し下（取った段階を覚える所）は、`newTier < TargetRules.Tier.values().length` も確かめている
- 変更: 知らせる所も、`newTier < TargetRules.Tier.values().length` を確かめる（範囲の外なら知らせない）
- 同じマイナー同士しか接続しないので、今は起きない。守りとして揃える

## 8. ユーザーに確認してもらうこと

- 3 つの版: 剣を持って敵に近づくと、今までどおり近接の弱点が出ること。HOME キーで一時オフにすると出ないこと
- 3 つの版（シングルプレイかマルチプレイのサーバー側）: 設定画面でサーバーの項目（例: 採掘の倍率）を変えて「完了」を押すと、今までどおり効くこと。マルチプレイでは、ほかの人にも効くこと
- 3 つの版: 統計画面の平均・短縮した時間、的当ての残り時間が `1.5` の形で出ること（OS の言語を変えられるなら、ドイツ語などでも）
- 3 つの版: スポナーを見て機械のバーが出ること。5 分ほど離れてから戻っても、またバーが出ること
- 3 つの版: 的当てで新しい段階を取ったとき、今までどおり知らせが出ること
