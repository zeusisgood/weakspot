# 弱点破壊 Mod 追加仕様書（v1.9.0）

`SPEC_v1.8.9.md`（Mod 1.8.9）に対する**マイナー**の仕様。ここに書かれていないことは、それと現行実装のままとする。
この仕様書は `doc/spec/SPEC_v1.9.0.md`。

- 対象: Minecraft Java Edition 1.12.2 / Forge 14.23.5.2860
- 前提: 1.8.9 がリリース済み
- この仕様書の内容は、Mod のバージョン **1.9.0** として、リリースする

---

## 0. バージョンと互換性

- バージョンは 1.8.9 → **1.9.0**。`WeakSpotMod.ACCEPTED_VERSIONS` を `"[1.9,1.10)"` に
- **通信内容が変わる**（2・3・4）ので、**1.8.x とは接続できない**。サーバーと全員のクライアントを同時に更新する
- 保存データ: 近接の統計のキーを改名する（5.1）。1.8.x のワールドは読める（古いキーを読む）。1.9.0 で遊んだワールドを 1.8.x に戻すと、近接の数は 0 に見える
- 設定: 項目を足す（2）。古い項目を消す（5.4）。設定キーの改名はしない
- `WireCompatTest` の期待値は、1.9.0 の送る中身で作り直す（1.8.5 と同じであることは確かめない）

## 1. やりたいこと（ユーザーの判断: 1.8.6〜1.8.8 のあとの相談で決めた）

互換性を破るので、パッチではできなかった整理と設定の追加をまとめて行う。

## 2. 設定の追加

- **`miningWeakSpotEnabled` / `growthWeakSpotEnabled` / `machineWeakSpotEnabled` / `animalWeakSpotEnabled`**（`[サーバー]`、初期値 true）: サーバーの管理者が、その種類を全員に対して止める（ほかの種類の `…WeakSpotEnabled` と同じ。オフの種類はクライアントが弱点を出さず、サーバーもヒットと右クリックの抑止を止める）。1.8.9 の種類の表 `SyncedSettings.enabled(kind)` に入れる
- **`miningComboBonus`**（`[サーバー]`、初期値 true）: 採掘のコンボ倍率（1.8.7）のオン・オフ。オフなら掛け数は常に 1 で、「採掘 ×n」も出さない。クライアントも掛け数を知る必要があるので `SyncedSettings` に入れる
- 5 つとも `SyncedSettings` に入れ、`doc/config.md` と設定画面の説明（英語・日本語）に足す

## 3. 状態の問い合わせの通信をまとめる（相談の 3）

- 今: 動物（`AnimalQueryMessage` / `AnimalStateMessage`）・釣り（`FishingQueryMessage` / `FishingStateMessage`）・機械（`MachineQueryMessage` / `MachineStateMessage`）の 6 個
- 汎用の **`QueryMessage`**（C→S。種類と相手。相手は、生き物の ID かブロックの位置か、なし）と **`StateMessage`**（S→C。種類と相手と値の並び）の 2 個にする
- サーバーは種類ごとの処理の表（`HitHandlers` と同じ形）で返事を作り、クライアントは種類ごとに受け取る所（`AnimalStates`・`FishingSpot`・`MachineBars`）へ渡す。問い合わせの間隔（`QueryThrottle`）と、値の意味・補間は今と同じ
- パケットの番号は登録順で振り直す（マイナーなのでよい）
- 村人の繁殖できない理由（1.8.4）は、動物の問い合わせの返事のときに出す今の形のまま

## 4. 送る並びを素直にする（1.9.0 のメモの 3）

- `MiningStats.writeTo` / `readFrom` は、種類の順のループにする（1.8.5 までの手書きの並びと、`maxStreak` が機械のあとに入る都合をやめる）
- `SyncedSettings.WIRE` も、種類ごと・意味ごとの素直な並びにする（2 の新しい項目も入れる）
- `WireCompatTest` の期待値を 1.9.0 の中身で作り直す（次のマイナーまで、これが変わらないことを確かめる）

## 5. 互換のためだけに残しているものの整理（1.9.0 のメモの 1・2・4・5・6）

1. 保存のキー `critHits` を `meleeHits` に改名する。読むときは `meleeHits` がなければ `critHits` を読み、書くのは `meleeHits` だけ（古いワールドの数字は引き継ぐ）
2. 保存データに残った古いキー `rewardHits`（1.6.1 でやめた）を、読み込んだときに消す
3. （メモの 3 は上の 4）
4. `weakspot.cfg` に残った、今の設定にない項目（1.7.x の `meleeWeakSpotScale` など）を、設定ファイルの移行（`configVersion` 6）で消す。Forge が自分では消さないことを、実装のときに確かめる
5. 設定ファイルの移行 1〜5（1.2.x〜1.6.x の古い初期値の直し）を消す。`configVersion` の仕組みと 6 は残す。1.6.x 以前から直接上げた人は古い初期値のままになるので、更新履歴で案内する
6. 古いガイドの本の差し替え（1.8.5、`GuideBook.isOutdated`・`GuideBookGiver` の差し替え・`client/GuideBookOpener`）を消す。更新履歴に「1.8.4 以前に受け取った本は文章がキーのまま出るので、捨てて K キーの『ガイド』で読んでください」と書く

残すもの: `ServerLang`（パッチ同士の新しい翻訳キーのため）、設定キーの名前（`boostMultiplier`・`critsPerRepair` など）、`HitKind` の番号、`ServerFeatures`（1.9.x のパッチで使う。1.9.0 より前のサーバーにはつながらないので、`since("1.8.x")` の判定は常に true になる。判定ごと消してよい）

## 8. ユーザーに確認してもらうこと

- 1.8.x のワールド（統計あり）を 1.9.0 で開いて、統計（特に近接の数）が引き継がれていること
- 1.8.x の `weakspot.cfg` のまま起動して、`meleeWeakSpotScale` などの古い項目が消え、ほかの値は残っていること
- サーバーの設定で採掘・成長・機械・動物をオフにすると、その弱点が出ず、バニラの動き（機械の GUI が開くなど）に戻ること
- `miningComboBonus` をオフにすると、採掘がコンボで速くならず、「採掘 ×n」も出ないこと
- 動物・釣り・機械の弱点とバー、村人の繁殖の理由が今までどおり出ること（問い合わせの通信をまとめたため）
- 統計画面の数字が正しいこと（送る並びを変えたため）
- 1.8.x のクライアント・サーバーとは接続できないこと（接続を断られる）
