# 弱点破壊 Mod 追加仕様書（v1.1.3）

`SPEC_v1.1.md`（Mod 1.1.0）、`SPEC_v1.1.1.md`（Mod 1.1.1）、`SPEC_v1.1.2.md`（Mod 1.1.2）に対する**パッチ**の仕様。ここに書かれていないことは、それらと現行実装のままとする。
仕様書は、リポジトリの `doc/` ディレクトリに置く（この仕様書は `doc/spec/SPEC_v1.1.3.md`）。
仕様と食い違う実装をする場合は、`CLAUDE.md` のリリースの流れ（止まる条件）に従う。

- 対象: Minecraft Java Edition 1.12.2 / Forge 14.23.5.2860
- 前提: **1.1.2 がリリースされたあと**に、この仕様書の作業を始める（1.1.2 の内容を土台にする）
- 内容: **連続ヒットの表示演出（コンボ）**。**画面の演出だけ**で、破壊の速さや報酬のボーナスは付けない
- この仕様書の内容は、Mod のバージョン **1.1.3** として、リリースする
- 統計画面に「最大連続ヒット数」を足すことは、通信内容が変わるため、**1.2.0**（`SPEC_v1.2.md` §1.8）で行う

## 0. バージョンとパッチの制約

- バージョンは 1.1.2 → **1.1.3**（`build.gradle` の `version` と `WeakSpotMod.VERSION` の2か所を、そろえて変える）
- `WeakSpotMod.ACCEPTED_VERSIONS`（`[1.1,1.2)`）は、変えない。1.1.x 同士は、互いに接続できる
- **パッチなので、互換性を破る変更を入れない**（`SPEC_v1.1.md` §0 のバージョンの方針）
  - パケットの追加・削除・中身の変更をしない。`SyncedSettings` に、項目を足さない
  - サーバーが保存するデータの形式を変えない
  - 設定キーの削除や、意味の変更をしない
- この仕様書の変更は、**クライアントだけ**。サーバーは変えない

## 1. コンボ（連続ヒット）の考え方

### 1.1 数え方
- コンボは、**ヒット音の音階と同じ連続ヒット数**を使う（`CLAUDE.md` に、連続ヒット数は、種類・ブロックをまたいで続き、40 tick ヒットがないとリセットされる、とある）
- 音階は、1オクターブで最初の音に戻る。**コンボの数は、戻らずに上がり続ける**。音階は、コンボの数から求める形にする（数え方を1つにして、音とコンボが、ずれないようにする）
- 音階が途切れる（最初の音に戻る）条件と、コンボが途切れる条件は、**同じ**: 40 tick（約2秒）ヒットがないこと。ほかの条件（別のブロックに移る、採掘・成長・機械の種類が変わる）では、途切れない
- 途切れたら、コンボは 0 に戻る

### 1.2 リセットするタイミング（音階もコンボも、同じ）
- 40 tick ヒットがなかったとき
- ワールドやサーバーから出たとき
- 死亡したとき
- ディメンションを移動したとき
- 実装時に、現行の音階が、死亡やディメンション移動でリセットされているか確認する。されていなければ、音階もコンボも、同じように**リセットする**（音とコンボが、ずれないようにするため）

### 1.3 数えるもの
- 採掘、成長、機械のヒットを、すべて数える（音階と同じ）

## 2. 画面の表示

画面の HUD として、クライアントだけで描く。

### 2.1 数字
- コンボが **2以上**になったら、照準の近くに「12 HIT」のような数字を出す。1のときは出さない
- 位置の初期値: 照準の少し下（設定で変えられる。§3）
- ヒットのたびに、数字が一瞬大きくなって戻る（弾む動き）

### 2.2 色の段階

| コンボ | 色 |
|---|---|
| 2〜9 | 白 |
| 10〜24 | 黄 |
| 25〜49 | 橙 |
| 50〜99 | 赤 |
| 100 以上 | 虹色（ゆっくり色が変わる） |

### 2.3 残り時間のバー
- 数字の下に、細いバーを出し、途切れるまでの残り時間（40 tick）に合わせて、縮めていく
- ヒットしたら、満タンに戻る
- 「あと少しで途切れる」が、見て分かるようにする

### 2.4 途切れたとき
- 数字が薄くなって消える
- 直前のコンボが **5以上**だったときは、「MAX 23」のように、最後の数を、約1秒（20 tick）残してから消す
- 残している間に、新しいヒットがあって、コンボが始まったら、残しは消して、新しいコンボを出す

### 2.5 段階の演出（軽く）
- コンボが **10、25、50、100** に達した瞬間に、次の演出を、1回だけ出す
  - 短い強調音（既存のヒット音の楽器で、高い音を1つ。音量は自分のヒット音の音量に従う）
  - 数字の周りの光（一瞬）
- 累計ヒットの節目（100 / 777 / 1000 / 10000。`SPEC_v1.1.md` §5）の演出とは、**別物**。こちらは、その連続の中だけのもの
- 演出はMVPでは簡素でよい

### 2.6 表示しない場合
- 設定で、表示をオフにしたとき
- HUD を隠しているとき（F1 キー）（要確認）
- 他のプレイヤーのコンボは、表示しない。自分のコンボだけ

## 3. 設定（クライアント）

`weakspot.cfg` の `[クライアント]` の項目として足す。見た目だけに関わるので、各自の設定で、サーバーとは同期しない。

| キー | 初期値 | 説明 |
|---|---|---|
| `comboDisplayEnabled` | `true` | コンボの表示のオンオフ |
| `comboScale` | 1.0 | 数字の大きさの倍率（0.5〜2.0） |
| `comboPosition` | `BELOW_CROSSHAIR` | 表示の位置（`BELOW_CROSSHAIR` / `RIGHT_OF_CROSSHAIR` / `TOP_CENTER`） |
| `comboMilestoneEffects` | `true` | 10、25、50、100 のときの演出（強調音と光）のオンオフ |

- 途切れる時間（40 tick）は、設定にしない。音階のリセットと同じ値で、固定
- `CLAUDE.md` の設定のルールを守る: `[クライアント]` の項目は、`WeakSpotConfig` をそのまま読む。README の設定表（クライアントの項目）にも足す
- 画面の文字列（設定の説明、「HIT」「MAX」など）は、`en_us.lang` と `ja_jp.lang` の両方に足す
- 既存の `weakspot.cfg` には、次に起動したときに、初期値で追加される

## 4. 実装の範囲

### 4.1 やること
- 連続ヒットの数え方を、音階とコンボで共通にする（コンボの数は、1オクターブで戻らない）。数える処理は、Minecraft に依存しない純粋な計算として `common/` に置く（`HitPitch` にあれば、そこから切り出す。1.2.0 で、サーバーが統計のために同じ数え方を使えるようにするため）
- コンボの HUD の描画（数字、弾む動き、色の段階、残り時間のバー、途切れたときの消え方と「MAX」）
- 段階の演出（10、25、50、100）
- 設定の追加（§3）

### 4.2 やらないこと
- コンボによる破壊の速さや報酬のボーナス（画面の演出だけ）
- サーバーの変更、通信内容の変更
- 統計への「最大連続ヒット数」の追加（1.2.0 で行う）
- 他のプレイヤーのコンボの表示

### 4.3 単体テスト
`common/` に置く純粋な計算に、テストを書く。
- 連続ヒットの数え方: 40 tick 以内のヒットで続き、41 tick 以上あくと 0 に戻ること（境界の値を含める）
- 音階との関係: コンボが 8 を超えても数が戻らず、音階だけが1オクターブで最初の音に戻ること
- 色の段階の判定: 1 → 表示なし、2 と 9 → 白、10 → 黄、25 → 橙、50 → 赤、100 → 虹色
- 段階の演出の判定: コンボが 10、25、50、100 になった瞬間だけ、真になり、同じ数を続けて判定しても、1回しか真にならないこと
- 残り時間の割合: 経過 tick から、バーの割合（1.0〜0.0）を返すこと

## 6. 実装時に確認すること

- 現行の連続ヒット数の数え方が、どこにあるか（`HitPitch`、`HitSounds`）。数がオクターブで戻る作りになっていないか
- 死亡、ディメンション移動、ワールドを出たときに、現行の音階がリセットされているか（§1.2）
- HUD の描画イベントと、F1 で HUD を隠したときの挙動
- ほかの HUD（ヘルスバーなど）と、位置が重ならないこと

## 8. ユーザーに確認してもらうこと（クライアントの見た目・操作は、Claude Code が確認できない）

ビルドした jar を、ホストの Minecraft で試す。

- コンボが 2 になったところで、数字が出て、ヒットのたびに弾むこと
- 数字の下のバーが、約2秒かけて縮み、ヒットで満タンに戻ること
- ヒットをやめて、約2秒後に、音階が最初の音に戻る瞬間と、コンボが消える瞬間が、同時であること
- 8 ヒットを超えても、コンボの数が上がり続け、音階だけが、1オクターブで最初の音に戻ること
- 別のブロックに移っても、採掘から成長に切り替えても、コンボが続くこと
- コンボが 5 以上のとき、途切れたあとに「MAX」が約1秒残ること
- 10、25、50、100 で、色が変わり、強調音と光が出ること
- 設定で、表示のオフ、位置、大きさ、演出のオフが効くこと
- 死亡したとき、コンボと音階が、同時に 0 に戻ること
- 1.1.2 のサーバー（またはクライアント）と、1.1.3 のクライアント（またはサーバー）で、接続できること
