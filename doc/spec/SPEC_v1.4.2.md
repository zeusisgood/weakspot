# 弱点破壊 Mod 追加仕様書（v1.4.2）

`SPEC_v1.4.1.md`（Mod 1.4.1）に対する**パッチ**の仕様。ここに書かれていないことは、それと現行実装のままとする。
仕様書は、リポジトリの `doc/` ディレクトリに置く（この仕様書は `doc/spec/SPEC_v1.4.2.md`）。
仕様と食い違う実装をする場合は、`CLAUDE.md` のリリースの流れ（止まる条件）に従う。

- 対象: Minecraft Java Edition 1.12.2 / Forge 14.23.5.2860
- 前提: 1.4.1 がリリース済み。1.4.1 の内容を土台にする
- 内容: 機械の加速を強める。①加速の切れ目をなくす（続く時間の初期値 4 → 6 tick）。②コンボに応じて機械の倍率を上げる（1000 コンボで 4 倍）。③コンボの段階の演出を 250 / 500 / 1000 まで延ばし、上の段階ほど派手にする。④機械を叩いている間、コンボの倍率を HUD に出す
- この仕様書の内容は、Mod のバージョン **1.4.2** として、リリースする

---

## 0. バージョンとパッチの制約

- バージョンは 1.4.1 → **1.4.2**（`build.gradle` の `version` と `WeakSpotMod.VERSION` の2か所を、そろえて変える）
- `WeakSpotMod.ACCEPTED_VERSIONS`（`[1.4,1.5)`）は、変えない。1.4.x 同士は、互いに接続できる
- **パッチなので、互換性を破る変更を入れない**
  - パケットは足さない・変えない。`SyncedSettings` にも項目を足さない
  - 連続ヒット数は、サーバーがすでに数えているもの（`ServerStats.countStreak` の `HitStreak`）を使う。クライアントから数を受け取らない
  - 設定は、サーバーだけが使うもの（送らない）を1つ足し、既存の1つの初期値を変える（意味は変えない）
  - 保存データは変えない

## 1. 加速の切れ目をなくす

- `machineBoostDurationTicks` の初期値を **4 → 6** にする（`machineMinHitIntervalTicks` の初期値 6 と同じ）
  - 最短の間隔で当て続けると、加速が途切れずにつながる（今は 6 tick のうち 2 tick が等倍に戻り、平均で約 3 倍どまり。変更後は、ずっと 4 倍）
- 設定ファイルの移行（`WeakSpotConfig.migrate`）に、**4: `machineBoostDurationTicks` が古い初期値 4 なら 6 に**を足す（`configVersion` を 4 に）。ユーザーが 4 以外に変えていれば、そのまま

## 2. コンボで機械の倍率を上げる

- 機械のヒットを受け付けたときの倍率を、次のように決める（**サーバー**）

```
倍率 = min(machineBoostMultiplier × コンボの掛け数, machineBoostMaxMultiplier)
```

- コンボは、**このヒットを数えたあと**の、サーバーの連続ヒット数（`HitStreak`。採掘・成長・機械・動物・釣り・弓・近接のすべてで数え、種類・ブロックをまたいで続き、40 tick ヒットがないと途切れる。ヒット音・コンボの表示と同じ数え方）
  - 今の `RightClickHits` は、`MachineAccelerator.hit` のあとに `ServerStats.countStreak` を呼んでいる。`countStreak` が数を返すようにし、先に数えてから、その数で倍率を決める
- コンボの掛け数（固定。`common/MachineComboBoost` に置き、単体テストを書く）

| コンボ | 掛け数 | 機械の速さ（初期値の 4 倍のとき） |
|---|---|---|
| 1〜24 | ×1.0 | 4 倍 |
| 25〜 | ×1.25 | 5 倍 |
| 50〜 | ×1.5 | 6 倍 |
| 100〜 | ×2.0 | 8 倍 |
| 250〜 | ×2.5 | 10 倍 |
| 500〜 | ×3.0 | 12 倍 |
| 1000〜 | ×4.0 | 16 倍 |

- 1000 より上は ×4.0 のまま
- 新しい設定 `machineBoostMaxMultiplier`（**サーバーだけが使う**。送らない）
  - 初期値 **16.0**（上の表の最大をそのまま使える値）、範囲 1.0〜100.0
  - 機械 Mod の不具合やサーバーの負荷が気になるときに、ホストが下げる。`machineBoostMultiplier` より小さいときも、上限を優先する
- 複数のヒット（複数のプレイヤーを含む）が重なったときは、今と同じく、足さずに大きいほうを使う（`MachineBoost.hit`）。コンボが途切れても、すでに受け付けた加速は、残り時間の間そのまま続く
- 成長・採掘など、機械以外の種類の効果は変えない

## 3. コンボの段階の演出を 1000 まで延ばす

### 3.1 段階

- 演出を出す段階（`ComboMilestones`）を **10 / 25 / 50 / 100 / 250 / 500 / 1000** にする
- 1000 より上は、**1000 ごとに**（2000、3000、…）1000 と同じ演出を出す（タイトルの数は、その数）
- 色の段階（`ComboTier`）は変えない（100 以上は虹色のまま）。虹色の一周の時間を、段階ごとに短くする（速く流れる）

| コンボ | 虹色の一周 |
|---|---|
| 100〜 | 4000 ms（今と同じ） |
| 250〜 | 3000 ms |
| 500〜 | 2000 ms |
| 1000〜 | 1200 ms |

### 3.2 演出（上の段階ほど足していく）

音は、どれも自分のヒット音の楽器と音量（`myHitSound` / `myHitVolume`）で、距離なしで鳴らす。今と同じく、ヒット音から少し（2 tick）遅らせて始める。

| コンボ | 音 | 見た目 |
|---|---|---|
| 10 / 25 / 50 | 最高音（今と同じ） | 数字が光る（今と同じ） |
| 100 | 和音（ド・ミ・ソ・上のドを同時に） | 数字が光る |
| 250 | 駆け上がり（ドからソまでの 5 音、1 tick ごと） | 数字の光を強め、弾みを大きくする。光の色はピンク `#FF55FF` |
| 500 | 駆け上がり（ドから上のドまでの 8 音、1 tick ごと） | 250 に加えて、自分のまわりに小さい花火 1 発。光の色は水色 `#55FFFF` |
| 1000（以降 1000 ごと） | 駆け上がり（ピッチ 0.5 の低いドから 2.0 の高いドまでの 2 オクターブ、1 tick ごと）＋最後に和音 | 500 に加えて、画面中央のタイトル「1000 COMBO!」（金 `#FFD700`）、花火 3 発。光の色は金 `#FFD700` |

- 花火・タイトルは、累計の節目の演出（`MilestoneEffects`）の部品を流用する。自分の画面だけに出す（他のプレイヤーには見えない。通信を変えない）
- 花火の粒子と音は、クライアントだけで出す（ワールドに花火のエンティティを出さない）
- すべての演出は、今と同じく `comboDisplayEnabled` と `comboMilestoneEffects` の両方がオンのときだけ出す

## 4. 機械の倍率を HUD に出す

- 機械の弱点が出ている間（`ClientWeakSpotHandler.spot` の種類が機械で、このフレームで照準が合っている）、コンボの数字の下に、小さく「**機械 ×2.5**」と出す（英語は「**Machine ×2.5**」）
- 出す数は**コンボの掛け数**（2 の表）。クライアントが自分のコンボの数（`ClientWeakSpotHandler.STREAK`）から、同じ `MachineComboBoost` で求める
  - `machineBoostMultiplier` と `machineBoostMaxMultiplier` はクライアントに届いていない（送らない）ので、機械の実際の速さではなく、掛け数を出す
  - サーバーの数とは、ネットワークの遅れで一瞬ずれることがある（見た目だけ）
- 掛け数が ×1.0（コンボが 24 以下）のときは出さない
- 掛け数が上がった瞬間は、コンボの数字と同じように光らせる
- 色は白 `#FFFFFF`、光る間はその段階の光の色（25 / 50 / 100 は今の段階の色、250 / 500 / 1000 は 3.2 の色）
- コンボの表示と同じく、`comboDisplayEnabled` がオフ、F1 で隠しているときは出さない。大きさ・位置は `comboScale` / `comboPosition` に従う
- 画面の文字列は `en_us.lang` と `ja_jp.lang` の両方に足す

## 7. 実装時の確認事項

- 花火の粒子をクライアントだけで出す方法（`World#makeFireworks` など）が、今の `MilestoneEffects` の方法と同じで使えるか。使えなければ、`MilestoneEffects` と同じ方法にそろえる
- 1000 のタイトルは、累計の節目のタイトルと同じ仕組み（`GuiIngame#displayTitle` など）で出す。累計の節目と同じ瞬間に重なったら、累計の節目のほうを優先する（あとから出したほうが上書きしないようにする）

## 8. ユーザーに確認してもらうこと

- 機械（かまどなど）を最短の間隔で叩き続けたとき、加速が途切れずに速く動くこと
- コンボが 25 / 50 / 100 / 250 / 500 / 1000 に上がるたびに、機械がさらに速くなること。コンボが途切れると元の速さに戻ること
- 機械を叩いている間、コンボの数字の下に「機械 ×n」が出て、段階が上がった瞬間に光ること。コンボが 24 以下では出ないこと
- 100 / 250 / 500 / 1000 の演出（音・光・花火・タイトル）が、上の段階ほど派手になっていること。うるさすぎないか
- 虹色が、段階ごとに速く流れること
- 1.4.1 以前の設定ファイル（`machineBoostDurationTicks=4`）が、起動後に 6 に直っていること
