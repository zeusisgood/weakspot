# 弱点破壊 Mod 仕様書（MVP）

Fortnite の資材集めにある「弱点（クリティカル）を叩くと速く壊せる」システムを Minecraft に持ち込む Mod。

- 対象: Minecraft Java Edition **1.12.2** / **Forge**
- 開発環境: devcontainer（JDK 8）+ Claude Code
- 位置づけ: MVP（動くものを作り、遊びながら数値を調整する）

---

## 1. コンセプト

長押し破壊の操作感は変えない。ブロック面に出る弱点に照準を合わせた瞬間だけ、破壊が一気に進む。
エイムの上手さが素材集めの速さに反映される。

## 2. 基本動作

1. プレイヤーがブロックを長押しで破壊し始めた瞬間、狙っているブロック面に**弱点マーク**を表示する
2. 弱点に照準が重なった瞬間を**ヒット**とする
3. ヒットしたら、破壊速度に倍率を掛ける（短時間のみ。§4 参照）
4. ヒットと同時に、弱点を**前回の位置から一定距離以上離れた場所**へ移動する
5. 長押しをやめても、弱点はしばらく残る
6. 別の面を狙ったら、その面に弱点を出し直す
7. 弱点に当てなくても、破壊は通常速度で進む（弱点は「上乗せ」であり必須ではない）

## 3. 対象と除外

| 項目 | 仕様 |
|---|---|
| 対象ブロック | 全ブロック |
| ツール | 問わない（素手でも有効） |
| 除外 | 岩盤など壊せないブロック（硬度が負）、瞬間破壊できるブロック |
| ゲームモード | クリエイティブは対象外 |

「瞬間破壊」は、そのプレイヤーの現在の破壊速度で1tick以内に壊れるかで判定する（硬度0のブロックに限らない）。

## 4. ヒット時の効果

- 短時間だけ、そのプレイヤーの破壊速度に倍率を掛ける
- 初期値: **約4倍を約0.2秒間**（通常の約0.6秒分の追加進捗）
- 連続ヒットでコンボは付かない
- 狙い: 連続でヒットし続けたとき、通常の**約2倍**の速さになること

追加進捗 = (倍率 − 1) × 継続時間。倍率と継続時間は設定で変えられるようにする。

## 5. 弱点の仕様

| 項目 | 初期値 |
|---|---|
| 形 | 円 |
| 大きさ | ブロック面の1/6〜1/8程度（半径は面サイズの比率で設定） |
| 出現位置 | 狙っているブロック面の内側（縁に近すぎない範囲） |
| 移動距離 | 前回の位置から **0.4ブロック以上**離れた場所 |
| 長押し停止後の残存時間 | 約 **2秒**（40tick） |

## 6. マルチプレイ

- **サーバー・クライアント両方に Mod を導入する**（バニラクライアントは非対応）
- 弱点の位置決めと表示は、**各プレイヤーのクライアントだけ**で行う。他のプレイヤーとは共有しない（Fortnite と同じ）
- クライアントは、ヒット時にサーバーへ「ヒットした」という通知だけを送る
- サーバーは通知を受けたら、そのプレイヤーの破壊速度に倍率を掛ける時間枠を開始する
- 通知の間隔が極端に短いものは無視する（簡易対策）。それ以上の不正対策はしない

### なぜサーバー側も必要か

1.12.2 の破壊進捗はクライアントとサーバーがそれぞれ計算する。クライアントだけ速くすると、クライアント上で壊れたブロックがサーバーに戻される（ゴーストブロック）ため、サーバー側でも同じ倍率を掛ける必要がある。

## 7. 演出

- **MVP**: ヒット音と、ヒット時の軽い表示のみ
- 将来: 原作（Fortnite）に寄せた演出（マーカーの見た目、パーティクル、画面の揺れなど）

## 8. 設定項目（Forge Config）

すべて設定ファイルで変更可能にする。

| キー | 初期値 | 説明 |
|---|---|---|
| boostMultiplier | 4.0 | ヒット時の破壊速度の倍率 |
| boostDurationTicks | 4 | 倍率を掛ける時間（tick） |
| weakSpotRadiusRatio | 約0.14 | 弱点の半径（面サイズに対する比率） |
| minMoveDistance | 0.4 | 弱点の最小移動距離（ブロック） |
| lingerTicks | 40 | 長押し停止後に弱点が残る時間（tick） |
| minHitIntervalTicks | 要調整 | サーバーがヒット通知を受け付ける最小間隔（tick） |

## 9. 実装方針（案）

Claude Code で進めるときの目安。実装で問題があれば、より良い方法に変更してよい。

- **弱点の状態管理（クライアント）**: 位置（面の2D座標）、対象ブロック、対象面、最後に狙った時刻
- **ヒット判定（クライアント）**: プレイヤーの視線とブロック面の交点（`RayTraceResult` の `hitVec`）を、面ローカルの2D座標に変換し、弱点の円との距離を比べる
- **描画（クライアント）**: ワールド描画のイベントで、ブロック面に少し浮かせた円を描く
- **通信**: `SimpleNetworkWrapper` で、クライアント→サーバーの「ヒット通知」パケットを1種類だけ作る
- **破壊速度への介入（両側）**: Forge の `PlayerEvent.BreakSpeed` で、時間枠の間だけ倍率を掛ける

### パッケージ構成（案）

```
com.example.weakspot
├─ WeakSpotMod            // Mod本体（@Mod）
├─ config/                // 設定
├─ client/                // 弱点の状態管理、ヒット判定、描画、音
├─ server/                // 時間枠の管理、通知の検証
├─ network/               // パケット
└─ common/                // 面の座標変換など、両側で使う計算
```

弱点の位置決め、面座標の変換、距離判定は、Minecraft のクラスに依存しない純粋な計算として `common/` に分けると、テストしやすく、将来1.7.10などへ移植するときも楽になる。

## 10. 実装時に確認すること

- `BreakSpeed` イベントが、クライアントとサーバーの両方の破壊進捗計算で発火するか
- 「瞬間破壊」と「壊せない」の判定方法
- サーバー側で「そのプレイヤーが今そのブロックを破壊中か」を確認する方法（必要ならアクセストランスフォーマーを検討）
- クライアントとサーバーで設定値が食い違ったときの扱い（MVPは同じ設定を使う前提）

## 11. 開発環境とワークフロー

- devcontainer で JDK 8 を使う（Forge 1.12.2 / ForgeGradle 2.3 は JDK 8 が前提）
- ベースは Forge 1.12.2 の MDK（Gradle ラッパー付き）
- **ビルド**: コンテナ内で `./gradlew build`。成果物は `build/libs/` に出る
- **サーバー確認**: コンテナ内で `./gradlew runServer`（初回は `eula.txt` の同意が必要）。ポート 25565 を転送済み
- **クライアント確認**: コンテナ内ではゲーム画面を出しにくいので、ビルドした jar をホストの Minecraft（Forge 1.12.2）の `mods` フォルダへ入れて確認する

## 12. MVP の完了条件

- [ ] 長押しを始めると、ブロック面に弱点が出る
- [ ] 弱点に照準が重なった瞬間にヒットし、弱点が離れた場所へ移動する
- [ ] ヒット中は、破壊が通常より明らかに速くなる
- [ ] 弱点に当て続けると、通常の約2倍の速さで壊れる
- [ ] 素手でも動く
- [ ] マルチ（専用サーバー）で、ゴーストブロックなしに動く
- [ ] 設定ファイルで数値を変えられる

## 13. スコープ外（MVP では作らない）

- コンボ、連続ヒットのボーナス
- 原作に寄せた凝った演出
- 弱点の他プレイヤーとの共有
- 本格的な不正対策
- 1.12.2 以外のバージョン（1.7.10 への移植は MVP 後）
