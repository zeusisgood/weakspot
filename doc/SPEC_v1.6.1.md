# 弱点破壊 Mod 追加仕様書（v1.6.1）

`SPEC_v1.6.md`（Mod 1.6.0）に対する**パッチ**の仕様。ここに書かれていないことは、それと現行実装のままとする。
仕様書は、リポジトリの `doc/` ディレクトリに置く（この仕様書は `doc/SPEC_v1.6.1.md`）。
仕様と食い違う実装をする場合は、`CLAUDE.md` のリリースの流れ（止まる条件）に従う。

- 対象: Minecraft Java Edition 1.12.2 / Forge 14.23.5.2860
- 前提: 1.6.0 がリリース済み。1.6.0 の内容を土台にする
- 内容: 統計の累計をリセットしたら、節目（採掘ヒット 100 / 777 / 1000 / 10000 回）をもう一度受け取れるようにする。節目のための、リセットされない隠れた回数（`rewardHits`）はやめる（ユーザーの判断）
- この仕様書の内容は、Mod のバージョン **1.6.1** として、リリースする

---

## 0. バージョンとパッチの制約

- バージョンは 1.6.0 → **1.6.1**（`build.gradle` の `version` と `WeakSpotMod.VERSION` の2か所を、そろえて変える）
- `WeakSpotMod.ACCEPTED_VERSIONS`（`[1.6,1.7)`）は、変えない
- **パッチなので、互換性を破る変更を入れない**。通信・設定は変えない。保存データは、キーを使わなくなるだけ（古いキー `rewardHits` は読まず、消しもしない。古い版に戻しても読める）
- サーバーだけの変更（クライアントは変わらない）。`ServerFeatures` で囲むものはない

## 1. 節目の数え方

- 節目は、統計の**累計の採掘ヒット数**（`MiningStats.hits` の累計。採掘ヒットを受け付けたときに `ServerStats.record` で増えたあとの値）で判定する。`ServerStats.addRewardHit` と `rewardHits` はやめる
- 統計画面の「累計をリセット」でも、`/weakspot reset <プレイヤー>`（OP）でも、累計が 0 に戻るので、**100 回目からまた節目を受け取れる**（演出も報酬ももう一度出る。どちらのリセットでも同じ。ユーザーの判断）
- 報酬は少しの経験値と耐久回復だけなので、リセットを繰り返して稼げても問題にしない
- これまでに一度リセットした人は、隠れた回数のほうが累計より多かった。更新後は累計で数えるので、累計が節目に届いたときに、受け取ったことのある節目をもう一度受け取る（新しい決まりどおりの動き）

## 2. README

- 「耐久回復と節目」の節の「節目の回数は、統計の『累計をリセット』では戻りません」を、「累計をリセットすると、節目の回数も 0 に戻り、100 回目からもう一度受け取れます（1.6.1）」に
- 「統計」の節の「累計をリセット」の説明と、管理コマンドの `/weakspot reset` の説明にも、節目を受け取り直せることを書く
- 「最新版」の行を 1.6.1 にし、「更新履歴」に 1.6.1 を追加する（サーバーだけの変更。通信内容は変わっていない）
- 「開発」の節の仕様書へのリンクに `doc/SPEC_v1.6.1.md` を足す
- ガイドの本は、リセットの話を書いていないので変えない

## 3. `CLAUDE.md` に書くこと

- 「仕様の正本」の一覧に `doc/SPEC_v1.6.1.md` を足す。現行のバージョンを 1.6.1 に
- `ServerStats` と `MiningRewards` の説明の `rewardHits` を、「節目は累計の採掘ヒット数で判定する（1.6.1。リセットで受け取り直せる）」に

## 4. ユーザーに確認してもらうこと

- 統計画面で累計をリセットしてから採掘の弱点に 100 回当てると、100 回の節目の演出と報酬がもう一度出ること
- `/weakspot reset <プレイヤー>` でも同じこと
