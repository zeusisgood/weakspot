# 弱点破壊 Mod 追加仕様書（v1.5）

`SPEC_v1.4.4.md`（Mod 1.4.4）に対する**マイナー**の仕様。ここに書かれていないことは、それと現行実装のままとする。
仕様書は、リポジトリの `doc/` ディレクトリに置く（この仕様書は `doc/SPEC_v1.5.md`）。
仕様と食い違う実装をする場合は、`CLAUDE.md` のリリースの流れ（止まる条件）に従う。

- 対象: Minecraft Java Edition 1.12.2 / Forge 14.23.5.2860
- 前提: 1.4.4 がリリース済み。1.4.4 の内容を土台にする
- 内容: **近接の弱点のマーカーだけ**を大きくする。大きさを別の設定に切り出し、初期値を今より大きくする
- この仕様書の内容は、Mod のバージョン **1.5.0** として、リリースする

---

## 0. バージョンと互換性

- バージョンは 1.4.4 → **1.5.0**（`build.gradle` の `version` と `WeakSpotMod.VERSION` の2か所を、そろえて変える）
- **通信内容が変わる**: 弱点の大きさはサーバーの値（`SyncedSettings`）を使うので、新しい設定も `SyncedSettings` に足して送る。そのため 1.4.x とは接続できない
  - `WeakSpotMod.ACCEPTED_VERSIONS` を `[1.5,1.6)` にする
  - README の更新履歴に、1.4.x とは接続できないこと（サーバーとクライアントを同時に更新すること）を書く
- 保存データは変えない

## 1. 設定 `meleeWeakSpotScale`（[サーバー]。`SyncedSettings` で送る）

| キー | 初期値 | 範囲 | 説明 |
|---|---|---|---|
| `meleeWeakSpotScale` | 1.5 | 1.0〜3.0 | 近接の弱点の大きさの倍率。ほかの弱点の大きさ（`weakSpotRadiusRatio` と `weakSpotMinRadius`）に掛ける |

- 近接の弱点（`HitKind.MELEE`）の半径だけを、次のように決める。ほかの種類（採掘・成長・機械・動物）は変えない

```
半径 = min(max(短い辺 × weakSpotRadiusRatio × 倍率, weakSpotMinRadius × 倍率), 短い辺 × weakSpotMaxRadiusRatio)
```

  - 「短い辺」は、近接の弱点を出す範囲（`MeleeArea` で側面の下 40% を除いたもの）の短い辺
  - 上限（`weakSpotMaxRadiusRatio`）は倍率を掛けない。弱点が面からはみ出さないようにするため
- 目安（初期値）: ゾンビの側面（幅 0.6）で、半径 0.084 → **0.126**（約 1.5 倍）。クモの側面など大きい面も同じく 1.5 倍（上限まで）
- 見た目の大きさと当たり判定の大きさは、今までどおり同じ（どちらも大きくなる）
- 近接の弱点は他のプレイヤーに見せないので、マークの送信は変わらない

## 2. README

- 近接の弱点の節に、マーカーがほかの弱点より大きいこと（設定 `meleeWeakSpotScale`）を書く
- 設定表（サーバー）に `meleeWeakSpotScale` を足す
- 「最新版」の行を 1.5.0 にし、「更新履歴」に 1.5.0 を追加する（通信内容が変わったので、1.4.x とは接続できない）
- 「開発」の節の仕様書へのリンクに `doc/SPEC_v1.5.md` を足す
- ガイドの本は、技術的な数字の話なので変えない

## 3. `CLAUDE.md` に書くこと

- 「仕様の正本」の一覧に `doc/SPEC_v1.5.md` を足す。現行のバージョンを 1.5.0、範囲を `[1.5,1.6)` に
- 「両方に Mod が必要」の説明に、1.5.0 で通信内容が変わったので 1.4.x と接続できないことを足す
- 近接の弱点の説明に、`meleeWeakSpotScale`（`SyncedSettings`）を足す

## 4. ユーザーに確認してもらうこと

- 敵に出る近接の弱点のマーカーが、今より大きく（約 1.5 倍）なっていること。当てやすくなったか
- 採掘・動物などほかの弱点の大きさは、変わっていないこと
- 設定 `meleeWeakSpotScale` を変えて `/weakspot reload` すると、大きさが変わること
