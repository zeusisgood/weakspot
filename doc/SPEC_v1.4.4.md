`SPEC_v1.4.3.md`（Mod 1.4.3）に対する**パッチ**の仕様。ここに書かれていないことは、それと現行実装のままとする。
仕様書は、リポジトリの `doc/` ディレクトリに置く（この仕様書は `doc/SPEC_v1.4.4.md`）。
仕様と食い違う実装をする場合は、`CLAUDE.md` のリリースの流れ（止まる条件）に従う。

- 対象: Minecraft Java Edition 1.12.2 / Forge 14.23.5.2860
- 前提: 1.4.3 がリリース済み。1.4.3 の内容を土台にする
- 内容: 機械の加速の対象に、**予約された tick（スケジュール tick）で動くレッドストーンの部品**（コンパレーター・リピーター・オブザーバー・ディスペンサー・ドロッパー）を足す。クロック回路を速くできるようにする
- この仕様書の内容は、Mod のバージョン **1.4.4** として、リリースする

## 0. バージョンとパッチの制約

- バージョンは 1.4.3 → **1.4.4**（`build.gradle` の `version` と `WeakSpotMod.VERSION` の2か所を、そろえて変える）
- `WeakSpotMod.ACCEPTED_VERSIONS`（`[1.4,1.5)`）は、変えない
- **パッチなので、互換性を破る変更を入れない**。パケット・`SyncedSettings`・保存データ・設定は変えない
  - 対象はコードで決める（設定で増やせるようにすると `SyncedSettings` が変わるので、しない）。外したいときは、今ある `excludedBlocks` に書く
  - 1.4.3 以前のクライアントでは、これらのブロックに弱点が出ない（加速できないだけ）。1.4.4 のサーバーは、しゃがみ+素手の右クリックでのモード切り替え・GUI を止める（後述）ので、古いクライアントでは一瞬だけ切り替わって見えることがある

## 1. 対象（両側。`RightClickTargets.isMachine`）

今の「`ITickable` のタイルエンティティを持つブロック」に加えて、次のクラスのブロック（とそれを継承した Mod のブロック）を機械の対象にする。`excludedBlocks` にあれば対象外。

| 種類 | クラス | バニラのブロック |
|---|---|---|
| 信号の部品 | `BlockRedstoneDiode` | リピーター、コンパレーター |
| 信号の部品 | `BlockObserver` | オブザーバー |
| 発射の部品 | `BlockDispenser` | ディスペンサー、ドロッパー |

- 操作は、ほかの機械と同じ（しゃがんで、両手が空のまま右クリックを押しっぱなし）。弱点は照準の面に出る（リピーター・コンパレーターは薄いので、実際には上面だけに出る。側面は `minFaceSize` 未満で出ない）
- この操作をしている間は、コンパレーターのモード切り替え、リピーターの遅延の切り替え、ディスペンサー・ドロッパーの GUI が止まる（ほかの機械の GUI と同じ）。しゃがまなければ、今までどおり
- 倍率は、ほかの機械と同じ（`machineBoostMultiplier` × コンボの掛け数、上限 `machineBoostMaxMultiplier`。続く時間は `machineBoostDurationTicks`）

## 2. 信号の部品の加速（予約を前倒しする）

- 加速中のブロックに予約された tick があれば、その残り時間を、1 tick ごとに余分に **(倍率 − 1)** 減らす（端数は、今の `MachineBoost` と同じく持ち越す）。4 倍なら、残り時間が 1 tick に 4 ずつ減る
- 残り時間が 0 以下になったら、その場で予約を取り除き、バニラと同じ条件（そのブロックがまだ予約したブロックのまま）で `updateTick` を呼ぶ
- **1 つのブロックが前倒しで動くのは、1 tick に 1 回まで**。自分自身に信号を戻すクロックが、同じ tick の中で回り続けないようにする（倍率を上げても「1 tick に 1 回」が上限）
- 処理するのは、ワールドの tick の最後（今の機械の加速と同じ `WorldTickEvent` END）。バニラの予約の処理が終わったあと
- 予約の取り出しと入れ直しは、`WorldServer` の公開のメソッド（`isUpdateScheduled`、`getPendingBlockUpdates(StructureBoundingBox, true)`、`scheduleBlockUpdate`）で行う
  - `getPendingBlockUpdates` は X と Z だけで絞り込む（高さを見ない）ので、同じ列のほかの予約も取り出される。それらは、元の予定の時刻と優先度のまま入れ直す
  - 予約がないとき（`isUpdateScheduled` が false）は、何もしない（全部の予約をなめる処理を避ける）
- 前倒しの計算（残り時間と余分の tick から、新しい残り時間）は `common/ScheduledBoost` に置き、単体テストを書く

## 3. 発射の部品の加速（1 回で複数発）

- 加速中のディスペンサー・ドロッパーに予約された tick（信号を受けてから発射までの 4 tick 待ち）があれば、残り時間によらず、**その tick の最後に**前倒しで動かす（2 と同じく、1 tick に 1 回まで）
- そのとき、バニラの発射（`updateTick` の中の 1 回）に加えて、**余分に発射する**。発射の回数は:

```
回数 = min(5, floor(1 + 倍率 ÷ machineBoostMultiplier))
```

| コンボの掛け数 | ×1 | ×1.25 | ×1.5 | ×2 | ×2.5 | ×3 | ×4 |
|---|---|---|---|---|---|---|---|
| 回数（初期値） | 2 | 2 | 2 | 3 | 3 | 4 | 5 |

- 上限の設定（`machineBoostMaxMultiplier`）で倍率が抑えられたときは、回数も減る
- 余分の発射は、`BlockDispenser` の非公開の `dispense(World, BlockPos)`（SRG `func_176439_d`）を `Reflect.method` で呼ぶ。ドロッパーは自分の `dispense` を持っているので、そちらが呼ばれる。見つからなければ警告を1回出し、余分の発射だけしない（前倒しはする）
- 中身が空なら、バニラと同じく空の音が鳴るだけ
- 回数の計算は `common/ScheduledBoost` に置き、単体テストを書く

## 6. ユーザーに確認してもらうこと

- コンパレーターの自己ループのクロック（コンパレーターの出力を、減算モードで横に戻す形）のコンパレーターを叩くと、クロックが速くなること。叩くのをやめると元に戻ること
- リピーターのループのクロックで、叩いたリピーターの分だけ速くなること
- クロックにつないだディスペンサーを叩くと、1 回の信号で 2 発（コンボが上がると最大 5 発）出ること。ドロッパーも同じ
- しゃがんで素手で右クリックしても、コンパレーターのモード・リピーターの遅延が変わらないこと。しゃがまなければ、今までどおり変わること
- 回路やサーバーが重くならないこと
